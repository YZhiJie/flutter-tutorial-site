EP.01 问号满天飞 · Dart 语法基础 ​

对应正文：阶段一 · Dart 语法基础

剧情回顾 ​

达达第一次翻开 Flutter 代码，被 String? name 里的问号和 required 关键字整懵了；小薇也跟着吐槽装环境时从没见过这些。帧叔出场，用「声明三板斧」讲清 var / final / const 的分工，并用 const DateTime.now() 的翻车现场说明了编译期常量与运行期值的边界。最后帧叔点题：类型不是枷锁，是护栏。

知识点拆解 ​

格 1 · 困境：问号满天飞 ​

初学 Dart 最先撞见的两个陌生符号：

  • String? —— 可空类型标记。Dart 开启空安全后，变量默认不可为 null，只有显式加 ? 才允许为空。
  • required —— 命名参数的必传标记。Flutter Widget 的构造函数大量出现，如 required this.title。

这两个符号不是装饰，而是编译器强制执行的契约：可空变量不判空就用，编译直接报错；required 参数不传，同样编译报错。

格 2 · 揭秘：声明三板斧 ​

声明赋值时机能否改典型场景
var声明时可以普通局部变量
final运行期，仅一次不可改网络请求结果、当前时间
const编译期不可改数学常量、写死的配置

配套技能：

  • 空合并 ??：nick ?? '暂无'——左边为 null 时取右边的兜底值。
  • 空安全调用 ?.：user?.name——对象为 null 时整个表达式返回 null，不崩溃。

格 3 · 实证：const 翻车现场 ​

dart
const now = DateTime.now(); // 编译错误
final now = DateTime.now(); // 正确

const 要求值在编译期就确定，而 DateTime.now() 要等到运行期才能算出来，所以编译器拒绝。判断口诀：这个值是写代码时就知道，还是跑起来才知道？ 前者才能 const。

格 4 · 结案：类型是护栏 ​

最佳实践三条：

  1. 能 final 不 var，能 const 不 final——越严格的声明，编译器能帮你拦下的错误越多；
  2. Widget 构造参数优先用命名参数 { }，调用处自解释；
  3. 运行期的值别用 const 接。

坑点清单 ​

本话坑点

  1. [ ] 与 { } 混用：[int b = 0] 是可选位置参数，{int b = 0} 是命名参数，传参方式完全不同，混用直接编译报错。
  2. 可空变量未判空就使用：String? name; print(name.length) 编译不通过，改用 name?.length 或 if (name != null) 判空。
  3. 对 final 变量二次赋值：final 不是「暂时不变」，是「永远只能赋一次」，编译期就会拦下。

自测 3 题 ​

Q1：const pi = 3.14159 和 final pi = 3.14159 都能编译通过，二者区别是什么？

查看答案

const 是编译期常量，内存中只有一份，且可嵌套进 const 构造；final 是运行期赋值一次。对字面量而言行为接近，但习惯上写死的字面量用 const，让编译器做更多优化。

Q2：下面代码为什么不通过编译？怎么改？

dart
String? nickname;
print(nickname.length);
查看答案

nickname 是可空类型，直接访问 .length 可能空指针，空安全下编译器拒绝。改法：print(nickname?.length ?? 0)，或先 if (nickname != null) 判空。

Q3：const now = DateTime.now() 为什么报错？应该用什么？

查看答案

DateTime.now() 是运行期才能确定的值，不满足 const 的编译期常量要求。应改用 final now = DateTime.now()。
