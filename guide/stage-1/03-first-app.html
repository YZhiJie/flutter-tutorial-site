第一个 Flutter 应用 ​

学习目标 ​

学完本章，你将能够：

  • 说清一个 Flutter 应用从 main() 到屏幕像素的启动链路
  • 逐行读懂默认计数器模板的每一部分
  • 使用热重载快速迭代 UI
  • 对模板代码做简单改造，验证自己的理解

先跑起来 ​

下面就是 Flutter 官方的计数器示例，点击 Run，右侧会出现一个完整可交互的应用——点击右下角浮动按钮，数字会递增。试着把 ++ 改成 += 2，再点 Run 看看效果：

DartPad 运行环境将在滚动到此处时加载…

这就是 Flutter 开发的日常循环：改代码 → 看结果，在真实项目里由热重载把这个循环压缩到亚秒级。

启动链路：四层结构 ​

flutter create 生成的 lib/main.dart，剥掉注释后核心只有四层：

dart
import 'package:flutter/material.dart';

void main() => runApp(const MyApp());          // ① 入口

class MyApp extends StatelessWidget {          // ② 应用壳
  const MyApp({super.key});
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Flutter Demo',
      theme: ThemeData(colorSchemeSeed: Colors.deepPurple),
      home: const MyHomePage(title: '首页'),   // ③ 首页
    );
  }
}

class MyHomePage extends StatefulWidget {      // ④ 有状态的页面
  const MyHomePage({super.key, required this.title});
  final String title;
  @override
  State<MyHomePage> createState() => _MyHomePageState();
}
  1. main()：一切从这里开始，runApp() 把根 Widget 交给 Flutter 框架
  2. MyApp：应用外壳，持有主题、路由等全局配置，通常是无状态的
  3. MaterialApp：Material Design 风格的应用容器，提供导航、主题、国际化等基础设施
  4. MyHomePage：真正干活的页面，因为有计数器状态，所以是 StatefulWidget

状态的读写：setState 是第一课 ​

计数器的核心逻辑在 _MyHomePageState 里：

dart
class _MyHomePageState extends State<MyHomePage> {
  int _counter = 0;                     // 状态数据

  void _incrementCounter() {
    setState(() {                       // 告诉框架：状态变了
      _counter++;
    });                                 // 框架随后重建本 Widget
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(widget.title)),
      body: Center(
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            const Text('按钮被点击的次数：'),
            Text(
              '$_counter',
              style: Theme.of(context).textTheme.headlineMedium,
            ),
          ],
        ),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: _incrementCounter,   // 点击触发状态变更
        child: const Icon(Icons.add),
      ),
    );
  }
}

理解这一页，就理解了 Flutter 的半壁江山：

  • UI = f(state)：界面是状态的函数。你不「改界面」，你改状态，框架负责重建界面
  • setState 不是赋值器：它只是通知机制，把修改包在里面是为了语义清晰
  • build 会被反复调用：所以它必须「快且无副作用」，绝不能在里面发请求、写数据库
  • widget.title：在 State 里通过 widget. 访问所属 Widget 的属性

动手改造：三步验证理解 ​

在上面的运行框里依次完成这三个小改造（改完点 Run）：

① 改文案：把 'You have pushed the button this many times:' 改成中文。

② 加速度：把 _counter++ 改成 _counter += 5。

③ 加按钮（进阶）：在浮动按钮上方加一个「归零」按钮，提示：

dart
TextButton(
  onPressed: () => setState(() => _counter = 0),
  child: const Text('归零'),
)

三步都顺利完成，说明你已经掌握了「状态变更 → 界面更新」的完整闭环。

项目结构速览 ​

真实项目中，flutter create 生成的目录各司其职：

my_first_app/

│   └── main.dart

pubspec.yaml

常见坑 ​

高频踩坑点

  1. 改了状态界面不动：十有八九是赋值发生在 setState 之外。记住：任何希望触发界面刷新的状态变更，都必须包在 setState(() { ... }) 里。
  2. 在 build 里写副作用：build 里发网络请求会导致无限循环请求。副作用请放 initState 或事件回调。
  3. 滥用全局变量当状态：模块级变量改了不会触发重建，状态必须放在 State（或状态管理框架）里。
  4. const 乱加或漏加：构造参数完全不变的 Widget 建议加 const（如 const Text('...')），可减少重建开销；但含有变量的不能加。

课后练习 ​

  1. 把计数器改造成「步进可配置」：页面顶部显示当前步长，再加一个按钮在 1 / 2 / 5 之间循环切换步长。
  2. 给「归零」按钮加上条件：仅当计数大于 0 时才可点击（提示：onPressed 传 null 即禁用）。
  3. 把首页标题从硬编码改为通过 MyHomePage 构造参数传入，理解数据从父到子的流动。
