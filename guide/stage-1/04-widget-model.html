Widget 心智模型 ​

学习目标 ​

学完本章，你将能够：

  • 建立「一切皆 Widget」的心智模型，理解 Widget 是配置的不可变描述
  • 区分 StatelessWidget 与 StatefulWidget 的适用场景
  • 理解 initState / didUpdateWidget / dispose 等生命周期回调的调用时机
  • 掌握「组合而非继承」构建 UI 的 Flutter 思维
  • 初步认识 Widget / Element / RenderObject 三棵树（详解见阶段四）

核心一句话

Flutter 的 UI = Widget 的嵌套树。你不「改界面」，你「改配置」，框架负责重建差异。

Widget 是什么 ​

Widget 不是屏幕上的像素，也不是真正的渲染对象——它只是一份轻量、不可变、描述性的数据。它的职责只有一个：告诉框架「我想在屏幕上长什么样」。

dart
Text('Hello Flutter', style: TextStyle(fontSize: 24, color: Colors.blue))

这一行代码创建了一个 Text Widget 实例，里面装的全部是参数值。Widget 本身几乎没有运行时开销，两个参数一样的 Text 在 Dart 里可以被认为是等价的。

关键认知

Widget 是不可变的（immutable）。状态变化时不是修改同一个 Widget，而是创建一个新的 Widget 实例，让框架比较差异后高效重建。

两类 Widget：Stateless vs Stateful ​

所有你写的 Widget 最终都继承自这两个基类之一。

StatelessWidget：只配置，不持有状态 ​

适合：纯展示组件、不随用户交互变化的 UI 片段。

dart
class Greeting extends StatelessWidget {
  final String name;       // final 关键字 = 不可变配置
  const Greeting({super.key, required this.name});

  @override
  Widget build(BuildContext context) {
    return Text('你好, $name！');
  }
}
运行示例

查看完整源码
dart
import 'package:flutter/material.dart';

// StatelessWidget：只有配置，没有可变状态
// 每次重建都是「重新描述」，框架负责比对差异

class Greeting extends StatelessWidget {
  final String name;
  const Greeting({super.key, required this.name});

  @override
  Widget build(BuildContext context) {
    return Text('你好, $name！');
  }
}

void main() {
  runApp(const MaterialApp(
    home: Scaffold(
      body: Center(child: Greeting(name: 'Flutter')),
    ),
  ));
}

StatefulWidget：持有可变状态 ​

适合：需要响应点击、输入、动画等动态变化的场景。状态数据封装在独立的 State 对象里。

dart
class Counter extends StatefulWidget {
  const Counter({super.key});            // Widget 本身仍不可变
  @override
  State<Counter> createState() => _CounterState(); // 把状态托管给 State
}

class _CounterState extends State<Counter> {
  int _count = 0;                         // ← 可变状态

  void _increment() {
    setState(() => _count++);             // 告诉框架：状态变了，重建
  }
  // build 里用 widget.xxx 访问 Widget 传入的配置
  @override
  Widget build(BuildContext context) { ... }
}
运行示例
DartPad 运行环境将在滚动到此处时加载…
查看完整源码
dart
import 'package:flutter/material.dart';

// StatefulWidget：持有可变状态，状态数据封装在 State 对象里

class Counter extends StatefulWidget {
  const Counter({super.key});

  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  int _count = 0;

  void _increment() {
    setState(() => _count++); // 只有 setState 内的修改才触发重建
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      mainAxisAlignment: MainAxisAlignment.center,
      children: [
        Text('点击了 $_count 次',
            style: Theme.of(context).textTheme.headlineMedium),
        const SizedBox(height: 16),
        ElevatedButton(onPressed: _increment, child: const Text('点我')),
      ],
    );
  }
}

void main() => runApp(const MaterialApp(
      home: Scaffold(body: Center(child: Counter())),
    ));

选型口诀

  • 能 Stateless 就 Stateless——少一层状态管理，更易测试
  • 只有「确实需要随时间变化的数据」时才 Stateful
  • const 构造函数优先加：const Text('Hi') 比 Text('Hi') 可优化更多

生命周期：State 的一生 ​

State 从被创建到被销毁，会依次走过几个关键回调。写 Flutter 应用时，80% 的 bug 都和生命周期时序有关。

回调触发时机典型用途
initStateState 首次创建后、首次 build 之前初始化变量、订阅监听器、发首屏网络请求
didChangeDependenciesinitState 之后 / 依赖的 InheritedWidget 变化时依赖 context 的配置（如 MediaQuery）
build每次需要渲染 Widget 时构建 UI，必须无副作用、足够快
didUpdateWidget父 Widget 重建导致该 Widget 被替换旧 Widget 与新 Widget 的配置比对
disposeWidget 被永久移除时取消订阅、释放控制器、关闭动画
运行示例（控制台观察调用顺序）
DartPad 运行环境将在滚动到此处时加载…

运行后观察控制台输出：第一次看到 initState → build，当 Widget 被移除时会看到 dispose。

查看完整源码
dart
import 'package:flutter/material.dart';

// StatefulWidget 生命周期演示
// 在控制台观察 initState / didUpdateWidget / dispose 的调用时机

class LifeCycleDemo extends StatefulWidget {
  final String label;
  const LifeCycleDemo({super.key, required this.label});

  @override
  State<LifeCycleDemo> createState() => _LifeCycleDemoState();
}

class _LifeCycleDemoState extends State<LifeCycleDemo> {
  @override
  void initState() {
    super.initState();
    print('🟢 initState → 首次构建前，label=${widget.label}');
  }

  @override
  void didUpdateWidget(covariant LifeCycleDemo oldWidget) {
    super.didUpdateWidget(oldWidget);
    if (oldWidget.label != widget.label) {
      print('🟡 didUpdateWidget → label 变更: ${oldWidget.label} → ${widget.label}');
    }
  }

  @override
  void dispose() {
    print('🔴 dispose → 组件被销毁');
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    print('🔵 build → 重建');
    return Text('状态值: ${widget.label}');
  }
}

void main() => runApp(const MaterialApp(
      home: Scaffold(body: Center(child: LifeCycleDemo(label: '初始'))),
    ));

高频踩坑

  1. 在 build 里发网络请求：build 会被高频调用，导致无限循环请求。正确做法：initState 里发。
  2. 忘记 dispose 控制器：AnimationController、ScrollController、TextEditingController、StreamSubscription 如果不 dispose，会造成内存泄漏。
  3. 在 initState 里用 context 取 InheritedWidget：此时 context 还没挂载完成，用 WidgetsBinding.instance.addPostFrameCallback 延后一帧。

组合优于继承 ​

Flutter 的 UI 哲学是像搭积木一样堆 Widget，而不是通过继承改变行为。下面这个卡片组件只用 Row + Column + Padding + Container + CircleAvatar + Text 几个基础 Widget 就搭出来了：

运行示例
DartPad 运行环境将在滚动到此处时加载…
查看完整源码
dart
import 'package:flutter/material.dart';

// 组合优于继承：用 Row + Column + Padding + Container 搭出一张卡片
// 把「搭积木」思维打透——Flutter 的 UI 本质就是 Widget 的嵌套

class UserCard extends StatelessWidget {
  final String name;
  final String role;
  final IconData icon;

  const UserCard({
    super.key,
    required this.name,
    required this.role,
    required this.icon,
  });

  @override
  Widget build(BuildContext context) {
    return Padding(
      padding: const EdgeInsets.all(16),
      child: Container(
        padding: const EdgeInsets.all(16),
        decoration: BoxDecoration(
          color: Colors.white,
          borderRadius: BorderRadius.circular(12),
          boxShadow: [
            BoxShadow(
              color: Colors.black.withValues(alpha: 0.1),
              blurRadius: 8,
              offset: const Offset(0, 2),
            ),
          ],
        ),
        child: Row(
          children: [
            CircleAvatar(
              backgroundColor: Colors.blue.shade50,
              child: Icon(icon, color: Colors.blue.shade700),
            ),
            const SizedBox(width: 12),
            Column(
              crossAxisAlignment: CrossAxisAlignment.start,
              mainAxisSize: MainAxisSize.min,
              children: [
                Text(name,
                    style: const TextStyle(
                        fontWeight: FontWeight.w600, fontSize: 16)),
                Text(role,
                    style: TextStyle(color: Colors.grey.shade600, fontSize: 13)),
              ],
            ),
          ],
        ),
      ),
    );
  }
}

void main() => runApp(MaterialApp(
      home: Scaffold(
        backgroundColor: Colors.grey.shade100,
        body: const Center(
          child: Column(
            mainAxisSize: MainAxisSize.min,
            children: [
              UserCard(name: '张三', role: 'Flutter 工程师', icon: Icons.code),
              SizedBox(height: 8),
              UserCard(name: '李四', role: '产品经理', icon: Icons.design_services),
            ],
          ),
        ),
      ),
    ));

这种写法的好处：

  • 职责单一：每个小 Widget 只管自己的渲染
  • 易于组合：换背景色？改 BorderRadius？改文字？随便调哪层都不影响其他
  • 可复用：抽出来当独立 Widget（如上面的 UserCard），两处页面都能用

深度观察

Flutter 内部也是这样写的——Scaffold 是 Material + SafeArea + AnimatedBody + AppBar + FloatingActionButton + Drawer + BottomNavigationBar 的组合体，每个子组件又是一堆更基础 Widget 的嵌套。

三棵树初探（阶段四精讲） ​

Flutter 运行时在后台维护了三棵平行的树：

树角色类比
Widget 树不可变配置，框架重建时被创建/丢弃HTML 模板
Element 树Widget 与 RenderObject 之间的中间层，管理生命周期和位置React Fiber
RenderObject 树真正参与布局（layout）和绘制（paint）的对象DOM + CSSOM

写业务代码时你几乎只用 Widget 树，但遇到布局问题（溢出、约束冲突）或性能问题时，理解另外两棵树的工作原理能帮你高效定位。我们把更深入的三棵树讲解放到阶段四「Flutter 内部原理」。

常见坑 ​

高频踩坑点

  1. 把状态放在 Widget 类里：Widget 重建时会被重新创建，里面存的数据直接丢失。状态必须放 State。
  2. setState 外部改状态期望刷新：setState 只是通知机制，你写 _count++ 而不包在 setState 里，界面绝对不会动。
  3. build 里做耗时操作：build 要求 16ms 内完成（60fps）。把请求、计算、JSON 解析都放别处（initState / 事件回调 / FutureBuilder）。
  4. 漏加 const 导致无谓重建：两个完全相同的 const Text('Hi') 在重建时框架会复用；非 const 则每次都新建实例。

课后练习 ​

  1. Stateless → Stateful：把 03-first-app 里的计数器 MyHomePage（Stateful）里的纯展示子组件抽成 Stateless，比如 _CounterDisplay(amount: _counter)，观察代码整洁度。
  2. 生命周期实战：在你自己的 CounterState 里打印所有生命周期，热重载后观察 didUpdateWidget 的触发。
  3. 卡片改造：复制 UserCard 改成「产品卡片」——加一个图片占位、一个价格、一个「加入购物车」按钮。尝试给按钮加点击回调（onPressed 需要 StatefulWidget 或回调参数）。
  4. 组合思维训练：用 5 个基础 Widget 以内，搭出一个天气卡片（图标 + 温度 + 城市 + 天气描述）。
