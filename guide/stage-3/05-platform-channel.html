平台通道 ​

学习目标 ​

学完本章，你将能够：

  • 理解 Flutter 如何通过 MethodChannel / EventChannel / BasicMessageChannel 与原生通信
  • 在 Android（Kotlin/Java）和 iOS（Swift/ObjC）写原生代码
  • 用 Pigeon 生成类型安全的桥接代码
  • 了解 FFI、Platform Views 等更深度的跨语言方案

三种 Channel 定位

  • MethodChannel：Flutter 主动调原生方法（请求-响应），最常用
  • EventChannel：原生推事件给 Flutter（传感器、定位、蓝牙扫描结果）
  • BasicMessageChannel：双向异步消息（类似 WebSocket）

三者底层都是同一个 Platform Channel 机制，只是通信模式不同。

MethodChannel：最常用的跨语言调用 ​

Flutter 侧发起调用，原生侧接收并返回结果：

dart
// Flutter 侧
final channel = MethodChannel('com.example/app_info');

Future<String> getAppVersion() async {
  final version = await channel.invokeMethod('getVersion');
  return version as String;
}

Android 侧（Kotlin） ​

kotlin
class MainActivity : FlutterActivity() {
    override fun configureFlutterEngine(flutterEngine: FlutterEngine) {
        super.configureFlutterEngine(flutterEngine)
        MethodChannel(flutterEngine.dartExecutor.binaryMessenger, "com.example/app_info")
            .setMethodCallHandler { call, result ->
                when (call.method) {
                    "getVersion" -> result.success(BuildConfig.VERSION_NAME)
                    "getDeviceModel" -> result.success(Build.MODEL)
                    else -> result.notImplemented()
                }
            }
    }
}

iOS 侧（Swift） ​

swift
import UIKit
import Flutter

@main
class AppDelegate: FlutterAppDelegate {
    override func application(
        _ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
    ) -> Bool {
        GeneratedPluginRegistrant.register(with: self)
        
        let controller = window?.rootViewController as! FlutterViewController
        let channel = FlutterMethodChannel(name: "com.example/app_info",
                                            binaryMessenger: controller.binaryMessenger)
        channel.setMethodCallHandler { call, result in
            switch call.method {
            case "getVersion":
                result(FlutterMethodNotImplemented) // 或返回实际值
            default:
                result(FlutterMethodNotImplemented)
            }
        }
        return super.application(application, didFinishLaunchingWithOptions: launchOptions)
    }
}

EventChannel：原生推事件 ​

适合原生做轮询、传感器、持续更新的场景：

dart
// Flutter 侧监听
final channel = EventChannel('com.example/sensor');
channel.receiveBroadcastStream().listen((event) {
  print('传感器数据: $event');
}, onError: (e) => print('错误: $e'));

原生侧周期性 Sink.success(event)，停止时调用 Sink.endOfStream()。

Pigeon：类型安全的生成代码 ​

手写 Channel 代码的最大问题是类型不安全——Flutter 传了个 Map，原生要猜 key；原生返回的是 int 还是 string 也不确定。Pigeon 通过声明式接口自动生成两端代码：

dart
// pigeon.dart（接口定义）
import 'package:pigeon/pigeon.dart';

@HostApi()
abstract class AppInfoApi {
  String getVersion();
  DeviceInfo getDeviceInfo();
}

class DeviceInfo {
  final String model;
  final String osVersion;
  DeviceInfo({required this.model, required this.osVersion});
}

运行生成：dart run pigeon --input pigeon.dart，生成 Android (Kotlin/Java) + iOS (Swift/ObjC) + Dart 三端代码，类型完全对齐。

什么时候用 Pigeon

  • 跨平台都要写原生代码 → 必须用 Pigeon，避免手动维护两份不一致的桥
  • 接口复杂、有数据类 → 强烈推荐
  • 只有一个简单方法调用 → 手写也无妨

Platform Views：嵌入原生 UI ​

Flutter 默认把所有 UI 交给 Skia 自己画，所以能跨平台。但某些场景需要用原生控件：WebView、地图、视频播放器、Android 原生 RecyclerView。

dart
import 'package:webview_flutter/webview_flutter.dart';

WebViewWidget(
  controller: WebViewController()
    ..loadRequest(Uri.parse('https://flutter.cn')),
)

WebView / GoogleMaps / video_player 这些流行包都是用 Platform Views 实现的。性能上 Platform Views 比 Flutter 自己画差一些（需要 TextureLayer 桥接），非必要不推荐。

FFI：Dart 直接调 C 代码 ​

更深度的跨语言方案——Dart FFI (Foreign Function Interface) 允许直接调用 C / C++ / Rust 写的动态库：

dart
import 'dart:ffi';

final lib = DynamicLibrary.open('libcrypto.so');
final SSL_CTX_new = lib.lookupFunction<Pointer Function(), Pointer Function()>('SSL_CTX_new');

FFI 不走 Platform Channel，性能是原生级的。适合加密、编解码、图像处理、游戏引擎等对性能极致敏感的场景。

常见坑 ​

高频踩坑点

  1. Channel 名字拼写不一致：Flutter 侧和原生侧的 Channel 字符串必须一字不差，空格都不能多。建议用常量统一定义。
  2. 返回类型不匹配：Flutter invokeMethod 返回 dynamic，需要手动 as String / as int 转换；类型不匹配会抛异常，用 try-catch 包好。
  3. 主线程 vs 后台线程：Android 原生方法调用在主线程（UI 线程）执行，耗时操作要开 IO 线程再 result.success。iOS 同理。
  4. EventChannel 忘记 cancel 订阅：和 StreamSubscription 一样，listen 返回的订阅在 dispose 里必须 cancel。
  5. Pigeon 接口变更后忘记重生成：手动改生成的 .g.dart 文件会被下次 pigeon 覆盖。改接口定义后一定重新跑 pigeon。

课后练习 ​

  1. 版本号桥接：用 MethodChannel 分别在 Android 和 iOS 上实现 getAppVersion，Flutter 首页显示当前应用版本。
  2. EventChannel 电池监听：Android 侧注册 BatteryManager BroadcastReceiver，每秒通过 EventChannel 把电量推给 Flutter，Flutter 侧实时显示。
  3. Pigeon 改造：把第一题的 MethodChannel 用 Pigeon 重写，生成两端代码，对比两种写法的类型安全程度。
  4. Platform View 实战：用 webview_flutter 包嵌入一个网页，用 JavaScriptChannel 让网页能调用 Flutter 的 showDialog。
