性能分析与优化 ​

学习目标 ​

学完本章，你将能够：

  • 使用 Flutter DevTools 的 Performance / Memory / Timeline 面板定位性能问题
  • 识别常见性能陷阱：build 阻塞、布局溢出、OOM、jank
  • 应用性能优化三板斧：const 构造、懒加载、缓存
  • 了解 Jank（掉帧）的根因：GPU / CPU / Raster 线程谁在卡

Flutter 渲染线程分工

  • UI 线程：Dart 代码跑在这里（build / layout），60fps 要求每帧 16ms 以内
  • Raster 线程：把 UI 线程生成的 Layer 树光栅化成纹理
  • GPU 线程：执行 OpenGL / Metal 命令

任何一条超过 16ms 就掉帧。DevTools Performance 面板能看每条线的耗时。

性能分析工具：DevTools ​

bash
# 1. 用 profile 模式启动（比 release 模式多 DevTools 支持）
flutter run --profile

# 2. 或对已构建的 release APK 做 profile
flutter build apk --profile

# 3. DevTools 通过 `flutter pub global activate devtools` 启动
flutter pub global run devtools

关键面板：

面板看什么
PerformanceTimeline 看 UI / Raster / GPU 线程各帧耗时，看 build / layout / paint 哪些 Widget 花时间长
Memory内存分配图、GC 频率、泄漏对象、Snapshot 对比
Widget Inspector选中某个 Widget 看它的 build 调用栈、rebuild 次数
CPU Profiler具体函数耗时排行，定位哪个 Dart 函数在卡
Network所有网络请求的发起 / 响应时间

什么时候用什么面板

  • UI 卡 / 掉帧 → Performance Timeline + Widget Inspector 看哪个 Widget 在重建
  • 内存持续涨 → Memory 面板看 Snapshot 对比 + 搜索泄漏对象
  • 启动慢 → Performance 看第一帧之前的 Timeline
  • 网络慢 → Network 面板看请求耗时和瀑布图

常见性能陷阱 ​

1. build 里做重操作 ​

dart
// ❌ 错误
@override
Widget build(BuildContext context) {
  final data = heavyJsonParse(_rawString); // 每次 build 都 parse
  return Text(data.toString());
}

// ✅ 正确：把计算移出 build
final _parsed = heavyJsonParse(_rawString); // initState / 构造时算好
@override
Widget build(BuildContext context) {
  return Text(_parsed.toString());
}

2. 无意义的 setState ​

dart
// ❌ 整棵子树重建
void _toggle() {
  setState(() { _flag = !_flag; }); // 哪怕 flag 没变也触发重建
}

// ✅ 条件更新
void _toggle() {
  final next = !_flag;
  if (next != _flag) setState(() => _flag = next);
}

3. ListView 未懒加载 ​

dart
// ❌ ListView 默认 constructor：一次性构建全部 1000 项
ListView(children: List.generate(1000, (i) => Item(i)));

// ✅ ListView.builder：只构建可见的 6-8 项
ListView.builder(
  itemCount: 1000,
  itemExtent: 56,
  itemBuilder: (_, i) => Item(i),
);

4. const 漏掉 / 乱加 ​

dart
// ❌ 每次重建都新建对象
Text('你好'),                    // const Text('你好')
Container(padding: EdgeInsets.all(8)), // const EdgeInsets.all(8) 提前算好

// ✅ 正确加 const，框架复用 Widget
const Text('你好'),
const EdgeInsets.all(8),

// ❌ 错误：有变量还加 const（编译报错，但不要强行加）
const Text(_name),                // _name 是变量，不能 const

IDE 自动 const 提示

Android Studio / VS Code 里，光标停在可加 const 的位置会有绿色波浪下划线提示，快速修复 Cmd+Shift+P → "Quick Fix"。

5. Widget 重建无差别级联 ​

父 Widget 重建 → 所有子 Widget 都跟着重建。正确做法：

  • 纯展示子组件抽成独立的 StatelessWidget（框架按类型判断可以跳过重建）
  • 高频变化的部分和低频变化的部分拆进不同 Widget 层级

6. Image 列表 OOM ​

大图列表常见问题：图片还在显示、用户已滑走但内存不释放。

dart
// ✅ 用 cacheWidth / cacheHeight 自动下采样
Image.network(url, width: 300, cacheWidth: 600),

// ✅ 用 cached_network_image（带自动缓存 + 占位图 + 错误图）
CachedNetworkImage(
  imageUrl: url,
  placeholder: (_, __) => CircularProgressIndicator(),
  errorWidget: (_, __, ___) => Icon(Icons.broken_image),
  memCacheWidth: 300,
),

性能优化实战清单 ​

清单 1：Build 阶段 ​

  • [ ] 启动 DevTools Performance，看 UI 线程耗时最长的帧
  • [ ] 把耗时计算移出 build（initState / 构造时预计算）
  • [ ] 给所有固定 Widget 加 const
  • [ ] 拆分高频变化和低频变化到不同 Widget 层级
  • [ ] 用 AnimatedBuilder / AnimatedWidget 只重建动画相关子树

清单 2：布局阶段 ​

  • [ ] 避免嵌套多层 Row / Column + Expanded（Flutter 布局是 O(n²) 在极端嵌套下）
  • [ ] 固定高度列表用 itemExtent 让框架跳过测量
  • [ ] 避免给 Widget 设过大的 width/height（触发 relayout）
  • [ ] 复杂布局考虑用 CustomMultiChildLayout / Flow

清单 3：Memory ​

  • [ ] dispose 释放所有控制器（AnimationController / ScrollController / StreamSubscription）
  • [ ] 大图下采样（cacheWidth / memCacheWidth）
  • [ ] ListView 用 builder（自动销毁可见外项）
  • [ ] 用 Memory Snapshot 对比确认无泄漏

清单 4：启动速度 ​

  • [ ] 用 flutter run --profile 看 first frame 时间
  • [ ] 把重量级初始化移到 first frame 之后（WidgetsBinding.instance.addPostFrameCallback）
  • [ ] 首屏只渲染必要 UI，其余用 Shimmer 占位 + 异步加载
  • [ ] 用 flutter_deferred_components（原生）或 Isolate（Dart）延迟加载

常见坑 ​

高频踩坑点

  1. release 模式调试：release 模式优化激进，DevTools 看不到完整 Timeline。用 profile 模式调试性能，release 只做最终发布。
  2. 过度优化：const 漏了性能差，但到处加 const（变量值还在变）编译直接报错。优化建立在测量数据之上，别凭空猜瓶颈。
  3. Memory leak 假象：Dart 的 GC 不是即时的，短时间内内存涨了不一定是泄漏。用 Snapshot 对比两次状态差——持续增长才是泄漏。
  4. Platform View 性能差：WebView / GoogleMap 等 Platform View 每帧都要桥接纹理，列表里大量 Platform View 会极卡。非必要别滥用。
  5. 只看 UI 线程：Raster 线程也是瓶颈高发地——复杂绘制、阴影、圆角过多都会拖慢 Raster。

课后练习 ​

  1. DevTools 实战：跑你已有的计数器 app（profile 模式），在 Performance Timeline 里观察 setState 后 UI 线程耗时多少。试着用 AnimatedBuilder 替换并对比。
  2. const 漏检：在项目里用 IDE 快速修复加所有能加的 const，重新跑 profile，观察 Timeline 总耗时变化。
  3. 图片 OOM 复现：写一个 ListView.builder，加载 50 张 10MB 的无压缩大图，看 Memory 面板怎么变化；然后改用 cacheWidth 下采样，再看内存差异。
  4. 优化清单落地：对一个真实项目（或新建一个 demo）跑四个清单，提交 PR 前附上优化前后的 Timeline 截图和量化数据（如 "UI 线程耗时从 12ms 降到 3ms"）。
