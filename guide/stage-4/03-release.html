发布与热重载 ​

学习目标 ​

学完本章，你将能够：

  • 完成 Android APK / AAB 和 iOS IPA 的签名打包
  • 配置 fastlane 实现一键构建 + 上传 App Store / Google Play
  • 理解热重载的原理、限制和正确使用姿势
  • 使用 DevTools 的 Hot Restart / Full Restart 解决热重载失效问题
  • 掌握版本号管理（semver + build number 递增）

热重载三兄弟

  • Hot Reload（热重载）：保留 app 状态，替换 Widget 树，亚秒级——最常用
  • Hot Restart：重置 app 状态，重启 Flutter 引擎——比 reload 慢，但比完整重启快
  • Full Restart：彻底 kill app 再启动，带完整重新编译——只有改了 main / 启动参数 / 原生代码时才需要

Android 发布 ​

1. 生成签名密钥 ​

bash
keytool -genkeypair -v -keystore upload-keystore.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias upload
# 记下密码！丢了 Play Console 上就再也不能更新这个 App

2. 配置签名 ​

创建 android/app/key.properties（加入 .gitignore！）：

properties
storePassword=你的密钥密码
keyPassword=你的别名密码
keyAlias=upload
storeFile=../upload-keystore.jks

在 android/app/build.gradle.kts（或 build.gradle）里配置 signingConfigs：

kotlin
def keystorePropertiesFile = rootProject.file("key.properties")
def keystoreProperties = new Properties()
keystoreProperties.load(new FileInputStream(keystorePropertiesFile))

android {
    signingConfigs {
        create("release") {
            keyAlias = keystoreProperties["keyAlias"] as String
            keyPassword = keystoreProperties["keyPassword"] as String
            storeFile = file(keystoreProperties["storeFile"] as String)
            storePassword = keystoreProperties["storePassword"] as String
        }
    }
    buildTypes {
        release {
            signingConfig = signingConfigs.getByName("release")
            isMinifyEnabled = true      // 开启代码混淆
            isShrinkResources = true    // 移除未使用资源
        }
    }
}

3. 构建 AAB（推荐 Google Play 用） ​

bash
flutter build appbundle --release
# 产物在 build/app/outputs/bundle/release/app-release.aab
# 上传到 Play Console → 内部测试 → 正式发布

APK 也能出（给第三方渠道分发）：

bash
flutter build apk --release --split-per-abi
# 按 CPU 架构拆分成多个 APK，包体更小

iOS 发布 ​

1. Xcode 配置 ​

用 Xcode 打开 ios/Runner.xcworkspace，Signing & Capabilities 里选 Team，Bundle Identifier 改成你的（com.yourname.appname）。

2. 构建 IPA ​

bash
# 自动配置签名后，直接 archive
flutter build ipa --release \
  --export-method=app-store \
  --export-options-plist=ios/ExportOptions.plist

# 产物在 build/ios/ipa/Runner.ipa
# 上传用 Transporter 或 xcrun altool
xcrun altool --upload-app -f build/ios/ipa/Runner.ipa -u <你的 Apple ID>

3. App Store Connect 流程 ​

  1. IPA 上传后 10-30 分钟处理
  2. 处理完成后 App Store Connect 创建新版本
  3. 填描述、截图、隐私声明
  4. 提交审核（首次通常 24-48h，后续增量 4-24h）
  5. 审核通过后手动发布或设置自动发布

fastlane：一键流水线 ​

fastlane 把构建 + 签名 + 上传 + 通知全自动化：

ruby
# ios/fastlane/Fastfile
default_platform(:ios)

platform :ios do
  desc "构建 + 上传 App Store"
  lane :release do
    setup_codesigning(include_bitcode: false)
    build_app(scheme: "Runner", workspace: "Runner.xcworkspace")
    upload_to_app_store(skip_waiting_for_build_processing: true)
    slack(message: "🚀 #{lane_context[SharedValues::BUILD_NUMBER]} 已上传，等待审核")
  end
end

# android/fastlane/Fastfile
default_platform(:android)

platform :android do
  desc "构建 AAB 并上传 Play Console"
  lane :release do
    gradle(task: "bundleRelease")
    upload_to_play_store(track: "internal")
    slack(message: "🚀 Android 新版本已上线 Play 内部测试")
  end
end
bash
cd ios && bundle exec fastlane release      # 一键发 iOS
cd android && bundle exec fastlane release  # 一键发 Android

热重载原理与正确姿势 ​

工作原理 ​

  1. Hot Reload：Flutter 引擎保留 VM 状态，把新的 Dart 代码通过 send_port 热注入到正在运行的 isolate，重建 Widget 树。状态不丢、执行栈不重置。
  2. Hot Restart：重启 Dart isolate，状态重置，重新跑 main。比完整 compile + 启动快（引擎不重启），但比 reload 慢。
  3. Full Restart：kill 整个 app 进程，重新编译 AOT/JIT，完全冷启动。

什么能热重载、什么不能 ​

改什么Hot ReloadHot RestartFull Restart
Widget 布局、颜色、文案✅✅✅
新增 / 删除 Widget✅✅✅
状态逻辑、方法体✅✅✅
StatefulWidget 的 state 字段初始值❌ 保留旧值✅✅
新增字段⚠ 部分支持✅✅
main() 入口改动❌✅✅
原生代码（Kotlin/Swift）❌❌✅
pubspec.yaml 依赖❌❌✅
插件版本❌❌✅

// ✅ 正确：状态字段初始值改动后 Hot Restart

// ❌ 改了 State 的构造函数参数，但没加 key 区分
// ✅ Hot Restart 或手动 dispose + recreate

版本号管理 ​

pubspec.yaml 里的 version 字段是 主.次.修订+构建号：

yaml
version: 1.2.3+102
#   主 次 修订  构建号
  • 语义化版本 1.2.3 面向用户（显示在商店）
  • 构建号 102 面向系统（Android 和 iOS 都要求递增）
  • 发版时：flutter version 1.3.0+103 自动递增
  • CI 里自动递增：每次构建 build number +1

常见坑 ​

高频踩坑点

  1. Android keystore 丢了：Google Play 规定同一个 keystore 签名才能更新。备份到密码管理器，换电脑开发必须有。
  2. AAB 签名校验失败：Play Console 要求 upload key（Play App Signing）配置。如果还没开 Play App Signing，旧 keystore 就是 upload key，丢了等于 app 废了。
  3. iOS 签名过期：Developer Certificate 有效期 5 年，但 Distribution Certificate 现在也是 5 年——过期前记得续期。
  4. 版本号冲突：发版忘记递增 build number，App Store / Play Console 都不会接受。
  5. 热重载后 setState 崩溃：状态结构大改后（比如字段类型变了），热重载保留的旧状态与新代码不兼容。Hot Restart 即可解决。

课后练习 ​

  1. Android 完整发版：为项目生成签名 → 配置 build.gradle → 构建 AAB → 生成 Play Console 账号上传（哪怕不传正式商店，走完整个构建流程）。
  2. iOS 完整发版：Xcode archive 导出 IPA → Transporter 上传 App Store Connect。
  3. fastlane 集成：给项目写一套 fastlane 配置（android + ios 都可以），实现构建 + 上传的一键化，并在 GitHub Actions 里调用。
  4. 热重载实验：在计数器示例里，分别尝试修改以下内容，记录哪种重载能生效：State 字段初始值、新增 State 字段、修改 widget key、修改 onPressed 回调逻辑、修改 main()。
