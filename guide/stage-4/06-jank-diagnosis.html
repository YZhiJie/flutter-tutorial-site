卡顿与 shader jank 定位 ​

学习目标 ​

学完本章，你将能够：

  • 用 Timeline 里的 Frame / Raster 事件判断卡顿发生在 UI 线程还是 Raster 线程
  • 把一帧拆成 Build → Layout → Paint → Compositing 四段，逐段定位超预算环节
  • 识别 shader 编译 jank：为什么偏偏「第一次」进页面会卡 200~800ms
  • 用 --trace-skia 与 screenshot --type=skia 导出 skp，并在 Skia Debugger 里分析
  • 理解 Impeller 预编译对 shader jank 的影响，会用 --enable-impeller 做对照实验
  • 按判定树从「掉帧现象」一路收敛到具体 Widget 与具体写法

本章与阶段三的边界

阶段三《性能分析基础》讲的是「DevTools 有哪几个面板、const / ListView.builder 怎么用」。本章不重复这些，只回答一个问题：这一帧为什么慢，慢在哪条线程、哪一段、哪个 Widget。

一帧的预算：16.7ms 不是唯一答案 ​

「掉帧」（jank）指这一帧没在刷新周期内画完。预算随屏幕刷新率变化：

刷新率单帧预算常见设备
60Hz16.7ms大多数中低端机
90Hz11.1ms部分中端机
120Hz8.3msProMotion iPhone、旗舰 Android
144Hz6.9ms电竞屏、游戏手机

关键：这个预算是 UI 线程 + Raster 线程的总和，不是每条线程各有一份。UI 线程花 10ms、Raster 花 9ms，合起来 19ms，这一帧就已经迟到。

测之前先确认模式

只在 profile 模式（flutter run --profile）下测。debug 模式带断言、JIT 和调试开销，数字没有参考价值；release 模式又拿不到完整 Timeline。profile 是「AOT 编译 + 保留 trace 开关」的唯一组合。

先分线程：Frame 与 Raster 两条横条 ​

Flutter 每帧在 Timeline 上主要看两条：

事件名所属线程含义
FrameUI（Dart）线程从 vsync 回调到生成 Layer 树：build / layout / paint / compositing
RasterRaster 线程把 Layer 树光栅化成纹理并提交给 GPU
Build / Layout / PaintUI 线程Frame 的子事件，逐段拆开
program / shader 相关事件Raster 线程Skia 下编译着色器，见下一节
GPURasterizer 等GPU / IO 线程提交命令、上传纹理，部分设备上会排队

判定步骤：

bash
# 1. profile 模式启动，按 v 打开 DevTools（或手动连）
flutter run --profile

# 2. 复现卡顿（滚动、进新页面、触发动画），在 Performance 面板录 10 秒
# 3. 找最长的那几帧，比较 Frame 与 Raster 谁更长
  • Frame 长、Raster 短 → Dart 侧问题：build 重活、布局过深、paint 复杂
  • Raster 长、Frame 短 → 光栅化问题：过度绘制、大图、阴影裁剪、shader 编译、PlatformView
  • 两条都长且交替 → 多半是 UI 线程偶尔超时导致丢 vsync，先修 UI 线程
  • 两条都不长但手感仍卡 → 查输入延迟、Platform 通道、原生 View 桥接

再分阶段：把 Frame 拆成 Build / Layout / Paint ​

展开一帧的子事件，顺序永远是 Build → Layout → Paint → Compositing：

阶段典型耗时常见元凶主要修法
Build1~5ms每帧重建大子树、build 里做计算或 IO、缺 const拆分 Widget、提前算好数据、用 AnimatedBuilder 收窄重建范围
Layout0.5~3ms多层 Row/Column 嵌套、IntrinsicWidth、列表未设 itemExtent降低嵌套、固定尺寸、CustomMultiChildLayout
Paint0.5~4mssaveLayer（整体透明度、BackdropFilter）、大量裁剪与阴影用 withValues 改局部颜色、减少 Clip、用 RepaintBoundary 隔离
Compositing< 1msLayer 数量爆炸合并静态层、收敛 RepaintBoundary

debug 下先「看见」再回 profile 量化：

dart
import 'package:flutter/rendering.dart';

void main() {
  // Timeline 里出现每个 Widget 的 Build 事件（仅 debug 生效）
  debugProfileBuildsEnabled = true;
  // 重绘区域染成彩虹色，一眼看出谁在过度重绘
  debugRepaintRainbowEnabled = true;
  runApp(const MyApp());
}

染色只在 debug 可信

debugRepaintRainbowEnabled 和 Inspector 的「Track widget creation」都依赖 debug 信息。用它找位置，用 profile 量数字，别把 debug 下的毫秒数当结论。

shader 编译 jank：只有第一次会卡 ​

典型症状：第一次进入某页面、或第一次播放某段动画时明显一顿（常见 200~800ms），退出再进就顺滑了。这不是布局问题，而是 着色器编译（shader compilation）：Skia 在首次遇到某种绘制效果（渐变、模糊、圆角 + 阴影组合）时，才把 SkSL（Skia 的着色器中间语言）编译成 GPU 程序；编译发生在 Raster 线程，直接把这一帧顶爆。

识别三步：

  1. Timeline 上 Raster 出现异常长条，且只在首帧或首次交互出现；
  2. 展开长条，能看到 program / shader 编译相关事件（Skia 下形如 GrGLProgramBuilder）；
  3. 同一操作第二次执行不再出现。

抓证据的命令：

bash
# 打开 Skia 追踪，Raster 的绘制细节会进 Timeline
flutter run --profile --trace-skia

# 触发编译时把当时的 skp 落盘，便于离线分析
flutter run --profile --dump-skp-on-shader-compilation

# 导出 skp：App 需以 --trace-skia 运行，vm-service 地址从启动日志里抄
flutter screenshot --type=skia --vm-service-url=http://127.0.0.1:8181/

拿到的 .skp 拖进 Skia Debugger，逐层看 op 列表，确认是哪类绘制（drawRRect + MaskFilter？drawImage + ImageFilter？）触发了新 program。

Skia 时代的标准解法是 SkSL 预热：把常用着色器提前编译好打进产物。

bash
# 带上采集好的 sksl.json 构建（Skia 专用；Impeller 不需要）
flutter build apk --bundle-sksl-path=/tmp/sksl.json

Impeller 换了思路：构建期就把着色器编译成机器码，运行时不再即时编译，因此 shader jank 基本消失；代价是包体略增，个别老设备或特殊效果会走 fallback。

对比项SkiaImpeller
编译时机运行时首次使用（Raster 线程）构建期预编译
首帧 jank常见 200~800ms基本消除
预热手段--bundle-sksl-path不需要
平台状态逐步退场iOS 默认，Android 新版本默认

开关做对照实验：

bash
flutter run --profile --enable-impeller      # 强制开启
flutter run --profile --no-enable-impeller   # 回退 Skia

验证 shader jank 最快的实验

同一页面，分别用 --enable-impeller 与 --no-enable-impeller 在真机冷启动进入，对比首帧 Raster 耗时。差距巨大 → 就是 shader 编译；差距不大 → 去查大图解码与过度绘制。

判定树：从现象收敛到 Widget ​

掉帧
├─ Frame（UI 线程）超预算
│  ├─ Build 长  → Inspector 找重建最多的子树 / build 里的同步计算
│  ├─ Layout 长 → 嵌套深度、Intrinsic、列表缺 itemExtent
│  └─ Paint 长  → saveLayer / Clip / 阴影 / 自绘逻辑
├─ Raster 超预算
│  ├─ 只在首帧慢 → shader 编译（Skia）或大图首次解码
│  ├─ 持续慢     → 过度绘制、超大圆角阴影、PlatformView 纹理桥接
│  └─ 间歇慢     → 图片解码线程抢占、GC
└─ 都不长但感知卡 → 触摸响应链路、Platform 通道、首帧未上屏

收敛到 Widget 的两个手段：

  • Widget Inspector（debug）：选中可疑子树，看 rebuild 次数与 build 耗时，配合 Repaint Rainbow 看重绘范围。
  • RepaintBoundary 二分法：给可疑区域包一层隔离，若 Raster 从 14ms 降到 4ms，说明问题就在这棵子树。
dart
// 动的和不动的一起画，等于每帧重绘全屏；切开后静态部分只画一次
Stack(
  children: [
    RepaintBoundary(child: _StaticBackground()),
    _AnimatedBadge(), // 每帧重绘，但范围被限制在自己的 layer 内
  ],
)

可运行示例 ​

DartPad 运行环境将在滚动到此处时加载…
查看完整源码
dart
import 'package:flutter/material.dart';
// 逐帧耗时：蓝 = UI 线程，橙 = Raster 线程，红线 = 单帧预算；可切 60/120Hz 与隔离对比
void main() => runApp(const MaterialApp(home: _FrameBudgetPage()));

class _FrameBudgetPage extends StatefulWidget {
  const _FrameBudgetPage();
  @override
  State<_FrameBudgetPage> createState() => _FrameBudgetPageState();
}

class _FrameBudgetPageState extends State<_FrameBudgetPage> {
  // 每帧 = [UI 耗时, Raster 耗时]，ms。真实数据从 Timeline 抄下来
  static const List<List<double>> _plain = <List<double>>[
    <double>[7.2, 9.4], <double>[6.8, 10.1], <double>[9.4, 12.8], <double>[8.1, 8.9],
    <double>[7.6, 10.2], <double>[10.2, 11.5], <double>[6.5, 7.8], <double>[8.9, 12.3],
    <double>[7.1, 9.0], <double>[9.8, 10.9], <double>[6.9, 8.4], <double>[8.4, 11.1],
  ];
  // 同一页面给动画子树加 RepaintBoundary 后：Raster 只剩 3~5ms
  static const List<List<double>> _isolated = <List<double>>[
    <double>[7.0, 3.4], <double>[6.7, 4.1], <double>[9.1, 4.8], <double>[8.0, 3.2],
    <double>[7.4, 4.3], <double>[10.0, 5.1], <double>[6.4, 3.0], <double>[8.8, 4.6],
    <double>[7.0, 3.5], <double>[9.6, 4.9], <double>[6.8, 3.1], <double>[8.3, 4.4],
  ];

  bool _useBoundary = false;
  double _budget = 16.7;

  @override
  Widget build(BuildContext context) {
    final frames = _useBoundary ? _isolated : _plain;
    final over = frames.where((f) => f[0] + f[1] > _budget).length;
    return Scaffold(
      appBar: AppBar(title: const Text('一帧花在哪')),
      body: SingleChildScrollView(
        padding: const EdgeInsets.all(16),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: <Widget>[
            const Text('每根柱子是一帧：蓝色是 UI 线程，橙色是 Raster 线程，'
                '红线是单帧预算。超线的帧就是「卡了一下」。'),
            const SizedBox(height: 12),
            SegmentedButton<double>(
              segments: const <ButtonSegment<double>>[
                ButtonSegment<double>(value: 16.7, label: Text('60Hz 16.7ms')),
                ButtonSegment<double>(value: 8.3, label: Text('120Hz 8.3ms')),
              ],
              selected: <double>{_budget},
              onSelectionChanged: (s) => setState(() => _budget = s.first),
            ),
            SwitchListTile(
              contentPadding: EdgeInsets.zero,
              title: const Text('给动画子树加 RepaintBoundary'),
              subtitle: const Text('静态部分不再每帧重绘，看橙色柱子变矮'),
              value: _useBoundary,
              onChanged: (v) => setState(() => _useBoundary = v),
            ),
            Text('超预算帧：$over / ${frames.length}',
                style: Theme.of(context).textTheme.titleMedium),
            const SizedBox(height: 8),
            // 柱状图：每根柱子 = 一帧，高度按 ms 线性映射
            SizedBox(
              height: 120,
              child: Stack(
                children: <Widget>[
                  Row(
                    crossAxisAlignment: CrossAxisAlignment.end,
                    children: <Widget>[
                      for (final f in frames)
                        Padding(
                          padding: const EdgeInsets.symmetric(horizontal: 2),
                          child: Column(
                            mainAxisAlignment: MainAxisAlignment.end,
                            children: <Widget>[
                              Container(height: f[0] * 4.5, width: 14, color: Colors.blue),
                              Container(height: f[1] * 4.5, width: 14, color: Colors.orange),
                            ],
                          ),
                        ),
                    ],
                  ),
                  Positioned(
                    left: 0,
                    right: 0,
                    bottom: _budget * 4.5,
                    child: Container(height: 1.5, color: Colors.red),
                  ),
                ],
              ),
            ),
            const SizedBox(height: 12),
            Text(_useBoundary
                ? '隔离后 Raster 从 8~12ms 降到 3~5ms，这才是能拿去做决策的数据。'
                : '未隔离时整屏每帧重绘，Raster 长期 8~12ms，高刷设备几乎每帧都掉。'),
          ],
        ),
      ),
    );
  }
}

常见坑 ​

高频踩坑点

  1. 拿 debug 的数据下结论：debug 下 build 慢 3~10 倍是常态，很多「优化」在 profile 里根本不存在。
  2. 把所有卡顿都归因于 shader：只有「首次出现、第二次消失」才像 shader；持续卡顿更可能是过度绘制或布局。
  3. RepaintBoundary 到处包：每层多一个 Layer 和一次纹理合成，包多了 Raster 更慢，还涨内存。
  4. 只看 UI 线程：Raster 是独立线程，Dart 侧压到 3ms，Raster 仍可能 20ms。
  5. 在 120Hz 设备上按 16.7ms 判断：预算只有 8.3ms，60Hz 下「刚好及格」的帧在高刷机上就是掉帧。
  6. 开着 --trace-skia 测帧率：追踪本身拖慢 Raster，它只用来抓证据，不用于评估最终性能。

课后练习 ​

  1. 线程判定：同一页面做两个版本——A 在 build 里做 20 万次浮点累加，B 用 ClipPath 叠 5 层。各跑一次 profile，记录 Frame / Raster 耗时，验证「谁长谁是元凶」。
  2. shader 复现：做一个首次进入使用 ShaderMask + 大圆角阴影的页面，用 --trace-skia 录 Trace 找到首次 Raster 长条；再用 --enable-impeller 跑同一路径，记录首帧耗时差值（验证方法：两次都在真机冷启动、同一页面）。
  3. skp 分析：按上文导出 .skp，在 Skia Debugger 里找到触发编译的 op，用一句话说明是哪种绘制组合导致的。
  4. 隔离验证：给一个每帧重绘的动画页面加 RepaintBoundary，对比加之前/之后的 Raster 耗时与 Layer 数量，写出「是否值得」的结论（验证方法：DevTools 的 Layer 计数 + Timeline 两次数值）。 :::
