包体积优化 ​

学习目标 ​

学完本章，你将能够：

  • 用 flutter build apk/aab/ipa --analyze-size 产出体积分析数据，并在 DevTools 的 App Size 工具里定位「谁占了大头」
  • 读懂 AOT 产物（libapp.so / libflutter.so）与 assets 的体积占比，判断优化的优先级
  • 应用图标 tree shaking、按 ABI 拆分、字体子集化、资源压缩等常规裁剪手段
  • 用 --split-debug-info + --obfuscate 剥离符号，同时保留可还原的崩溃栈
  • 评估 deferred components（Android 动态特性模块）能否把非首屏功能移出主包
  • 在 CI 中建立包体积基线，让下载体积只降不升

包体积为什么值得单独一章

安装包体积直接影响下载转化率和安装成功率：Google 官方数据显示，包体每增加约 6MB，安装转化率平均下降约 1%。此外 Android AAB 的单个模块有 200MB 上限，iOS 蜂窝网络下载也有 200MB 限制。体积优化不是「洁癖」，而是增长指标。

先测量，再优化 ​

体积优化的第一步永远是拿到分项数据，而不是凭感觉删文件。Flutter 内置的体积分析命令：

bash
# Android APK：必须指定单一 ABI，否则多个架构混在一起，数据无法归因
flutter build apk --release --analyze-size --target-platform android-arm64

# Android App Bundle（Google Play 的分发格式）
flutter build appbundle --release --analyze-size --target-platform android-arm64

# iOS（需在 macOS 上执行）
flutter build ipa --release --analyze-size

命令结束时会打印一个 *.size.json 文件路径。启动 DevTools 后切到 App Size 面板，用 Open app size file 选择它：

bash
flutter pub global run devtools

App Size 工具会把体积按「包 / 类 / 文件」层层展开，还支持 Diff 模式对比两次构建。定位大头的顺序建议是：assets → 原生插件 .so → 字体 → libapp.so，因为引擎（libflutter.so）基本不用动。

体积都去哪了 ​

以一个 arm64 release 包约 42MB 的业务 App 为例（数字为示例量级，以你自己的分析结果为准）：

组成典型体积能否优化说明
libflutter.so约 10MB基本不能Flutter 引擎 + Skia/Impeller
libapp.so3-8MB少量Dart AOT 快照，与代码量正相关
assets/视业务能图片、字体、JSON、视频
原生插件 .so每插件 0.1-2MB能地图、音视频、人脸识别等
MaterialIcons 字体全量约 1.6MB能未 tree shake 时才会全量打入
dex / 清单 / 资源索引1-3MB少量Android 打包开销

别用 debug 包看体积

debug 包带 JIT 快照、调试服务和未压缩资源，通常是 release 包的 2-3 倍，没有任何参考价值。所有体积结论必须基于 --release 产物。

五类常规裁剪 ​

1. 图标 tree shaking ​

Flutter 默认在 release 构建时开启 --tree-shake-icons：只把代码里用到的 IconData 打进 MaterialIcons 字体，1.6MB 常能降到几 KB。前提是图标必须是 const：

dart
// ✅ 编译期常量，可被 tree shake
Icon(Icons.home)

// ❌ 图标来自变量 / JSON，分析器无法确定字形，tree shaking 直接失败
Icon(IconData(json['codePoint'] as int, fontFamily: 'MaterialIcons'))

遇到 This application cannot tree shake icons fonts 报错时，正确做法是把动态图标改成 const 白名单映射，而不是简单加 --no-tree-shake-icons 把 1.6MB 全量塞回去。

2. 按 ABI 拆分 ​

通用 APK 会把 arm64-v8a、armeabi-v7a、x86_64 三套原生库全部打进去。按 ABI 拆分后每个包只含一套：

bash
flutter build apk --release --split-per-abi
# 产物：
# app-arm64-v8a-release.apk     现代真机，首选
# app-armeabi-v7a-release.apk   老旧 32 位设备
# app-x86_64-release.apk        模拟器 / x86 设备

经验值：通用包 24MB 时，arm64 单包通常能降到 9-11MB。用 AAB 上架 Google Play 时，Play 会按设备自动下发对应 ABI，无需手动拆包。

3. 字体子集化与资源压缩 ​

中文字体是体积黑洞：Noto Sans SC 全量约 10MB，而 App 实际只用到几百个汉字。用 fonttools 做子集化：

bash
pip install fonttools
pyftsubset NotoSansSC-Regular.ttf \
  --text-file=used_chars.txt \
  --output-file=NotoSansSC-subset.ttf

图片侧的原则：优先矢量（SVG / Icon），位图导出 WebP，按 1x/2x/3x 提供合适尺寸，删除未被引用的资源。assets 里声明了但没人用的文件仍会被打进包，定期用分析工具扫一遍。

4. 原生插件与无用依赖 ​

每引入一个带原生实现的插件，就可能多出三套 .so。优化动作：

  • 删除「引用了但没调用」的插件（flutter pub deps 看依赖树）
  • 只保留目标 ABI：在 android/app/build.gradle 的 defaultConfig 里配置 ndk { abiFilters += listOf("arm64-v8a") }
  • Android 侧开启 minifyEnabled / shrinkResources（详见 03 章发布流程）

5. 去掉无用 locale ​

GlobalMaterialLocalizations 会带上大量语言的本地化数据。只保留真实需要的语言：

dart
MaterialApp(
  supportedLocales: const [Locale('zh'), Locale('en')],
  localizationsDelegates: GlobalMaterialLocalizations.delegates,
)

如果还要进一步压缩，可自行实现只包含所需语言的本地化委托，替换官方全量委托。

符号剥离与混淆 ​

Release 构建默认可读的符号信息会进入 libapp.so。用下面两条参数剥离：

bash
flutter build appbundle --release \
  --obfuscate \
  --split-debug-info=build/symbols
  • --obfuscate：把类名、方法名替换成短标识，增加逆向成本，同时略微缩小 AOT 快照
  • --split-debug-info：把符号表单独输出到 build/symbols/，不随包分发

上线后收到崩溃栈，需要用对应版本的符号还原：

bash
flutter symbolize -i crash.txt -d build/symbols/app.android-arm64.symbols

符号表必须归档

build/symbols/ 丢失后，混淆版本的线上崩溃栈基本无法还原。请把每次发版的符号文件按版本号上传到制品库或对象存储，并与 Release 记录绑定。

deferred components：把非首屏功能移出主包 ​

deferred components 是 Flutter 对 Android 动态特性模块（Dynamic Feature Module）的封装：主包只留首屏代码，视频、编辑器等大功能在需要时再下载。配置示例：

yaml
flutter:
  deferred-components:
    - name: video
      libraries:
        - package:flutter_mastery_lab/video/video_page.dart

代码侧用 deferred import 延迟加载：

dart
import 'video/video_page.dart' deferred as video;

Future<void> openVideo() async {
  await video.loadLibrary();     // 首次会触发模块下载
  // 之后再使用 video.VideoPage()
}

限制很明确：仅 Android + AAB 生效，iOS 不支持；首次加载受网络影响，且有安装体积下限，不适合把核心路径拆出去。

体积门禁：让增长在 CI 里被拦住 ​

体积优化最怕「优化一次，之后慢慢涨回来」。在 CI 里存一份基线并做阈值比较：

bash
#!/usr/bin/env bash
# scripts/size_gate.sh
set -euo pipefail
APK="build/app/outputs/flutter-apk/app-arm64-v8a-release.apk"
CUR=$(wc -c < "$APK")
BASE=$(cat .size-baseline)          # 单位：字节
LIMIT=$((BASE * 105 / 100))         # 允许上浮 5%

echo "基线 ${BASE}B → 当前 ${CUR}B（上限 ${LIMIT}B）"
if [ "$CUR" -gt "$LIMIT" ]; then
  echo "::error::包体积超过基线 5%，请检查新增依赖或资源"
  exit 1
fi

基线在主干合并后手动更新，PR 只做比较。想更精细，可以解析 *.size.json，对 assets、libapp.so、原生库分别设阈值，定位到具体模块。

可运行示例 ​

DartPad 运行环境将在滚动到此处时加载…
查看完整源码
dart
import 'package:flutter/material.dart';

// 包体积优化演示：用开关模拟常见裁剪手段，观察估算体积的变化。
// 数值为示意比例，真实数据以 --analyze-size 报告为准。
void main() => runApp(const MaterialApp(home: _AppSizeDemo()));

class _AppSizeDemo extends StatefulWidget {
  const _AppSizeDemo();

  @override
  State<_AppSizeDemo> createState() => _AppSizeDemoState();
}

class _AppSizeDemoState extends State<_AppSizeDemo> {
  bool _splitAbi = true;
  bool _treeShakeIcons = true;
  bool _subsetFonts = true;

  // 未优化时的构成约 42.6MB
  double get _size {
    var total = 10.0; // libflutter.so（引擎，基本不可裁剪）
    total += 5.0; // libapp.so（AOT 快照）
    total += _splitAbi ? 4.0 : 12.0; // 原生库：单 ABI vs 三 ABI
    total += _treeShakeIcons ? 0.05 : 1.6; // MaterialIcons 字体
    total += _subsetFonts ? 0.8 : 8.0; // 业务字体
    total += 6.0; // assets 图片等
    return total;
  }

  @override
  Widget build(BuildContext context) {
    final scheme = Theme.of(context).colorScheme;
    final size = _size;
    const baseline = 42.6;

    return Scaffold(
      appBar: AppBar(title: const Text('包体积优化')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          Text(
            '当前估算 ${size.toStringAsFixed(1)} MB / 基线 42.6 MB',
            style: Theme.of(context).textTheme.titleMedium,
          ),
          const SizedBox(height: 8),
          ClipRRect(
            borderRadius: BorderRadius.circular(8),
            child: LinearProgressIndicator(
              value: size / baseline,
              minHeight: 18,
              backgroundColor: scheme.surfaceContainerHighest,
            ),
          ),
          const SizedBox(height: 16),
          SwitchListTile(
            value: _splitAbi,
            title: const Text('按 ABI 拆分（--split-per-abi）'),
            subtitle: const Text('原生库从三套变一套'),
            onChanged: (v) => setState(() => _splitAbi = v),
          ),
          SwitchListTile(
            value: _treeShakeIcons,
            title: const Text('图标 tree shaking'),
            subtitle: const Text('只保留用到的 MaterialIcons 字形'),
            onChanged: (v) => setState(() => _treeShakeIcons = v),
          ),
          SwitchListTile(
            value: _subsetFonts,
            title: const Text('字体子集化'),
            subtitle: const Text('中文字体只打包用到的字符'),
            onChanged: (v) => setState(() => _subsetFonts = v),
          ),
          const SizedBox(height: 8),
          Text(
            '提示：逐个关闭开关，体积会回涨，差值就是该手段的收益。',
            style: TextStyle(color: scheme.onSurfaceVariant),
          ),
        ],
      ),
    );
  }
}

常见坑 ​

高频踩坑点

  1. 用通用 APK 做分析：多 ABI 混在一起，libflutter.so 数字翻倍，误判引擎占比。分析必须带 --target-platform。
  2. 拿 debug 包对比体积：debug 带 JIT 与调试服务，体积失真；所有结论只认 release。
  3. tree shaking 报错就关闭：加 --no-tree-shake-icons 会把 1.6MB 字体全量打回包里，正确做法是把动态图标改成 const 映射。
  4. 混淆后符号表丢失：build/symbols/ 没归档，线上崩溃只能看到 <unknown>，等于放弃了可观测性。
  5. 盲目上 deferred components：只支持 Android + AAB，首次打开要联网下载，核心功能拆出去会显著伤害体验。
  6. 只盯 assets：原生插件自带的 .so 往往才是大头，先看分析报告再动手。

课后练习 ​

  1. 体积画像：对配套 App 执行 flutter build apk --release --analyze-size --target-platform android-arm64，用 App Size 工具导出分项，画出占比表；指出前三名分别是什么。
  2. 图片实验：往 assets/ 放一张 5MB 的 PNG 并声明，重新构建看体积变化；再导出为 WebP（质量 80）替换，记录差值。
  3. 图标开关：分别用默认 tree shaking 与 --no-tree-shake-icons 构建，对比 MaterialIcons 字体在分析报告中的体积，验证 const 的作用。
  4. 门禁落地：把上面的 size_gate.sh 接入 CI，人为加入一个 6% 体积的改动，确认流水线变红；恢复后确认变绿。
  5. 进阶：给一个非首屏页面做 deferred components 改造（仅 Android），记录主包体积与首次打开该页面的耗时变化。
