Impeller 渲染引擎与着色器 ​

学习目标 ​

学完本章，你将能够：

  • 说清 Impeller 与 Skia 的架构差异：预编译管线 vs 运行时编译
  • 解释「着色器编译卡顿（shader jank）」的成因，以及 Impeller 为什么能消除它
  • 掌握 --enable-impeller / --no-enable-impeller 以及 Android / iOS 的配置开关
  • 知道 iOS、Android、桌面端的默认状态与 Metal / Vulkan / GLES 后端选择
  • 识别 Impeller 下 CustomPainter、模糊、ImageFilter、PlatformView 的行为差异
  • 用 profile 模式 + DevTools Timeline 做一次可复现的引擎对比
  • 按清单排查迁移时的兼容性问题

本章与第 04 章的分工

第 04 章讲的是「三棵树 → 渲染管线 → Skia/Impeller 概览」，帮你建立整体地图。本章把镜头推近到 引擎内部：一帧如何被录制、上传、光栅化，着色器在什么时刻编译，以及写业务代码时你会遇到哪些具体差异。

从 DisplayList 到光栅化 ​

先统一几个术语：

  • DisplayList：UI 线程把 Canvas 上的绘制调用录制下来的一串指令。
  • Raster（光栅化）：把矢量指令变成屏幕像素的过程，发生在 Raster 线程 / GPU 上。
  • Shader（着色器）：跑在 GPU 上的小程序，负责计算每个像素的颜色。

Skia 与 Impeller 的差别，就发生在「DisplayList 之后」这一段：

阶段SkiaImpeller
指令录制DisplayListDisplayList → 转成内部 Entity
着色器首次遇到新效果时运行时编译引擎构建期一次性编译，产物 .iplr
线程模型Raster 线程，部分场景线程合并固定管线 + 命令缓冲，减少同步点
后端OpenGL ES / Metal / Vulkan（视平台）Metal（iOS/macOS）、Vulkan（Android）、GLES（旧设备兜底）
典型卡顿新效果首帧的 shader 编译，几十毫秒级无编译卡顿，剩余是 CPU/GPU 本身开销

「预编译」不等于「零开销」

Impeller 消除的是运行时编译导致的长帧，不是把绘制变成免费。CustomPainter 里每帧重复上百次 drawCircle、超大面积的模糊、频繁 saveLayer，依然会让 Raster 线程超时。引擎优化和业务侧优化是两件事。

运行时开关与平台默认状态 ​

排查和对比时，命令行开关最方便：

bash
# 强制开启 Impeller
flutter run --enable-impeller --profile

# 临时回退 Skia（用于对比 / 定位兼容性问题）
flutter run --no-enable-impeller --profile

开关只影响本次运行，不能热重载切换，改完必须重启 App。要固化到安装包，用平台配置：

xml
<!-- android/app/src/main/AndroidManifest.xml -->
<application ...>
  <meta-data
      android:name="io.flutter.embedding.android.EnableImpeller"
      android:value="false" />
</application>
xml
<!-- ios/Runner/Info.plist -->
<key>FLTEnableImpeller</key>
<false/>

各平台现状（以你项目锁定的 Flutter 版本 release note 为准）：

平台默认引擎后端说明
iOSImpeller（Flutter 3.10 起默认）Metal新版本已移除 Skia 回退路径，FLTEnableImpeller=false 仅作过渡
AndroidImpeller（Flutter 3.29 起，API 29+）Vulkan，低版本 GLES老设备走 GLES 兜底，功能完整度略低
macOS较新版本已默认 ImpellerMetal旧版本需手动开启，注意插件兼容
Web不适用CanvasKit / skwasm与原生引擎无关

怎么确认当前跑的是哪个引擎

flutter run 启动日志会打印 Impeller 相关信息；DevTools 的 Performance 面板在 Skia 下会出现 Shader compilation 事件，Impeller 下没有。这是最快的判断依据之一。

着色器：从 FragmentProgram 到预编译管线 ​

FragmentProgram 是 Flutter 暴露给业务的片元着色器入口。把 .frag 文件声明到 pubspec.yaml：

yaml
flutter:
  shaders:
    - shaders/ripple.frag

运行时加载并给 uniform 赋值：

dart
// 只加载一次，缓存到 State 里；绝不要每帧 fromAsset
late final FragmentProgram _program;

@override
void initState() {
  super.initState();
  FragmentProgram.fromAsset('shaders/ripple.frag').then((p) => _program = p);
}

void paintShader(Canvas canvas, Size size, double t) {
  final shader = _program.fragmentShader()
    ..setFloat(0, t)
    ..setFloat(1, size.width)
    ..setFloat(2, size.height);
  canvas.drawRect(Offset.zero & size, Paint()..shader = shader);
}

关键差异在于编译时机：

SkiaImpeller
编译时刻第一次真正使用该 shader 时flutter build 阶段由 impellerc 编译
产物运行时生成 GPU 指令并缓存打包进 .iplr，运行时只加载
卡顿表现新效果首帧出现几十毫秒长帧首帧无编译长帧
报错来源SkSL 编译器impellerc（构建期直接失败）

这也是为什么 Impeller 下「首次进入某个花哨页面会卡一下」的问题会大幅减少：编译成本被前移到了构建阶段。

两个常见错误

  1. 在 build() 或 paint() 里 FragmentProgram.fromAsset：异步加载会让首帧拿不到 shader，还会造成重复 IO。放到 initState 并缓存。
  2. 以为写了 .frag 就自动预编译：必须先在 pubspec.yaml 的 shaders: 下声明，否则构建不会处理它。

Impeller 下绘制行为的差异 ​

同样的 Dart 代码，两套引擎的像素结果和耗时可能不同：

场景Skia 表现Impeller 表现 / 注意点
MaskFilter.blur、ImageFilter.blur运行时 SkSL 实现内建模糊通道，通常更稳；边缘处理可能有 1-2 px 差异
高级 BlendMode（如 saturation、hue）RuntimeEffect 模拟部分走 framebuffer fetch，旧 GLES 设备可能降级
BackdropFilter需要离屏图层同样昂贵，且与 ClipRect 搭配要求更严格
CustomPainter 抗锯齿Paint.isAntiAlias 可关闭策略不同，golden 测试像素级差异明显
PlatformView 混合hybrid composition纹理复制与合成开销更高，重叠 / 透明区域更明显

golden 迁移要重新生成基准图并人工 review；PlatformView 场景减少重叠与半透明叠加。

已知限制要分类看

Impeller 的限制通常分三类：后端能力差异（旧 GLES 缺特性）、实现路径差异（模糊 / 混合的边缘像素）、生态兼容（依赖 Skia 私有行为的插件）。遇到问题先归类，再决定改代码、换方案还是等版本。

性能对比：profile + Timeline 实操 ​

只有 profile 模式的帧时间才有参考价值（debug 有断言与 JIT 开销，release 又缺少 Timeline 事件）：

bash
# 同一台真机、同一段动画脚本
flutter run --profile                          # 默认引擎（新版本即 Impeller）
flutter run --profile --no-enable-impeller     # 对照组 Skia

对比步骤：

  1. 固定设备、亮度、动画时长，冷启动后先跑 10 秒预热。
  2. 用 DevTools → Performance 录制同一段操作（例如连续滚动 + 页面切换）。
  3. 看三个指标：UI 线程耗时、Raster 线程耗时、最长帧 / P99 帧。
  4. 在 Skia 的 Timeline 里搜索 Shader compilation，记录它出现在哪些帧；换 Impeller 后应消失。

iOS 模拟器不能代表真机

模拟器的 GPU 路径与真机不同，帧时间经常「看起来很美」。性能结论必须在 iOS / Android 真机上得出，低端 Android 还要单独覆盖 API 28 及以下的 GLES 设备。

迁移排查清单与已知限制 ​

按清单过一遍，能覆盖绝大多数迁移问题：

检查项怎么查处理
渲染相关插件版本flutter pub deps升级到声明支持 Impeller 的版本
模糊 / 滤镜全局搜 ImageFilter、MaskFilter、BackdropFilter真机对比边缘与耗时
高级混合模式搜 BlendMode.旧 GLES 设备实测，必要时改普通混合
自定义 shader搜 FragmentProgram、shaders:保证构建期编译通过
PlatformView搜 AndroidView、UiKitView、PlatformViewLink真机对比滚动、重叠、透明动画
golden 测试跑 flutter test重新录制并逐张确认
低端设备API 28 及以下 Android覆盖 GLES 兜底路径

已知限制（以当前稳定版 release note 为准）：

  • 部分高级 BlendMode 与 ImageFilter 组合在 GLES 兜底设备上会降级，像素结果也可能不同。
  • PlatformView 混合场景的合成开销高于 Skia，复杂页面需实测。
  • 着色器编译报错来自 impellerc，与 SkSL 报错文案不同，迁移时需按新错误逐条修。

不要把回退当长期方案

--no-enable-impeller 和 FLTEnableImpeller=false 是排查与过渡手段。官方会持续收敛 Skia 路径，长期依赖回退会在未来升级时集中爆雷。建议给每个回退配置记录负责人和清理时间。

dart
import 'dart:math' as math;
import 'dart:ui' as ui;

import 'package:flutter/material.dart';

// 同一动画的两种画法：左=每帧重跑全部绘制指令；右=内容只录制成 ui.Picture
// Impeller 预编译着色器消除 shader jank；业务侧减少每帧指令同样重要

void main() => runApp(const MaterialApp(home: _CacheDemo()));

class _CacheDemo extends StatefulWidget {
  const _CacheDemo();
  @override
  State<_CacheDemo> createState() => _CacheDemoState();
}

class _CacheDemoState extends State<_CacheDemo>
    with SingleTickerProviderStateMixin {
  late final AnimationController _ctrl;

  @override
  void initState() {
    super.initState();
    _ctrl = AnimationController(vsync: this, duration: const Duration(seconds: 4))
      ..repeat();
  }

  @override
  void dispose() {
    _ctrl.dispose();
    super.dispose();
  }

  Widget _panel(String title, String sub, bool cache) => Expanded(
        child: Column(
          children: [
            Text(title, style: const TextStyle(fontWeight: FontWeight.bold)),
            Text(sub, style: const TextStyle(fontSize: 11)),
            Expanded(
              child: RepaintBoundary(
                child: CustomPaint(
                    painter: _PatternPainter(_ctrl, cache: cache),
                    size: Size.infinite),
              ),
            ),
          ],
        ),
      );

  @override
  Widget build(BuildContext context) => Scaffold(
        body: Column(
          children: [
            Expanded(
              child: Row(
                children: [
                  _panel('直接绘制', '60 × drawCircle / 帧', false),
                  _panel('缓存 Picture', '1 × drawPicture / 帧', true),
                ],
              ),
            ),
            const Padding(
              padding: EdgeInsets.all(16),
              child: Text(
                '两边图案完全一样，区别只在每帧提交的指令数量。'
                '这里演示业务侧的离屏缓存，和引擎的预编译管线是两回事。',
                style: TextStyle(fontSize: 12),
              ),
            ),
          ],
        ),
      );
}
class _PatternPainter extends CustomPainter {
  _PatternPainter(this.anim, {required this.cache}) : super(repaint: anim) {
    if (cache) {
      final recorder = ui.PictureRecorder();
      _draw(Canvas(recorder), Offset.zero, 0); // 只录制这一次
      _picture = recorder.endRecording();
    }
  }
  final Animation<double> anim;
  final bool cache;
  ui.Picture? _picture;
  void _draw(Canvas canvas, Offset center, double rotation) {
    final paint = Paint()..color = const Color(0xFF2563EB);
    for (var i = 0; i < 60; i++) {
      final angle = rotation + i / 60 * math.pi * 2;
      final radius = 12.0 + (i % 6) * 7;
      final point = center +
          Offset(math.cos(angle) * radius, math.sin(angle) * radius);
      canvas.drawCircle(point, 5, paint); // 每帧真实执行 60 次
    }
  }
  @override
  void paint(Canvas canvas, Size size) {
    final rotation = anim.value * math.pi * 2;
    if (cache) {
      canvas.save();
      canvas.translate(size.width / 2, size.height / 2);
      canvas.rotate(rotation);
      canvas.drawPicture(_picture!); // 每帧只有 1 次绘制调用
      canvas.restore();
    } else {
      _draw(canvas, size.center(Offset.zero), rotation);
    }
  }
  @override
  bool shouldRepaint(covariant _PatternPainter oldDelegate) => false;
}

常见坑 ​

高频踩坑点

  1. 在 paint 里做异步加载：FragmentProgram.fromAsset、图片解码都应该在 initState / 首帧前完成，并缓存结果。
  2. 把「预编译」当成万能药：Impeller 只消除 shader 编译卡顿；超大模糊、频繁 saveLayer、每帧数百次绘制调用依旧会让 Raster 线程超时。
  3. 用 debug 模式做引擎对比：debug 的 JIT 与断言会污染数据，必须在 profile + 真机上测。
  4. 切换开关后没重启：--enable-impeller 不会热重载生效，切完必须冷启动。
  5. 忽略旧 GLES 设备：高端机表现一致，不代表 API 28 及以下设备也一致，混合模式与滤镜尤其容易出差异。

课后练习 ​

  1. 开关对比：用同一个动画页面，分别以 --enable-impeller 和 --no-enable-impeller 跑 profile，在 Timeline 里记录最长帧与 Raster 耗时。
  2. 复现 shader jank：写一个首次进入才触发的复杂 ImageFilter.blur 页面，在 Skia 下观察首帧长帧，换 Impeller 后再看一次。
  3. FragmentProgram 实战：写一个 .frag 波纹 shader，声明到 pubspec.yaml，在 initState 预加载并缓存，验证构建期编译失败时的报错来源。
  4. PlatformView 体检：找一个含 AndroidView / UiKitView 的页面，分别在两套引擎下滚动，记录 Raster 耗时与重叠 / 撕裂问题。
