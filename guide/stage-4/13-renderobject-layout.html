RenderObject 与自定义布局 ​

学习目标 ​

学完本章，你将能够：

  • 说清 RenderObject 的生命周期：创建 / attach / markNeedsLayout / layout / paint / detach
  • 掌握 BoxConstraints 的传递规则，以及 parentUsesSize 为什么不能省
  • 独立写出一个基于 RenderBox 的自定义布局（例如瀑布流）
  • 理解 MultiChildRenderObjectWidget、ParentData 与 ParentDataWidget 的协作
  • 用 CustomMultiChildLayout / Flow 实现「先测量再摆放」的布局

本章与阶段三的区别

阶段三讲了「怎么把 RenderBox 跑起来」；本章讲协议细节与选型：布局何时失效、尺寸何时可信、多子节点怎么组织、sliver 为什么不能当普通 Box 用。读完你应该能判断「这个需求到底要不要写 RenderObject」。

RenderObject 的生命周期 ​

一个 RenderObject 从创建到销毁，会经历下面的阶段：

text
createRenderObject（Element 挂载）
  → attach(PipelineOwner)     获得调度入口，可以参与布局 / 绘制
  → markNeedsLayout()         标脏，向上找到最近的 relayout boundary
  → layout(constraints)       由父级调用，决定 size 并布局子节点
  → paint(context, offset)    由父级调用，把内容录进 PictureLayer
  → detach()                  从树上摘除，不再参与调度

要点：

  • attach / detach：与 PipelineOwner 建立 / 解除关联。detach 后不能再访问 owner，也不该再标脏。
  • markNeedsLayout：会向上传播到最近的 relayout boundary，边界之上不受影响。

RenderObject 不要持有 BuildContext

RenderObject 的生命周期可能跨越多次 Widget 重建，而 BuildContext 属于 Element，随时可能失效。配置通过字段传入，并在 updateRenderObject 里更新。

布局协议：constraints、layout 与 parentUsesSize ​

Flutter 的布局是单趟自顶向下的：父级把 BoxConstraints 传给子级，子级在约束范围内决定尺寸，父级再根据结果摆放。

dart
const BoxConstraints(minWidth: 100, maxWidth: 300); // 宽 100~300，高不限
BoxConstraints.tightFor(width: 200, height: 80);    // 宽高锁死
constraints.loosen();                               // 去掉最小值，保留最大值
constraints.constrain(const Size(200, 200));        // 把尺寸夹到合法范围

核心 API：

方法职责关键约束
performLayout()决定 size、布局子节点、写 parentData.offsetsize 必须满足 constraints
computeDryLayout(constraints)纯函数式算出尺寸，不改状态供 intrinsics / dry layout 使用
paint(context, offset)绘制自身与子节点用 context.paintChild，不直接调 child.paint
hitTest(result, position)命中测试通常转发给 hitTestSelf / hitTestChildren

最关键的一条规则：读了子节点的 size，就必须传 parentUsesSize: true。

dart
child.layout(BoxConstraints.tightFor(width: 120),
    parentUsesSize: true); // 父级会读取 child.size
final childHeight = child.size.height; // 否则 debug 下会断言失败

传 false（默认）时，框架可以把子节点当作独立的 relayout boundary：子节点重排不会连累父级。反过来，读了尺寸却没声明依赖，父级就不会在子节点变化时重新布局，表现为「数据更新了但布局没动」。

三个布局断言

  1. size 超出 constraints：debug 下 debugAssertDoesMeetConstraints 会报错。
  2. 读了 child.size 却没传 parentUsesSize: true：断言失败或拿到过期尺寸。
  3. 在 performLayout 里访问未布局的子节点：child.size 是上一帧的旧值。

手写一个 RenderBox ​

以瀑布流为例：子节点按顺序放进「当前最矮的一列」。完整可运行版见本章示例，下面是核心 RenderObject：

dart
class WaterfallParentData extends ContainerBoxParentData<RenderBox> {}
class RenderWaterfall extends RenderBox
    with ContainerRenderObjectMixin<RenderBox, WaterfallParentData>,
        RenderBoxContainerDefaultsMixin<RenderBox, WaterfallParentData> {
  RenderWaterfall(this._columns);
  int _columns;

  set columns(int value) {
    if (value == _columns) return;
    _columns = value;
    markNeedsLayout(); // 布局参数变了，必须重新布局
  }
  @override
  void performLayout() {
    final columnWidth = constraints.maxWidth / _columns;
    final heights = List<double>.filled(_columns, 0);
    RenderBox? child = firstChild;
    while (child != null) {
      child.layout(BoxConstraints.tightFor(width: columnWidth),
          parentUsesSize: true);
      final column = heights.indexOf(heights.reduce(math.min));
      (child.parentData! as WaterfallParentData).offset =
          Offset(column * columnWidth, heights[column]);
      heights[column] += child.size.height;
      child = childAfter(child);
    }
    size = constraints.constrain(
        Size(constraints.maxWidth, heights.reduce(math.max)));
  }
}

外层还需要一个 MultiChildRenderObjectWidget 负责 createRenderObject 与 updateRenderObject；后者把新列数写回 RenderObject，从而触发 markNeedsLayout。子节点的 ParentData 要在 setupParentData 里初始化（示例源码中有完整写法）。

  • ContainerRenderObjectMixin：维护子节点双向链表，提供 firstChild / childAfter / adoptChild / dropChild。
  • RenderBoxContainerDefaultsMixin：提供 defaultPaint（按顺序画子节点）与 defaultHitTestChildren，多数布局可直接复用。

多子布局与 ParentDataWidget ​

ParentData 是挂在子节点身上、由父级写入的数据，例如 offset、flex、fit。它不参与 Widget 树，只在布局阶段使用：ContainerBoxParentData<RenderBox> 的子类记录 offset，FlexParentData 记录 flex / FlexFit，StackParentData 记录 Positioned 的四边偏移。

ParentDataWidget 是把配置写到对应子 RenderObject 上的 Widget，例如 Positioned、Expanded、Flexible。两条硬规则：

  1. 必须是目标 RenderObjectWidget 的直接子级（Positioned 只能放在 Stack 下）。
  2. 通过 applyParentData 写数据并调用 markNeedsLayout；构造时用 debugTypicalAncestorWidgetClass 声明期望祖先，放错位置会在 debug 下报错。
dart
// 结构：Stack（RenderObjectWidget）→ Positioned（ParentDataWidget）→ 内容
Stack(children: [Positioned(left: 12, top: 12, child: Text('角标'))])

改 ParentData 的时机

父级参数变化（如列数、间距）要在 updateRenderObject 里 markNeedsLayout；子节点自身的 ParentData 变化由 ParentDataWidget.applyParentData 标脏。两条路径都不要漏。

CustomMultiChildLayout 与 Flow ​

「需要先测量子节点，再按自定义规则摆放」不一定要手写 RenderBox，CustomMultiChildLayout 用委托就能完成：

dart
class _ListDelegate extends MultiChildLayoutDelegate {
  @override
  void performLayout(Size size) {
    var y = 0.0;
    for (final id in _ids) {
      final child = layoutChild(id, BoxConstraints.loose(size));
      positionChild(id, Offset(0, y));
      y += child.height;
    }
  }
  @override
  bool shouldRelayout(covariant _ListDelegate old) => false;
}

使用规则：

  • 每个子节点必须用 LayoutId(id: ...) 包裹，委托里通过同一个 id 访问。
  • layoutChild 对每个子节点只能调用一次，它返回布局后的 Size。
  • positionChild 只写偏移，不触发布局；shouldRelayout 返回 false 时约束不变就不重复布局。

Flow 则把「布局」和「绘制时的变换」拆开：FlowDelegate 通过 FlowPaintingContext 在绘制阶段给每个子节点设置矩阵。好处是动画期间只 repaint、不 relayout；代价是每帧重画所有子节点，适合子节点少的场景（弧形菜单、旋转卡片），不适合长列表。

Sliver 与 LayoutBuilder：选型速查 ​

Sliver 是「可滚动区域里的一段」，不使用 BoxConstraints，而是接收 SliverConstraints、返回 SliverGeometry：

对象关键字段你要回答的问题
SliverConstraintsscrollOffset、remainingPaintExtent、remainingCacheExtent、crossAxisExtent、axisDirection我在视口里还剩多少空间？
SliverGeometryscrollExtent、paintExtent、layoutExtent、maxPaintExtent、visible我占多长、画多长、还需要多少？

常见做法：单个 Box 子节点用 SliverToBoxAdapter / RenderSliverSingleBoxAdapter；列表用 SliverList，网格用 SliverGrid；吸顶头写 SliverPersistentHeaderDelegate。只有自定义滚动效果（视差、折叠、特殊回收）才值得继承 RenderSliver。

不要把 sliver 当普通 Box 布局

Sliver 的 constraints 里没有 min/max 高度，只有「已滚出多少、还剩多少」。习惯用 constraints.maxHeight 的代码直接搬到 RenderSliver 会得到无意义的结果。

LayoutBuilder 就够了的情况 ​

LayoutBuilder 在 build 阶段拿到父级约束，可以据此切换布局，完全不需要写 RenderObject：

dart
LayoutBuilder(builder: (context, constraints) {
  final columns = constraints.maxWidth > 720 ? 4 : 2;
  return GridView.count(crossAxisCount: columns, children: const [/* 卡片 */]);
})

适用：响应式断点、根据宽度决定列数 / 横竖排、容器尺寸变化时切换样式。不适用：需要「先测量子节点再决定怎么摆」；需要写 ParentData、自定义命中测试或绘制阶段变换；每帧高频变化且不想触发 Widget 重建。

需求首选方案
仅按约束切换布局LayoutBuilder
多子节点需要测量后摆放CustomMultiChildLayout
动画中变换子节点但不重排Flow
参与滚动协议 / 自定义回收RenderSliver

dart
import 'dart:math' as math;
import 'package:flutter/material.dart';
import 'package:flutter/rendering.dart';

// 自定义 RenderBox：重写 performLayout，把子节点按「最矮列」贪心摆放
void main() => runApp(const MaterialApp(home: _WaterfallDemo()));

class _WaterfallDemo extends StatefulWidget {
  const _WaterfallDemo();
  @override
  State<_WaterfallDemo> createState() => _WaterfallDemoState();
}

class _WaterfallDemoState extends State<_WaterfallDemo> {
  int _columns = 3;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Column(
        children: [
          Slider(
            value: _columns.toDouble(), min: 2, max: 4, divisions: 2,
            label: '列数 $_columns',
            onChanged: (v) => setState(() => _columns = v.round()),
          ),
          Expanded(
            child: _Waterfall(
              columns: _columns,
              children: [
                for (var i = 0; i < 12; i++)
                  Container(
                    height: 40 + (i % 4) * 24,
                    margin: const EdgeInsets.all(4),
                    color: Colors.primaries[i % Colors.primaries.length].shade200,
                  ),
              ],
            ),
          ),
        ],
      ),
    );
  }
}

class _Waterfall extends MultiChildRenderObjectWidget {
  _Waterfall({required this.columns, required super.children});
  final int columns;

  @override
  RenderObject createRenderObject(BuildContext context) =>
      _RenderWaterfall(columns);

  @override
  void updateRenderObject(BuildContext context, _RenderWaterfall renderObject) {
    renderObject.columns = columns;
  }
}

class _TileParentData extends ContainerBoxParentData<RenderBox> {}

class _RenderWaterfall extends RenderBox
    with
        ContainerRenderObjectMixin<RenderBox, _TileParentData>,
        RenderBoxContainerDefaultsMixin<RenderBox, _TileParentData> {
  _RenderWaterfall(this._columns);
  int _columns;
  set columns(int value) {
    if (value == _columns) return;
    _columns = value;
    markNeedsLayout(); // 布局参数变了，必须重新布局
  }

  @override
  void setupParentData(RenderObject child) {
    if (child.parentData is! _TileParentData) {
      child.parentData = _TileParentData();
    }
  }

  @override
  void performLayout() {
    final columnWidth = constraints.maxWidth / _columns;
    final heights = List<double>.filled(_columns, 0);
    RenderBox? child = firstChild;
    while (child != null) {
      // parentUsesSize: true 表示父级会读取 child.size
      child.layout(
        BoxConstraints.tightFor(width: columnWidth),
        parentUsesSize: true,
      );
      final column = heights.indexOf(heights.reduce(math.min));
      (child.parentData! as _TileParentData).offset =
          Offset(column * columnWidth, heights[column]);
      heights[column] += child.size.height;
      child = childAfter(child);
    }
    size = constraints.constrain(
      Size(constraints.maxWidth, heights.reduce(math.max)),
    );
  }

  @override
  void paint(PaintingContext context, Offset offset) =>
      defaultPaint(context, offset);

  @override
  bool hitTestChildren(BoxHitTestResult result, {required Offset position}) =>
      defaultHitTestChildren(result, position: position);
}

常见坑 ​

高频踩坑点

  1. 读了 child.size 却没传 parentUsesSize: true：debug 断言失败；release 下父级不会随子节点变化重新布局，布局卡在旧值。
  2. performLayout 里忘记给子节点布局：子节点尺寸是旧值或 0，defaultPaint 画出来位置全错。
  3. size 没受 constraints 约束：在 ListView 等无界约束下直接写死尺寸会崩，必须 constraints.constrain(...)。
  4. 在 RenderObject 里持有 BuildContext：Element 重建后 context 失效，容易触发「deactivated widget's ancestor」错误。

课后练习 ​

  1. 最小 RenderBox：写一个固定把子节点放在右下角的 RenderBox，验证 performLayout、paint、hitTest 都被调用。
  2. 瀑布流升级：给本章的瀑布流加上「列间距 / 行间距」参数，并在 updateRenderObject 里正确触发 markNeedsLayout。
  3. CustomMultiChildLayout 实战：用委托实现环形菜单，子节点沿圆周均匀分布，窗口尺寸变化时自动重排。
