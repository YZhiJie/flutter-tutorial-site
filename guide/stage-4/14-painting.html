绘制管线与 CustomPainter 进阶 ​

学习目标 ​

学完本章，你将能够：

  • 说清 paint → layer → raster 三个阶段各自发生了什么、在哪个线程
  • 熟练使用 Canvas 的 save / restore / 裁剪 / 变换，避免状态栈失衡
  • 用 Path.combine 做并集、交集、差集、异或，构造复杂图形
  • 配置 Paint 的混合模式、着色器、遮罩，并知道混合模式的隔离规则
  • 估算 saveLayer / BackdropFilter 的离屏成本，避免每帧分配大纹理
  • 用 drawAtlas 批量绘制，用 shouldRepaint / repaint / RepaintBoundary 控制重绘

本章与阶段三的区别

阶段三的 CustomPainter 示例只画了一颗心；本章讲绘制管线的成本模型：一条绘制指令如何变成 Layer、什么时候会多分配一张离屏纹理、哪些写法会让 Raster 线程超时。

绘制管线：paint → layer → raster ​

一帧的绘制可以拆成三个阶段：

阶段线程产物你要关心的事
paintUI 线程Picture（录制好的绘制指令）CustomPainter 里的每条指令都在这里执行
compositingUI 线程Layer 树RepaintBoundary 会把子树提成独立 Layer
rasterRaster 线程 / GPU屏幕像素模糊、混合、离屏纹理主要在这里花时间

RenderObject.paint 拿到的是 PaintingContext，它负责把绘制指令录进 PictureLayer。给子节点绘制时要走 context.paintChild(child, offset)，而不是直接调 child.paint，否则子节点的 Layer 语义会丢。

60fps 的预算是 16.6ms/帧，UI 与 Raster 两条线各自都要控制在预算内。绘制阶段写得再快，如果 Raster 阶段在处理大面积模糊，一样会掉帧。

paint 快不等于帧快

paint 阶段只是「录制指令」，真正昂贵的是 Raster 阶段的纹理分配、模糊采样与混合。优化时先看 Timeline 是 UI 线超时还是 Raster 线超时，再决定改代码还是改视觉方案。

Canvas 状态栈与 Path 布尔运算 ​

Canvas 维护一个状态栈：变换矩阵、裁剪区域、图层。save() 入栈、restore() 出栈，必须成对出现：

dart
canvas.save();
canvas.translate(100, 80);
canvas.rotate(math.pi / 6);
canvas.drawRect(const Rect.fromLTWH(0, 0, 120, 40), paint);
canvas.restore(); // 回到 save 时的状态

常用能力：变换（translate / rotate / scale / skew）、裁剪（clipRect / clipRRect / clipPath，一直生效到 restore）、路径（Path 支持 moveTo / lineTo / cubicTo / arcTo / addRRect）。

Path.combine 把两个路径做布尔运算，是构造复杂图形最省事的办法：

运算结果
PathOperation.union两个形状合并
PathOperation.intersect只保留重叠部分
PathOperation.difference第一个减去第二个（做镂空）
PathOperation.reverseDifference第二个减去第一个
PathOperation.xor只保留不重叠的部分
dart
final card = Path()
  ..addRRect(RRect.fromRectAndRadius(
      const Rect.fromLTWH(20, 20, 240, 120), const Radius.circular(16)));
final hole = Path()..addOval(const Rect.fromLTWH(180, 50, 60, 60));
final withHole = Path.combine(PathOperation.difference, card, hole);
canvas.drawPath(withHole, Paint()..color = Colors.indigo);

save / restore 要配对

忘记 restore 会让后续所有绘制都带着这次变换和裁剪，表现为「整页内容突然偏移或被裁掉」。调试时可打印 canvas.getSaveCount()，正常情况下每次绘制结束都应回到基线。

Paint：混合模式、着色器与遮罩 ​

Paint 是绘制样式对象，常用字段如下：

字段作用备注
color / style颜色、填充或描边PaintingStyle.stroke 需配 strokeWidth
strokeCap / strokeJoin线端、拐角形状画图表折线时很常用
shader渐变 / 图片着色器坐标基于 Canvas 空间，不是形状局部坐标
blendMode与已有像素的混合方式高级模式在 Impeller 下可能走特殊路径
maskFilter模糊遮罩BlurMaskFilter 只影响该次绘制
colorFilter颜色矩阵 / 模式可做置灰、去色、反色
isAntiAlias是否抗锯齿像素级 golden 会受它影响

混合模式描述的是 src（新绘制内容）与 dst（已有内容）的关系。常用的几个：

  • srcOver：默认，源盖在目标上。
  • multiply / screen / difference：照片风格的混合。
  • srcIn / dstIn / xor：Porter-Duff 裁剪类混合，常配合 saveLayer 做遮罩。
dart
final paint = Paint()
  ..shader = const LinearGradient(
    colors: [Color(0xFF6366F1), Color(0xFF22D3EE)],
  ).createShader(rect)
  ..blendMode = BlendMode.multiply
  ..maskFilter = const MaskFilter.blur(BlurStyle.normal, 6);
canvas.drawCircle(center, 80, paint);

着色器与遮罩都是「每个像素都要算一遍」的东西，面积越大越贵。MaskFilter.blur 适合小面积柔边；大面积模糊优先用 ImageFilter 或预渲染图片。

混合模式默认作用于整张画布

不带 saveLayer 时，blendMode 会与整个已绘制内容混合，包括背景。想要「只在几个形状之间混合」，必须先把这些形状放进一个离屏图层，见下一节。

saveLayer、ImageFilter 与离屏成本 ​

canvas.saveLayer(bounds, paint) 会把之后的绘制重定向到一张离屏纹理，restore 时再合成回主画布。它解决三类问题：组透明度、混合隔离、整体滤镜。

代价也很直接：一张 1080×2400 的 RGBA 离屏纹理约 10.4 MB，每帧新建 + 合成会带来分配与显存带宽开销。多层嵌套 saveLayer 是移动端掉帧的经典原因。

能力写法适用
组透明度 / 混合隔离canvas.saveLayer(rect, Paint())一组形状统一透明度或统一混合
模糊一张已有内容ImageFilter.blur(sigmaX:, sigmaY:)卡片阴影、磨砂玻璃
模糊背后内容BackdropFilter + ClipRect弹层、导航栏毛玻璃
给子树加滤镜ImageFiltered(imageFilter:, child:)图片 / 组件的整体调色

BackdropFilter 必须放在有裁剪的容器里（通常 ClipRect / ClipRRect），否则模糊区域会按整块屏幕计算：

dart
ClipRRect(
  borderRadius: BorderRadius.circular(16),
  child: BackdropFilter(
    filter: ImageFilter.blur(sigmaX: 12, sigmaY: 12),
    child: Container(color: Colors.white.withValues(alpha: 0.2)),
  ),
)

不要在动画里每帧 saveLayer

全屏 saveLayer + 大 sigma 模糊，单帧就可能吃掉十几毫秒 Raster 时间。能缓存成图片就缓存，能用 ImageFiltered 静态效果就别放进动画链路；确需动态模糊时降低分辨率和 sigma。

drawAtlas 与批量绘制 ​

drawAtlas 用一张图集（atlas）一次性画很多个精灵：每个精灵只需要一个源矩形和一个变换，GPU 只提交一次绘制调用。

dart
final transforms = <RSTransform>[
  RSTransform.fromComponents(
      rotation: 0.4, scale: 1, anchorX: 16, anchorY: 16,
      translateX: 120, translateY: 160),
];
final rects = <Rect>[Rect.fromLTWH(0, 0, 32, 32)];
canvas.drawAtlas(image, transforms, rects, null, BlendMode.srcOver, null, paint);

适用场景：粒子系统、地图标记、纸屑 / 雪花动画、图表里重复的小图标。对比「循环 200 次 drawImage」，drawAtlas 只有 1 次绘制调用，CPU 与驱动开销都更低。

热路径还可以用 drawRawAtlas + Float32List，省掉 RSTransform 与 Rect 对象的分配：

  • 每个精灵 4 个 float 描述 RSTransform，4 个 float 描述源矩形。
  • 颜色可选，传 null 表示不逐精灵着色。
  • 图集尺寸建议控制在 2048×2048 以内，避免超出老设备的纹理上限。

图集不是万能药

精灵数量少（十几个）时，drawAtlas 的收益有限；图集还会增加内存与打包复杂度。先确认绘制调用是瓶颈（Timeline 里绘制项多、Raster 时间长），再考虑图集化。

shouldRepaint、repaint 与 RepaintBoundary ​

CustomPainter 每次 build 都会创建新实例，框架用 shouldRepaint(oldDelegate) 判断要不要重绘：

dart
class WavePainter extends CustomPainter {
  WavePainter(this.anim) : super(repaint: anim); // 由动画直接驱动重绘
  final Animation<double> anim;

  @override
  bool shouldRepaint(covariant WavePainter oldDelegate) => false; // 数据没变
}

三种控制重绘的手段：

手段作用成本 / 注意
shouldRepaint新 painter 与旧 painter 数据是否不同只在提供新实例时调用
repaint: Listenable动画 tick 直接触发重绘，不重建 Widget最省，优先用于动画
RepaintBoundary把子树提成独立 Layer，隔离重绘多一层合成与显存，别滥用

CustomPaint 还有两个光栅缓存提示：isComplex: true 表示绘制复杂、值得缓存，willChange: true 表示内容会变、不要缓存。它们只是提示，不是强制。调试可开 debugRepaintRainbowEnabled = true，重绘区域会被涂上彩色，很容易看出 Boundary 有没有放对位置。

RepaintBoundary 放多了更慢

每个 Boundary 都是一层 Layer，会带来额外的合成与内存。只有「频繁重绘且与周围互不影响」的子树才值得包，例如旋转的加载图标、实时波形、打字光标。

dart
import 'dart:math' as math;

import 'package:flutter/material.dart';

// Path.combine 把两个路径做布尔运算：并 / 交 / 差 / 异或。
// 小圆绕中心旋转，四种运算的结果完全不同。

void main() => runApp(const MaterialApp(home: _PathOpsDemo()));

class _PathOpsDemo extends StatefulWidget {
  const _PathOpsDemo();
  @override
  State<_PathOpsDemo> createState() => _PathOpsDemoState();
}

class _PathOpsDemoState extends State<_PathOpsDemo>
    with SingleTickerProviderStateMixin {
  late final AnimationController _ctrl;

  @override
  void initState() {
    super.initState();
    _ctrl = AnimationController(
      vsync: this,
      duration: const Duration(seconds: 6),
    )..repeat();
  }

  @override
  void dispose() {
    _ctrl.dispose();
    super.dispose();
  }

  Widget _cell(String label, PathOperation op) {
    return Column(
      children: [
        Text(label, style: const TextStyle(fontWeight: FontWeight.bold)),
        Expanded(
          child: ClipRect(
            child: CustomPaint(
              painter: _CombinePainter(op, _ctrl),
              size: Size.infinite,
            ),
          ),
        ),
      ],
    );
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Path 布尔运算')),
      body: GridView.count(
        crossAxisCount: 2,
        padding: const EdgeInsets.all(8),
        children: [
          _cell('并集 union', PathOperation.union),
          _cell('交集 intersect', PathOperation.intersect),
          _cell('差集 difference', PathOperation.difference),
          _cell('异或 xor', PathOperation.xor),
        ],
      ),
    );
  }
}

class _CombinePainter extends CustomPainter {
  _CombinePainter(this.op, this.anim) : super(repaint: anim);
  final PathOperation op;
  final Animation<double> anim;

  @override
  void paint(Canvas canvas, Size size) {
    canvas.clipRect(Offset.zero & size); // 防止画到相邻格子
    final center = size.center(Offset.zero);
    final base = Path()
      ..addRRect(RRect.fromRectAndRadius(
        Rect.fromCenter(
          center: center,
          width: size.width * .7,
          height: size.height * .7,
        ),
        const Radius.circular(20),
      ));
    final angle = anim.value * math.pi * 2;
    final circleCenter = center +
        Offset(math.cos(angle) * size.width * .18,
            math.sin(angle) * size.height * .18);
    final circle = Path()
      ..addOval(Rect.fromCircle(
        center: circleCenter,
        radius: size.shortestSide * .22,
      ));
    final result = Path.combine(op, base, circle);
    canvas.drawPath(result, Paint()..color = const Color(0xFF4F46E5));
  }

  @override
  bool shouldRepaint(covariant _CombinePainter oldDelegate) =>
      oldDelegate.op != op;
}

常见坑 ​

高频踩坑点

  1. save / restore 不配对：少 restore 会污染后续绘制；多 restore 会抛断言。嵌套时用「进入前 save、离开前 restore」的结构化写法。
  2. shouldRepaint 恒返回 true：每帧都重绘，动画一多就掉帧；恒返回 false 又会导致数据变化不更新。按字段比较，或用 repaint。
  3. 在 paint 里 new 大对象 / 解码图片：Paint、Path 可以复用；图片、Paragraph 必须提前构建并缓存。
  4. 用 saveLayer 做普通裁剪：clipRect / clipPath 足够时不要开离屏层，后者成本高一个数量级。
  5. BackdropFilter 没有裁剪：模糊区域会覆盖整块可用空间，既慢又可能出现黑边。

课后练习 ​

  1. 布尔运算图形：用 Path.combine 画一个齿轮（多个旋转矩形并集）和一个镂空卡片（差集），并加上旋转动画。
  2. 混合模式实验：同一组圆形分别用 srcOver、multiply、srcIn 绘制，再对比「直接画」与「saveLayer 隔离后画」的差异。
  3. 离屏成本测量：写一个全屏 saveLayer + 模糊的页面，在 DevTools 里对比开关前后的 Raster 耗时。
  4. 图集批绘：用一张 4×4 的小图集，分别用 200 次 drawImage 和 1 次 drawAtlas 绘制，观察 Timeline 的绘制调用数量。
