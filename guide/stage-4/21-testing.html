测试金字塔：单测 / Widget / Golden / 集成 ​

学习目标 ​

学完本章，你将能够：

  • 用「单元 70% / Widget 20% / 集成 10%」的成本模型规划测试投入
  • 用 flutter test --coverage 产出 lcov 报告并设置覆盖率门禁
  • 写出稳定的 Widget 测试：pumpWidget、pumpAndSettle、find.byKey
  • 用 Golden 测试守住像素级 UI 回归，并处理字体与平台差异
  • 用 integration_test / flutter drive（以及 Patrol）覆盖真实设备链路
  • 识别「只写集成测试」等测试金字塔反模式

测试的价值不在数量，而在反馈速度

单测毫秒级、Widget 测试百毫秒级、集成测试分钟级。越靠下层越多，越靠上层越少，才能在十分钟内拿到可信反馈。

分层与成本：70 / 20 / 10 ​

层级占比单条耗时稳定性主要发现
单元测试~70%1-20ms高业务规则、边界、异常分支
Widget 测试~20%50-500ms中渲染、交互、状态联动
Golden 测试少量100-800ms中低像素级视觉回归
集成测试~10%10s-2min低真机链路、插件、权限

成本曲线是指数级的：一个集成测试跑 1 分钟，一百个就是两小时。把「满 200 减 30」这类规则放进集成测试，等于用卡车送快递。

反模式：倒金字塔

团队只写集成测试（「反正能点通」），结果 CI 跑 40 分钟、失败原因永远是「第 37 步超时」，没人愿意修。正确顺序是：先补纯逻辑单测，再补关键路径 Widget 测试，最后只留 5-10 条冒烟级集成测试。

单元测试：flutter test 与覆盖率 ​

dart
// test/price_calculator_test.dart
import 'package:flutter_test/flutter_test.dart';
import 'package:shop/price_calculator.dart';

void main() {
  group('PriceCalculator', () {
    test('未满 200 不减', () {
      expect(const PriceCalculator().total([10000, 5000]), 15000);
    });

    test('满 200 减 30', () {
      expect(const PriceCalculator().total([15000, 6000]), 18000);
    });

    test('VIP 再打 9 折', () {
      expect(const PriceCalculator(vip: true).total([15000, 6000]), 16200);
    });

    test('空购物车为 0', () {
      expect(const PriceCalculator().total([]), 0);
    });
  });
}
bash
flutter test                          # 跑全部
flutter test test/price_calculator_test.dart
flutter test --coverage               # 产出 coverage/lcov.info
flutter test --name "VIP"             # 只跑名字匹配的用例

Mock 方案取舍：

方案优点代价适用
mocktail无需代码生成、空安全友好手写 stub 略多大多数项目首选
mockito生态老、功能全需要 build_runner已有生成管线

优先「手写 Fake」而不是 Mock

Repository 接口只有一个方法时，写一个 class FakeRepo implements Repo 比引入 Mock 框架更直观。Fake 验证行为，Mock 验证调用；断言「总价算对了」比断言「第 2 次调用参数是 15000」更有价值。

测试夹具（fixture）是一组固定输入与期望值：抽成常量或 buildXxx() 工厂函数，保证用例不共享可变状态。

Widget 测试：pumpWidget / pumpAndSettle / Finder ​

dart
testWidgets('点击 +1 后计数变为 1', (tester) async {
  await tester.pumpWidget(const MaterialApp(home: CounterPage()));

  expect(find.text('计数: 0'), findsOneWidget);
  await tester.tap(find.byKey(const Key('increment')));
  await tester.pump(); // 处理一帧，setState 生效

  expect(find.text('计数: 1'), findsOneWidget);
  expect(find.byType(SnackBar), findsNothing);
});
  • pump()：推进一帧，适合同步 setState。
  • pumpAndSettle()：反复 pump 直到没有待处理帧；遇到无限动画（loading spinner）会超时。
  • 查找优先级：find.byKey > find.byType > find.text。文案会改，Key 不会。
  • 交互要 await tester.tap(...)，断言前记得 await tester.pump()。

pumpAndSettle 的经典超时

页面上有 CircularProgressIndicator 或循环动画时，pumpAndSettle 永远等不到「静止」，测试 10 秒后抛 pumpAndSettle timed out。改用 await tester.pump(const Duration(seconds: 1)) 精确推进，或把动画从测试路径里拿掉。

Golden 测试：像素级回归 ​

dart
testWidgets('价格卡片外观稳定', (tester) async {
  await tester.pumpWidget(
    const MaterialApp(home: Scaffold(body: PriceCard(total: 18000))),
  );
  await expectLater(
    find.byType(PriceCard),
    matchesGoldenFile('goldens/price_card.png'),
  );
});
bash
flutter test --update-goldens                     # 有意的 UI 变更后更新基准图
flutter test test/golden/                         # 只跑 golden 目录
flutter test --tags=golden                        # 配合 @Tags(['golden'])

Golden 的本质是「截图对比」，因此对环境极其敏感：

变量影响对策
字体本机字体 vs CI 字体不同 → 全红测试里加载固定字体（loadAppFonts）
平台macOS / Windows / Linux 渲染不同只在 Linux CI 生成与校验
引擎版本Flutter 升级可能改变排版基准图与 SDK 版本一起锁
设备像素比1x / 2x 截图尺寸不同固定 tester.view.devicePixelRatio = 1.0

Golden 适合「少而精」

不要给每个页面都加 golden。挑 5-10 个视觉复杂、容易误改的组件（价格卡、空状态、图表），否则每次改设计都要批量更新基准图，评审会变成「看 200 张图」。

集成测试：integration_test 与 Patrol ​

dart
// integration_test/app_test.dart
import 'package:integration_test/integration_test.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:shop/main.dart' as app;

void main() {
  IntegrationTestWidgetsFlutterBinding.ensureInitialized();

  testWidgets('登录 → 加购 → 下单', (tester) async {
    app.main();
    await tester.pumpAndSettle();
    await tester.enterText(find.byKey(const Key('phone')), '13800000000');
    await tester.tap(find.byKey(const Key('login')));
    await tester.pumpAndSettle();
    expect(find.text('首页'), findsOneWidget);
  });
}
bash
flutter test integration_test/app_test.dart -d <device-id>
flutter drive --driver=test_driver/integration_test.dart \
  --target=integration_test/app_test.dart -d <device-id>

integration_test 跑在真实设备上，能覆盖插件、权限、原生弹窗；flutter drive 是更老的方式，需要额外 driver 文件。Patrol 在此之上补了「系统弹窗、通知、跨 App 操作」的原生能力，适合权限/支付/推送链路。

集成测试只做冒烟

集成测试应该回答「主流程还能不能走通」，而不是覆盖每个字段校验。3-8 条关键路径足够；每条都要能在失败时指出「哪一步、哪个页面」。

覆盖率门禁与反模式 ​

bash
flutter test --coverage
lcov --summary coverage/lcov.info
genhtml coverage/lcov.info -o coverage/html   # 本地看 HTML
yaml
# CI 片段：低于 70% 直接失败（可用 very_good_coverage 等工具）
- run: flutter test --coverage
- run: |
    pct=$(lcov --summary coverage/lcov.info 2>&1 | grep -oE '[0-9.]+%' | head -1)
    echo "line coverage: $pct"

覆盖率不是 KPI。门禁看「新增代码覆盖率」比看全局数字更合理：老代码 40%、新 PR 必须 80%，团队才会真正补测试。

可运行示例 ​

DartPad 运行环境将在滚动到此处时加载…
查看完整源码
dart
import 'package:flutter/material.dart';

// 「测试即示例」：被测对象是纯 Dart 类，用例是可枚举的数据。
// 真实项目放进 test/ 由 flutter test 执行，这里直接跑在界面上。
void main() => runApp(const MaterialApp(home: _Demo()));

/// 订单金额计算（单位：分，整数避免浮点误差）：满 200 减 30，VIP 再 9 折。
class PriceCalculator {
  const PriceCalculator({this.vip = false, this.threshold = 20000});
  final bool vip;
  /// 满减门槛，做成可注入的，方便演示「变异测试」。
  final int threshold;
  int total(List<int> prices) {
    final sum = prices.fold<int>(0, (a, b) => a + b);
    final after = sum >= threshold ? sum - 3000 : sum;
    return vip ? after * 90 ~/ 100 : after;
  }
}
class _Case {
  const _Case(this.name, this.expected, this.prices, {this.vip = false});
  final String name;
  final int expected;
  final List<int> prices;
  final bool vip;
}

const List<_Case> _cases = <_Case>[
  _Case('空购物车', 0, <int>[]),
  _Case('未满 200 不减', 15000, <int>[10000, 5000]),
  _Case('满 200 减 30', 18000, <int>[15000, 6000]),
  _Case('VIP 再打 9 折', 16200, <int>[15000, 6000], vip: true),
  _Case('边界：刚好 200', 17000, <int>[20000]),
];

class _Demo extends StatefulWidget {
  const _Demo();
  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  /// 打开变异开关 = 故意把门槛改错，验证测试能否抓到 bug。
  bool _mutated = false;
  bool _run = false;

  bool _pass(_Case c) =>
      PriceCalculator(vip: c.vip, threshold: _mutated ? 25000 : 20000)
          .total(c.prices) ==
      c.expected;

  String _money(int cents) => '¥${(cents / 100).toStringAsFixed(2)}';

  @override
  Widget build(BuildContext context) {
    final scheme = Theme.of(context).colorScheme;
    final ok = _cases.where(_pass).length;
    return ListView(
      padding: const EdgeInsets.all(16),
      children: [
        Text(
          '纯 Dart 状态类没有 Widget、没有插件，毫秒级执行，是测试金字塔的底座。',
          style: TextStyle(color: scheme.onSurfaceVariant),
        ),
        OutlinedButton(
          onPressed: () => setState(() => _run = true),
          child: Text(_run ? '重新运行 ${_cases.length} 个用例' : '运行用例'),
        ),
        SwitchListTile(
          contentPadding: EdgeInsets.zero,
          title: const Text('变异开关：门槛改成 250 元'),
          subtitle: const Text('模拟改坏业务代码，看哪条用例变红'),
          value: _mutated,
          onChanged: (v) => setState(() {
            _mutated = v;
            _run = true;
          }),
        ),
        if (_run)
          Text(
            '通过 $ok / ${_cases.length}',
            style: TextStyle(
              fontWeight: FontWeight.bold,
              color: ok == _cases.length ? scheme.primary : scheme.error,
            ),
          ),
        for (final c in _cases)
          ListTile(
            dense: true,
            leading: Icon(
              !_run
                  ? Icons.radio_button_unchecked
                  : _pass(c)
                      ? Icons.check_circle
                      : Icons.error,
              color: !_run
                  ? scheme.outline
                  : _pass(c)
                      ? scheme.primary
                      : scheme.error,
            ),
            title: Text(c.name),
            subtitle: Text(
              '期望 ${_money(c.expected)} · 输入 '
              '${c.prices.isEmpty ? '空' : c.prices.map(_money).join(' + ')}',
            ),
          ),
      ],
    );
  }
}

常见坑 ​

高频踩坑点

  1. 只写集成测试：反馈慢、定位难、CI 成本高，最后没人跑。按 70/20/10 分配，先补纯逻辑。
  2. 测试依赖执行顺序：共享可变全局状态，单跑通过、全跑失败。每个用例自己构造数据。
  3. 断言文案而不是行为：find.text('保存成功') 一改文案就红；关键交互用 Key 定位，行为用状态/回调断言。
  4. 在测试里等真实网络/延时：Future.delayed(2s) 会让套件越来越慢；用注入的 Clock / FakeAsync。
  5. Golden 在本机更新、在 CI 校验：两台机器字体/渲染不同，基准图永远对不上。基准图只在 Linux CI 生成。

课后练习 ​

  1. 补齐单测：挑一个包含折扣/边界判断的纯 Dart 类，写 8 条用例覆盖正常、边界、异常，跑 flutter test --coverage 看行覆盖率。
  2. Widget 测试：给一个带表单的页面加 Key，写「输入非法手机号 → 显示错误」与「输入合法 → 按钮可点」两条测试。
  3. Golden 实战：选一个视觉组件生成基准图，故意改 2px 边距，确认测试变红后再改回。
  4. 集成冒烟：用 integration_test 写一条「启动 → 首页可见 → 进入详情」的冒烟用例，在真机跑通。
  5. 门禁设计：为你的项目设计覆盖率门禁（全局 + 新增代码），说明阈值、统计口径和豁免规则。
