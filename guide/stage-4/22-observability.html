可观测性与灰度开关 ​

学习目标 ​

学完本章，你将能够：

  • 用日志 / 指标 / 链路三件套描述线上系统的真实状态
  • 设计分级、结构化、可检索的日志，避免把隐私写进日志
  • 在正确的位置接入崩溃上报（Crashlytics / Sentry）并处理同意与脱敏
  • 用远程配置管理功能开关，做到「不发版也能关掉坏功能」
  • 设计可回滚的灰度与 A/B 实验：分流、指标、护栏、决策
  • 按规范定义埋点事件与参数，保证数据可信

可观测性回答三个问题

出了什么事（日志）、影响多大（指标）、卡在哪一步（链路）。三件套缺一，排障就会变成猜谜。

三件套：日志 / 指标 / 链路 ​

维度回答的问题典型载体成本
日志 Logs这一刻发生了什么结构化事件、异常栈低
指标 Metrics整体是否健康、趋势如何首帧、帧率、崩溃率、ANR 率中
链路 Traces一次请求慢在哪一跳span、trace id、上下游耗时高

Flutter 侧最值得上报的指标：

  • 首帧时间：WidgetsBinding.instance.addTimingsCallback 或自定义启动打点。
  • 帧率 / 掉帧：FrameTiming 的 build / raster 分布，按页面维度聚合。
  • ANR / 卡死：主 isolate 长时间无响应，配合原生侧 watchdog。
  • 崩溃率：按版本、机型、系统版本拆分，关注「新增崩溃」。

指标要有基线

单独一个「平均帧率 58」没有意义。必须带版本、机型档位、页面三个维度，并和上一个版本对比，才能判断是不是回归。

日志分级与结构化日志 ​

dart
import 'dart:developer' as developer;

enum LogLevel { debug(500), info(800), warn(900), error(1000); 
  const LogLevel(this.severity);
  final int severity;
}

void logEvent(LogLevel level, String event, Map<String, Object?> data) {
  // 结构化：事件名 + 参数，而不是拼一句话
  final payload = {'event': event, ...data};
  developer.log(payload.toString(), name: 'shop', level: level.severity);
}
dart
logEvent(LogLevel.info, 'checkout_submit', {
  'order_id': 'A1024',
  'amount_cents': 18000,
  'pay_method': 'wechat',
});
级别用途线上默认
debug开发细节、状态快照关闭
info关键业务动作（下单、登录）采样上报
warn可恢复异常（重试成功、降级）上报
error功能失败、崩溃前上下文全量上报

日志三不要

  1. 不要 print：release 下不可控、无法分级、无法脱敏。用 dart:developer 或日志库。
  2. 不要记录手机号、身份证、token、完整地址：日志会被导出、聚合、长期留存。
  3. 不要拼接非结构化字符串："用户 ${id} 下单 ${amount}" 无法检索与聚合，改用事件 + 参数。

崩溃上报与隐私合规 ​

接入点通常只有两处：

dart
void main() {
  FlutterError.onError = (details) {
    FlutterError.presentError(details);
    // crashReporter.recordError(details.exception, details.stack);
  };
  PlatformDispatcher.instance.onError = (error, stack) {
    // crashReporter.recordError(error, stack);
    return true;
  };
  runApp(const MyApp());
}
  • Crashlytics：与 Firebase 生态绑定，自动收集原生崩溃、ANR、符号化。
  • Sentry：跨端能力强，支持性能链路、release health，SDK 体积略大。
  • 无论选谁，都要在初始化时设置 release、environment、dist，否则聚合结果不可用。

隐私合规红线

崩溃上报默认可能带上设备标识、页面参数甚至用户输入。上线前必须确认：用户同意后才初始化、关闭 PII 自动采集、对 URL/参数做白名单脱敏、提供删除请求通道（GDPR/个保法）。

远程配置与功能开关 ​

dart
abstract class FeatureFlags {
  bool get newCheckout;
  bool get enableTrace;
}

/// 真实实现从 Firebase Remote Config / 自建配置中心拉取，
/// 这里给出「默认值 + 覆盖」的最小心智模型。
class RemoteFlags implements FeatureFlags {
  RemoteFlags(this._remote);
  final Map<String, bool> _remote;

  @override
  bool get newCheckout => _remote['new_checkout'] ?? false; // 默认关闭
  @override
  bool get enableTrace => _remote['enable_trace'] ?? false;
}

设计原则：

原则说明
默认安全拉不到配置时用「关闭/旧路径」，不要默认开实验
本地缓存冷启动先读缓存，再异步刷新，避免首帧被网络阻塞
服务端兜底开关也要有 kill switch，异常时可一键全关
类型明确bool / int / String 分开，不要一个 key 多种含义
可观测开关值随日志/事件一起上报，否则无法解释数据差异

开关不是「配置大杂烩」

功能开关用于控制风险，不是放运营文案的地方。每个开关都应有 owner、创建时间、预计删除时间，否则一年后没人敢动。

灰度与 A/B：指标、分流、回滚 ​

标准灰度节奏：

阶段比例观察重点退出条件
内测1% / 内部账号崩溃、核心链路无新增 P0
小流量5%-10%崩溃率、下单成功率护栏指标不劣化
扩量50%性能、客服反馈连续 2 天稳定
全量100%长尾机型保留 kill switch 一周

A/B 实验要先写清楚四件事：

  1. 假设：新版结算预计提升提交率 3%。
  2. 分流：按稳定 hash（设备/用户 id）分桶，保证同一用户始终同组。
  3. 主指标 + 护栏指标：提交率是主指标；崩溃率、支付失败率是护栏，护栏劣化立即停。
  4. 样本量与周期：至少覆盖一个完整业务周期，避免周内波动误判。

埋点规范：

项规范
命名全小写 + 下划线，动作用过去式：checkout_submitted
参数固定 schema，值用枚举/数字；禁止自由文本
公共参数版本、渠道、实验分组由 SDK 统一附加
校验开发期断言必填参数，CI 跑埋点 schema 校验
隐私不上报手机号、身份证、精确位置

分流与指标的两个暗坑

  1. 样本比例失衡（SRM）：预期 50/50，实际 52/48 且持续扩大，说明分流有 bug，实验结论作废。
  2. 只看主指标不看护栏：提交率涨了 5%，但崩溃率翻了 3 倍——这是用体验换数字，必须回滚。

开关治理与生命周期 ​

类型生命周期清理方式
发布开关数天到数周全量后删除判断分支
实验开关一个实验周期结论落地后删除
权限/套餐开关长期纳入配置中心管理
应急 kill switch长期保留，定期演练

每季度做一次开关审计：列出所有 key、最后读取时间、owner。三个月没人读的开关，大概率可以删。

dart
import 'dart:developer' as developer;

import 'package:flutter/material.dart';
void main() => runApp(const MaterialApp(home: _Demo()));
/// 日志级别：数值越大越严重，用来做「最低级别」过滤。
enum LogLevel {
  debug('D', 500, Colors.grey),
  info('I', 800, Colors.blue),
  warn('W', 900, Colors.orange),
  error('E', 1000, Colors.red);

  const LogLevel(this.tag, this.severity, this.color);
  final String tag; final int severity; final Color color;
}
class _LogEntry {
  const _LogEntry(this.level, this.message);
  final LogLevel level; final String message;
}
/// 最简结构化日志器：按级别过滤、环形缓冲，同时写进 dart:developer。
class AppLogger {
  LogLevel minLevel = LogLevel.debug;
  final List<_LogEntry> entries = <_LogEntry>[];

  void log(LogLevel level, String message) {
    if (level.index < minLevel.index) return; // 低于阈值直接丢弃
    entries.insert(0, _LogEntry(level, message));
    if (entries.length > 20) entries.removeLast();
    developer.log(message, name: 'shop.${level.name}', level: level.severity);
  }
}
class _Demo extends StatefulWidget {
  const _Demo();
  @override
  State<_Demo> createState() => _DemoState();
}
class _DemoState extends State<_Demo> {
  final AppLogger _logger = AppLogger();
  bool _newCheckout = false;
  void _log(LogLevel level, String message) =>
      setState(() => _logger.log(level, message));
  @override
  Widget build(BuildContext context) {
    final scheme = Theme.of(context).colorScheme;
    return ListView(
      padding: const EdgeInsets.all(16),
      children: [
        SwitchListTile(
          contentPadding: EdgeInsets.zero,
          title: const Text('新结算流程（远程开关）'),
          subtitle: Text(_newCheckout ? '实验组：新版 UI' : '对照组：旧版 UI'),
          value: _newCheckout,
          onChanged: (v) => setState(() {
            _newCheckout = v;
            _logger.log(LogLevel.info, '开关 new_checkout 切换为 $v');
          }),
        ),
        Card(
          margin: EdgeInsets.zero,
          child: ListTile(
            leading: Icon(
              _newCheckout ? Icons.rocket_launch : Icons.shopping_cart,
              color: scheme.primary,
            ),
            title: Text(_newCheckout ? '新版结算：一步下单 + 预估到达' : '旧版结算：地址 → 支付 → 确认'),
          ),
        ),
        Wrap(
          spacing: 8,
          children: [
            for (final level in LogLevel.values)
              OutlinedButton(
                onPressed: () => _log(level, '手动触发 ${level.name} 日志'),
                child: Text('写 ${level.name}'),
              ),
          ],
        ),
        const Text('最低级别'),
        Wrap(
          spacing: 6,
          children: [
            for (final level in LogLevel.values)
              ChoiceChip(
                label: Text(level.name),
                selected: _logger.minLevel == level,
                onSelected: (_) => setState(() => _logger.minLevel = level),
              ),
          ],
        ),
        const Divider(),
        if (_logger.entries.isEmpty) const Text('当前过滤条件下没有日志'),
        for (final entry in _logger.entries.take(6))
          Padding(
            padding: const EdgeInsets.symmetric(vertical: 4),
            child: Row(
              children: [
                Icon(Icons.circle, size: 10, color: entry.level.color),
                const SizedBox(width: 8),
                Expanded(
                  child: Text(
                    '${entry.level.tag} ${entry.message}',
                    style: TextStyle(color: entry.level.color),
                  ),
                ),
              ],
            ),
          ),
      ],
    );
  }
}

常见坑 ​

高频踩坑点

  1. 日志里带 PII：手机号、token、地址进了日志平台，等于把隐私复制到第三个系统。
  2. 开关默认开启：远程配置拉取失败时直接进实验组，故障面被放大。默认值必须是安全路径。
  3. 开关读取散落各处：if (RemoteConfig.getBool('x')) 出现在 20 个文件里，无法统一清理。收敛到 FeatureFlags 接口。
  4. 只上报崩溃不上报上下文：没有页面、版本、实验分组，崩溃无法复现也无法归因。
  5. 灰度没有回滚预案：扩量后才发现服务端不兼容，此时只能发版。上线前先验证 kill switch。

课后练习 ​

  1. 日志分级：给现有项目加一个最小 Logger，支持 debug/info/warn/error 与采样开关，确保 release 不输出 debug。
  2. 开关抽象：定义 FeatureFlags 接口 + 本地 Fake 实现 + 远程实现，让 UI 只依赖接口，并写单测覆盖「默认关闭」。
  3. 灰度方案：为「新版结算页」写一份灰度计划：分流键、比例节奏、主指标、护栏指标、回滚条件。
  4. 埋点校验：为 3 个核心事件定义 schema（事件名、必填参数、类型），写一个测试校验参数完整性。
  5. 隐私自查：列出当前崩溃/日志上报中可能包含的 PII 字段，给出脱敏或删除方案。
