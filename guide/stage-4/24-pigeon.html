Pigeon 与类型安全通道 ​

学习目标 ​

学完本章，你将能够：

  • 说清手写 MethodChannel 的「字符串契约」风险：key 拼错、类型漂移、两端解析代码重复
  • 用 @HostApi / @FlutterApi 在 Dart 里声明双向接口，并区分调用方向与线程
  • 配置 pigeon.yaml（或 @ConfigurePigeon 注解）生成 Dart / Kotlin / Swift 三端代码
  • 处理嵌套数据类、枚举、集合与可空，理解生成代码的编解码路径
  • 在两端实现 HostApi，用稳定错误码替代裸字符串判断，并制定迁移策略

与阶段三的边界

阶段三《平台通道》已讲过三种 Channel 与手写桥接。本章不重复「怎么建 Channel」，只回答：怎样让跨语言契约在编译期就被检查。

一、字符串契约的三种失效方式 ​

手写通道传的本质是 Map<Object?, Object?>，两端靠口头约定对齐，故障只在运行时出现：

失效方式现场代价
key 拼错Dart 取 map['deviceModel']，Kotlin 写 "device_model"拿到 null，往往上线才暴露
类型漂移原生返回 Int，Dart 直接 as Stringtype 'int' is not a subtype of type 'String'
结构重构嵌套 Map / List 手写解析两端都要改，改漏一处就是线上事故

Pigeon 把接口收敛到一份 Dart 文件，同时生成 Dart 代理、Kotlin 处理器、Swift 处理器。名字、类型、可空性由生成器保证，字符串 key 根本不存在。

二、把接口写进 Dart：@HostApi 与 @FlutterApi ​

dart
import 'package:pigeon/pigeon.dart';

enum DeviceTier { low, mid, high }

class DeviceInfo {
  const DeviceInfo({required this.model, required this.tier, required this.cores});
  final String model;
  final DeviceTier tier;
  final int cores;
}

@HostApi()
abstract class DeviceApi {
  String getVersion();
  DeviceInfo getDeviceInfo();
  void startScan(); // 无返回值的方法，Dart 侧仍返回 Future<void>
}

@FlutterApi()
abstract class DeviceEvents {
  void onBatteryChanged(int percent, bool charging);
}

两个注解的方向正好相反：

@HostApi@FlutterApi
调用方向Dart → 原生原生 → Dart
生成物Dart 代理 + Kotlin / Swift 处理器Dart 处理器 + Kotlin / Swift 代理
典型用途取数据、触发系统能力传感器、电量、下载进度
执行位置原生平台线程（默认）Dart UI isolate
生命周期引擎 attach 后注册一次原生侧必须持有强引用

@HostApi 的 Dart 声明看似同步，生成的方法一律返回 Future：跨语言调用没有同步返回这回事。

不要把 HostApi 当本地函数

每个 await 背后都是一次二进制消息往返。在滚动或 build 里连续调用十几个 HostApi，掉帧的是 UI 线程；批量接口应设计成一次往返拿一组数据。

三、生成配置与产物 ​

输入放在 pigeons/，生成参数写进 pigeon.yaml：

yaml
# pigeon.yaml
input: pigeons/messages.dart
dart_out: lib/src/pigeon/messages.g.dart
dart_test_out: test/pigeon/messages_test.g.dart
kotlin_out: android/src/main/kotlin/dev/example/app/pigeons/Messages.g.kt
kotlin_package: dev.example.app.pigeons
swift_out: ios/Runner/Pigeons/Messages.g.swift
bash
flutter pub add --dev pigeon
dart run pigeon --config pigeon.yaml
pigeons/messages.dart              # 唯一事实源（接口声明）
lib/src/pigeon/messages.g.dart     # Dart 代理 + 数据类
test/pigeon/messages_test.g.dart   # mock 处理器，用于纯 Dart 单测
android/.../pigeons/Messages.g.kt  # Kotlin 处理器 + 数据类
ios/Runner/Pigeons/Messages.g.swift # Swift 处理器 + 数据类

也可以直接在输入文件加 @ConfigurePigeon(PigeonOptions(...))，效果等价；团队更推荐 YAML，路径集中、评审时一眼能看到产物落在哪。

生成物要进 CI

提交生成物，并在 CI 跑 dart run pigeon --config pigeon.yaml && git diff --exit-code。有人改了接口忘记重生成时，流水线会直接拦下。

四、类型系统：嵌套、枚举、集合与可空 ​

Pigeon 为自定义类生成两端的真实类型，而不是 Map：

DartKotlinSwift
String / int / double / boolString / Long / Double / BooleanString / Int64 / Double / Bool
Uint8ListByteArrayData
List<T> / Map<K, V>List<T> / Map<K, V>[T] / [K: V]
enumenum classenum（Int 原始值）
T?T?T?

把 List<DeviceInfo> 放进数据类字段即可，生成器会递归处理：

  • 可空性必须显式：非空字段原生返回 null 会在反序列化时抛错，比业务层拿到 null 更早暴露。
  • 枚举跨版本：新增枚举值时旧版本原生解码会失败；先发能产生新值的一端，或改用 String 兼容。
  • 不要用 Object：生成器无法建立两端映射。
  • 集合只支持一层泛型：List<List<T>> 需要包一层数据类。

五、错误处理：让失败也是契约的一部分 ​

原生侧用稳定错误码返回失败，Swift 对应 PigeonError：

kotlin
if (!hasPermission) throw PigeonError("PERMISSION_DENIED", "缺少相机权限", null)
if (timeout) throw PigeonError("DEVICE_BUSY", "设备无响应", null)
return scanResult

Dart 侧按 PlatformException.code 分支，而不是匹配错误文案：

dart
try {
  final info = await DeviceApi().getDeviceInfo();
  setState(() => _info = info);
} on PlatformException catch (e) {
  switch (e.code) {
    case 'PERMISSION_DENIED':
      _showGuide('去系统设置开启权限');
    case 'DEVICE_BUSY':
      _showGuide('稍后重试');
    default:
      _showGuide('未知错误：${e.code}');
  }
}

不要用异常做正常流程

「用户还没授权」是正常状态，不是异常。权限、首次引导这类可预期分支应设计成返回值里的状态字段；PlatformException 只留给真正的失败。

六、Android / iOS 侧实现 ​

Kotlin 侧实现生成的接口，并在 configureFlutterEngine 注册一次：

kotlin
class DeviceApiImpl : DeviceApi {
    override fun getVersion(): String = BuildConfig.VERSION_NAME
    override fun getDeviceInfo(): DeviceInfo =
        DeviceInfo(Build.MODEL, DeviceTier.HIGH, Runtime.getRuntime().availableProcessors().toLong())
    override fun startScan() { /* 切 IO 线程，完成后回调 */ }
}

override fun configureFlutterEngine(flutterEngine: FlutterEngine) {
    super.configureFlutterEngine(flutterEngine)
    DeviceApi.setUp(flutterEngine.dartExecutor.binaryMessenger, DeviceApiImpl())
    DeviceEvents.setUp(flutterEngine.dartExecutor.binaryMessenger, BatteryEvents())
}

Swift 侧对应 DeviceApiSetup.setUp(binaryMessenger:api:)。如果使用插件形态，注册放 onAttachedToEngine、在 onDetachedFromEngine 置空；写在 MainActivity 里热重启、多引擎会重复注册。

七、迁移、性能与测试 ​

迁移按「一个 API 一条通道」推进：新接口直接用 Pigeon，旧 MethodChannel 保留；用 feature flag 灰度；每次只迁一个方法，迁完删旧分支；最后统一错误码表，避免同一失败有两个名字。

性能上要建立正确预期：

对比项手写 MethodChannelPigeon
通道往返次数1 次1 次（不会更少）
编解码StandardMessageCodec + Map仍是 StandardMessageCodec，但按位置编码 List
手动类型转换每个字段一次生成代码完成，业务层零转换
小 payload 开销基准通常省 10%~30% 解码时间，不是数量级差异
主要收益灵活编译期契约、重构安全、两端同步

真正的耗时大头仍是线程切换与原生实际工作。测试方面，开启 dart_test_out 会生成 mock 处理器，可在纯 Dart 单测模拟原生返回值与错误；原生侧再补 Kotlin / Swift 单测覆盖错误码，真机只验证「注册成功 + 一次快乐路径」。

dart
import 'package:flutter/material.dart';

// 纯 Dart 模拟 Pigeon：契约写在接口上，两端共享同一套类型。
// 真实项目里这些接口与实现由 `dart run pigeon` 生成，这里手写等价物看结构。
void main() => runApp(const MaterialApp(home: _PigeonPage()));

enum DeviceTier { low, mid, high }

class DeviceInfo {
  const DeviceInfo({required this.model, required this.tier, required this.cores});
  final String model;
  final DeviceTier tier;
  final int cores;
}
/// 等价 PlatformException：跨边界的失败必须带稳定的 code。
class BridgeException implements Exception {
  const BridgeException(this.code);
  final String code;
}
/// 等价 @HostApi()：Dart 调原生，返回值类型在编译期固定。
abstract class HostApi {
  Future<DeviceInfo> getDeviceInfo();
}
/// 等价 @FlutterApi()：原生调 Dart，参数不是 Map。
abstract class FlutterApi {
  void onBatteryChanged(int percent, bool charging);
}

/// 模拟原生侧持有的 FlutterApi 引用，回调方向是 原生 → Dart。
class _BatteryListener implements FlutterApi {
  _BatteryListener(this.onEvent);
  final void Function(String) onEvent;

  @override
  void onBatteryChanged(int percent, bool charging) =>
      onEvent('↓ 原生推送：电量 $percent%${charging ? '（充电中）' : ''}');
}

/// 模拟原生实现；offline 用来演示错误码分支。
class FakeNativeHost implements HostApi {
  const FakeNativeHost({this.offline = false});
  final bool offline;

  @override
  Future<DeviceInfo> getDeviceInfo() async {
    if (offline) throw const BridgeException('DEVICE_BUSY');
    return const DeviceInfo(model: 'Pixel 8', tier: DeviceTier.high, cores: 9);
  }
}

class _PigeonPage extends StatefulWidget {
  const _PigeonPage();
  @override
  State<_PigeonPage> createState() => _PigeonPageState();
}

class _PigeonPageState extends State<_PigeonPage> {
  bool _offline = false;
  final List<String> _log = <String>[];
  late final FlutterApi _events =
      _BatteryListener((msg) => setState(() => _log.insert(0, msg)));

  Future<void> _call(String label, Future<String> Function(HostApi) run) async {
    try {
      final result = await run(FakeNativeHost(offline: _offline));
      setState(() => _log.insert(0, '✓ $label → $result'));
    } on BridgeException catch (e) {
      setState(() => _log.insert(0, '✗ $label → ${e.code}（按 code 分支，不猜文案）'));
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: <Widget>[
          const Text('返回值是 DeviceInfo 而不是 Map；原生失败抛出带 code 的异常。'),
          SwitchListTile(
            contentPadding: EdgeInsets.zero,
            title: const Text('模拟原生不可用'),
            value: _offline,
            onChanged: (v) => setState(() => _offline = v),
          ),
          Wrap(
            spacing: 8,
            children: <Widget>[
              FilledButton.tonal(
                onPressed: () => _call('getDeviceInfo', (api) async {
                  final info = await api.getDeviceInfo();
                  return '${info.model} / ${info.tier.name} / ${info.cores} 核';
                }),
                child: const Text('取设备信息'),
              ),
              OutlinedButton(
                onPressed: () => _events.onBatteryChanged(76, true),
                child: const Text('原生推事件'),
              ),
            ],
          ),
          for (final line in _log)
            Padding(
              padding: const EdgeInsets.only(bottom: 6),
              child: Text(line),
            ),
        ],
      ),
    );
  }
}

常见坑 ​

高频踩坑点

  1. 手改 .g.dart：下次生成直接覆盖。要改就改 pigeons/messages.dart 再重生成。
  2. 生成物没提交：CI 或新同事拉下代码后编译失败。生成物入库，并在 CI 做一致性检查。
  3. 在 Activity 里重复注册：热重启或多引擎时 handler 叠加，一次调用触发多次回调。
  4. FlutterApi handler 被释放：原生只持弱引用，页面销毁后事件静默丢失，需显式 detach。
  5. 在平台线程做重活：HostApi 默认在平台线程执行，文件扫描、图片解码会卡 UI 甚至 ANR。
  6. 枚举悄悄扩值：一端新增、另一端仍是旧版本，解码直接抛错；跨版本字段优先用 String。

课后练习 ​

  1. 迁移一个方法：把阶段三的 getAppVersion 改成 Pigeon，记录删除的手写解析代码与新增的生成文件。
  2. 嵌套类型：设计 ScanResult（含 List<DeviceInfo>、枚举、可空时间戳），两端各实现一次，验证 null 与空列表。
  3. 双向事件：用 @FlutterApi 把电量变化推给 Dart，页面销毁时解除注册，观察是否还会收到回调。
  4. 错误码单测：用 dart_test_out 生成的 mock 覆盖 PERMISSION_DENIED 与未知错误码。
