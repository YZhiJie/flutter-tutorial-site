原生插件开发 ​

学习目标 ​

学完本章，你将能够：

  • 判断一段原生能力该留在 App 内、做成普通插件，还是拆成 federated 插件
  • 用 flutter create --template=plugin 搭出含 example、test、多平台目录的工程
  • 说清 app-facing / platform interface / platform implementation 三层的职责与依赖方向
  • 正确配置 plugin.platforms，区分 pluginClass、dartPluginClass、default_package
  • 处理 Android（Kotlin / AGP / Gradle）与 iOS（Swift / CocoaPods / SPM）的实现要点

与上一章的衔接

24 章讲「桥怎么建才类型安全」，本章讲「桥建成后，怎么打包成可复用、可发布、可维护的插件」。两者是同一件事的两个阶段。

一、先决定要不要做插件 ​

不是所有原生代码都值得抽成插件：

形态适用场景代价
App 内 MethodChannel / Pigeon只服务当前 App、与业务强绑定无法复用，测试要起整个 App
普通插件（含 example）能力相对独立、可能被别的项目复用多一个仓库与发布流程
Federated 插件按平台独立发版，或允许第三方提供实现包数量多，版本协调复杂

判断标准：这段能力有没有独立的产品边界。相机封装、打印机 SDK、支付通道适合插件；「读取本 App 的配置」留在 App 内。多平台实现各自有团队维护时，才值得上 federated。

二、创建工程与目录结构 ​

bash
flutter create --template=plugin --org dev.example \
  --platforms=android,ios,macos --project-name battery_info battery_info
battery_info/
├── lib/
│   ├── battery_info.dart                 # app-facing 门面
│   └── src/battery_info_method_channel.dart
├── android/src/main/kotlin/dev/example/battery_info/BatteryInfoPlugin.kt
├── ios/
│   ├── battery_info.podspec
│   ├── battery_info/Package.swift        # SPM 清单（新模板）
│   └── Classes/BatteryInfoPlugin.swift
├── example/                              # 可直接 flutter run 的演示 App
├── test/
└── pubspec.yaml

example/ 不是摆设：它是唯一能同时验证 Dart API、原生注册和权限声明的入口。发布前必须能在 example 里跑通。

插件不能依赖 example

example 通过 path 依赖插件；插件不能反向依赖 example，也不能依赖某个具体 App 的 BuildConfig、minSdk 或资源，否则换一个宿主就编译失败。

三、Federated 插件：三层职责 ​

packages/
├── battery/                     # app-facing：稳定 Dart API
├── battery_platform_interface/  # 抽象层：接口 + 数据模型
├── battery_android/             # 实现层：Kotlin + Dart 注册类
└── battery_ios/                 # 实现层：Swift + Dart 注册类
层职责依赖方向
App-facing对外 API，选择默认实现→ platform interface
Platform interface抽象类、签名、平台接口 token不依赖任何实现
Platform implementation真正调原生，注册 Dart 类→ platform interface
Endorsed 实现由 app-facing 的 default_package 指定被 app-facing 引用

抽象层用 token 防止随便 setInstance：

dart
abstract class BatteryPlatform extends PlatformInterface {
  BatteryPlatform() : super(token: _token);
  static final Object _token = Object();
  static BatteryPlatform? _instance;
  static BatteryPlatform get instance => _instance ?? throw UnimplementedError('未注册实现');
  static set instance(BatteryPlatform v) {
    PlatformInterface.verify(v, _token);
    _instance = v;
  }
  Future<int> get level;
}

四、pubspec 的 plugin platforms 配置 ​

app-facing 包只声明默认实现，不写原生类：

yaml
# battery/pubspec.yaml
flutter:
  plugin:
    platforms:
      android:
        default_package: battery_android
      ios:
        default_package: battery_ios

实现包声明 implements 与具体原生类：

yaml
# battery_android/pubspec.yaml
flutter:
  plugin:
    implements: battery
    platforms:
      android:
        package: dev.example.battery_android
        pluginClass: BatteryAndroidPlugin
        dartPluginClass: BatteryAndroid
  • pluginClass：原生注册类，由引擎自动实例化。
  • dartPluginClass：Dart 注册类，在 registerWith() 里把实现塞进平台接口。
  • default_package：federated 场景下 app-facing 默认拉起的实现包。

dartPluginClass 通常只有一行：BatteryPlatform.instance = BatteryAndroidImpl();。

五、Android 与 iOS 的实现要点 ​

Android 用 FlutterPlugin 管生命周期：

kotlin
class BatteryAndroidPlugin : FlutterPlugin, MethodCallHandler {
    private var channel: MethodChannel? = null

    override fun onAttachedToEngine(binding: FlutterPlugin.FlutterPluginBinding) {
        channel = MethodChannel(binding.binaryMessenger, "dev.example/battery")
            .also { it.setMethodCallHandler(this) }
    }

    override fun onDetachedFromEngine(binding: FlutterPlugin.FlutterPluginBinding) {
        channel?.setMethodCallHandler(null)
        channel = null
    }

    override fun onMethodCall(call: MethodCall, result: Result) {
        if (call.method == "level") result.success(readLevel()) else result.notImplemented()
    }
}

iOS 在 register(with:) 里用 FlutterMethodChannel(name:binaryMessenger:) 建立通道，再 registrar.register(channel, with:) 交给引擎。

要点：

  • AGP 8 起 build.gradle 必须写 namespace，Manifest 里的 package 属性已移除。
  • 插件自己的 compileSdk / minSdk 显式声明，不要读宿主的 rootProject.ext。
  • 用到 Activity 时实现 ActivityAware，在 onDetachedFromActivity 置空引用，否则旋转就泄漏。
  • iOS podspec 的 source_files 必须覆盖新增 Swift 文件；迁移 SPM 时保留 podspec 作为 CocoaPods 回退，漏写会在全新 pod install 后找不到类。

六、生命周期、线程与内存 ​

时机AndroidiOS该做什么
引擎 attachonAttachedToEngineregister(with:)建通道、注册 handler
Activity 可用onAttachedToActivityregistrar 提供 viewController获取 UI 上下文
引擎 detachonDetachedFromEnginedetachFromEngine（如有）解绑 handler、取消订阅
页面销毁Dart disposeDart dispose取消 EventChannel、detach FlutterApi

三类典型泄漏

  1. 静态字段持有 Activity / UIViewController：旋转或返回后旧页面无法回收。
  2. BroadcastReceiver / NotificationCenter 只注册不注销：detach 后仍在回调。
  3. 缓存 EventSink 却不 endOfStream：Dart 侧永远等不到结束，订阅也无法释放。

Android 方法调用默认在主线程、iOS 在 main queue。插件内部可把工作丢给 Executor / DispatchQueue，但回调必须在原线程。

七、测试、本地依赖与发布 ​

层工具覆盖什么
Dart 单测flutter test + 平台接口 fake门面逻辑、参数校验、错误映射
原生单测./gradlew test / XCTest纯 Kotlin / Swift 逻辑、边界值
集成测试example + integration_test注册、权限弹窗、一次快乐路径

本地联调优先用 path 依赖，不要每次发版本：

yaml
dependencies:
  battery_info:
    path: ../battery_info

发布前跑 flutter pub publish --dry-run，确认 README、CHANGELOG、example、LICENSE 齐全；example 不留 path 依赖或私有 SDK；federated 多包按依赖顺序发。

可运行示例 ​

DartPad 运行环境将在滚动到此处时加载…
查看完整源码
dart
import 'package:flutter/material.dart';

// 纯 Dart 模拟 federated plugin 的三层：门面 → 平台接口 → 平台实现。
// 真实项目里四层分别是 battery / battery_platform_interface / battery_android / battery_ios。
void main() => runApp(const MaterialApp(home: _FederatedPage()));

enum HostOs { android, ios, desktop }

/// 平台接口：只声明签名，不依赖任何实现。
abstract class BatteryPlatform {
  static BatteryPlatform? _instance;
  static BatteryPlatform get instance =>
      _instance ?? (throw StateError('没有注册平台实现'));
  static set instance(BatteryPlatform impl) => _instance = impl;
  Future<int> readLevel();
  String get implementation;
}

class AndroidBattery implements BatteryPlatform {
  @override
  Future<int> readLevel() async => 82;
  @override
  String get implementation => 'battery_android（Kotlin）';
}

class IosBattery implements BatteryPlatform {
  @override
  Future<int> readLevel() async => 61;
  @override
  String get implementation => 'battery_ios（Swift）';
}

/// app-facing 门面：业务代码只 import 这一层。
class Battery {
  Battery({BatteryPlatform? platform})
      : _platform = platform ?? BatteryPlatform.instance;
  final BatteryPlatform _platform;
  Future<int> level() => _platform.readLevel();
  String get implementation => _platform.implementation;
}

/// 等价 dartPluginClass 的 registerWith()。
void registerFor(HostOs os) {
  if (os == HostOs.android) BatteryPlatform.instance = AndroidBattery();
  if (os == HostOs.ios) BatteryPlatform.instance = IosBattery();
  if (os == HostOs.desktop) throw UnsupportedError('桌面实现尚未发布');
}

class _FederatedPage extends StatefulWidget {
  const _FederatedPage();
  @override
  State<_FederatedPage> createState() => _FederatedPageState();
}

class _FederatedPageState extends State<_FederatedPage> {
  HostOs _os = HostOs.android;
  String _result = '尚未调用';

  Future<void> _run() async {
    try {
      registerFor(_os);
      final Battery battery = Battery();
      final int level = await battery.level();
      setState(() => _result = '${battery.implementation} → $level%');
    } on UnsupportedError catch (e) {
      setState(() => _result = 'UnsupportedError：${e.message}');
    } on StateError catch (e) {
      setState(() => _result = 'StateError：${e.message}');
    }
  }
  @override
  Widget build(BuildContext context) {
    final theme = Theme.of(context);
    return Scaffold(
      appBar: AppBar(title: const Text('Federated 分层')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: <Widget>[
          SegmentedButton<HostOs>(
            segments: const <ButtonSegment<HostOs>>[
              ButtonSegment<HostOs>(value: HostOs.android, label: Text('Android')),
              ButtonSegment<HostOs>(value: HostOs.ios, label: Text('iOS')),
              ButtonSegment<HostOs>(value: HostOs.desktop, label: Text('桌面')),
            ],
            selected: <HostOs>{_os},
            onSelectionChanged: (s) => setState(() {
              _os = s.first;
              _result = '尚未调用';
            }),
          ),
          const SizedBox(height: 12),
          const Text('调用链：Battery().level() → BatteryPlatform → 平台实现'),
          const SizedBox(height: 8),
          FilledButton(onPressed: _run, child: const Text('调用 level()')),
          const SizedBox(height: 12),
          Card(
            child: ListTile(
              leading: const Icon(Icons.storage),
              title: const Text('解析结果'),
              subtitle: Text(_result),
            ),
          ),
          Text('桌面平台会抛 UnsupportedError：门面只负责路由，'
              '缺实现时应显式失败而不是返回假数据。',
              style: theme.textTheme.bodySmall),
        ],
      ),
    );
  }
}

常见坑 ​

高频踩坑点

  1. pluginClass 与 dartPluginClass 写反：前者是 Kotlin/Swift 类，后者是 Dart 注册类，编译能过、运行时找不到实现。
  2. 插件依赖宿主配置：读宿主的 minSdk、BuildConfig 或主题资源，换一个 App 就崩。
  3. example 没声明权限：插件代码没错，但 example 缺 Info.plist / Manifest，一跑就失败。
  4. detach 后还持有上下文：不清 handler、不注销监听，热重启出现双份回调。
  5. 只测 Dart 不测原生：参数校验全绿，原生空指针却在真机才炸。

课后练习 ​

  1. 最小插件：用模板创建返回电池电量的插件，Dart 只暴露 Future<int> get level，在 example 显示。
  2. Federated 拆分：把插件拆成 app-facing / platform interface / android / ios 四个包，用 path 依赖串起来。
  3. 生命周期实验：在 onDetachedFromEngine 打日志，反复热重启，确认没有重复注册与回调。
