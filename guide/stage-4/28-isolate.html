Isolate 与并发模型 ​

学习目标 ​

学完本章，你将能够：

  • 说清 Dart 单线程下事件循环、微任务队列与 await 的调度顺序
  • 解释为什么 Future / async 不能把 CPU 密集计算移出 UI 线程
  • 用 Isolate.run 把一次性重计算搬离主 isolate，并回传结果
  • 用 Isolate.spawn + SendPort / ReceivePort 建立长生命周期工作 isolate
  • 评估消息深拷贝的成本，并用 TransferableTypedData 传递大块二进制
  • 处理 isolate 的关闭、错误传播、调试命名与后台计算选型

一句话结论

Future 解决「等待」，Isolate 解决「并行」。所有 await 仍然跑在同一个线程上；想让另一颗 CPU 核心干活，必须开 isolate。

一、单线程事件循环：event loop 与 microtask ​

Dart 的每个 isolate 都是单线程的，靠事件循环调度两类任务：

队列来源清空时机
微任务队列（microtask）scheduleMicrotask、Future 的完成回调、await 的续体当前同步代码结束后立刻清空
事件队列（event）定时器、I/O、Future(...)、端口消息每轮取一个，处理完再清微任务
dart
import 'dart:async';

void main() {
  print('A');
  Future(() => print('B'));            // 事件队列
  scheduleMicrotask(() => print('C')); // 微任务队列
  print('D');
}
// 输出：A D C B —— 同步代码先跑完，再清微任务，最后才是事件

await x 的本质是：把后续代码注册成 x 完成后的微任务。所以 await 只会「让出当前函数的执行权」，不会让出线程——CPU 仍然被同一个事件循环占用。

二、为什么 Future 不能做 CPU 密集计算 ​

dart
int fib(int n) => n < 2 ? n : fib(n - 1) + fib(n - 2);

Future<void> bad() async {
  final value = await Future(() => fib(42)); // 依然阻塞 UI
  print(value);
}

Future(() => ...) 只是把这段同步计算推迟到事件队列，执行时仍独占主 isolate。界面会在这几百毫秒到几秒里停止出帧：动画冻结、点击无响应，严重时触发 ANR / watchdog。

判断标准很简单：单次同步执行超过一帧预算（约 16ms）且纯 CPU，就应该考虑搬到 isolate。典型例子：大 JSON 解析、图片缩放/滤镜、加密与哈希、压缩解压、复杂排序与统计。

异步不等于并行

async / await 适合 I/O 等待（网络、文件、数据库），因为等待期间线程可以处理别的事件。纯计算没有「等待」可让，只能靠 isolate 换一条执行线程。

三、Isolate.run：一行代码把计算搬走 ​

Dart 2.19+ / Flutter 3.7+ 提供 Isolate.run，它负责创建 isolate、运行闭包、回传返回值并在结束后销毁：

dart
import 'dart:isolate';

final count = await Isolate.run(() => countPrimes(200000));

约束与细节：

  • 闭包及其捕获的变量必须可发送（sendable）：不能捕获 this、BuildContext、打开的文件句柄、ReceivePort 等。
  • 在方法里调用时，先把需要的值放进局部变量：final limit = 200000; await Isolate.run(() => countPrimes(limit));
  • 内部抛出的异常会被包装并重新抛回调用方，try-catch 照常可用。
  • debugName: 参数会显示在 DevTools 的 isolate 列表里，排查卡顿很有用。
  • 每次调用都会新建 isolate，启动开销约几毫秒；高频小任务应改用长生命周期 worker。
dart
final data = await Isolate.run(() => parseHugeJson(raw), debugName: 'json-parse');

Flutter 还提供 compute()（来自 package:flutter/foundation.dart）：只接受一个顶层/静态函数和一个参数。Isolate.run 能力更强，新项目优先用它；compute 的优势是 Web 上会自动退化为当前事件循环执行（不会真的并行）。

选 Isolate.run 还是 compute

一次性、需要闭包、需要传多个值 → Isolate.run。需要兼容 Web 且能接受「Web 上不并行」→ compute。需要反复收发消息 → Isolate.spawn。

四、Isolate.spawn 与 SendPort / ReceivePort ​

需要持续处理任务（例如解压流、批量图片、长连接解析）时，创建一次 worker，通过端口通信：

dart
import 'dart:isolate';

Future<Isolate> startWorker() async {
  final receive = ReceivePort(); // 主 isolate 收结果
  final isolate = await Isolate.spawn(
    _worker,
    receive.sendPort, // 把「回信地址」传给子 isolate
    debugName: 'image-worker',
  );
  receive.listen((message) {
    print('worker 返回: $message');
  });
  return isolate;
}

void _worker(SendPort reply) {
  final commands = ReceivePort(); // 子 isolate 收命令
  reply.send(commands.sendPort);  // 先把命令端口发回主 isolate
  commands.listen((message) {
    if (message == 'exit') {
      commands.close();
      Isolate.exit(); // 结束当前 isolate
    }
    reply.send('处理: $message');
  });
}

要点：

  • SendPort 可以在 isolate 间自由传递；ReceivePort 不行，只能在本 isolate 监听。
  • 双向通信通常需要「握手」：子 isolate 先把自己的 SendPort 发回主 isolate。
  • 结束前 close() 端口；否则端口和监听会一直存活。
  • Isolate.exit(port, result) 可以只发一条最终消息就退出，比 send 后再 kill 更干净。

五、消息传递的成本：深拷贝与 TransferableTypedData ​

isolate 之间不共享可变内存，消息默认做深拷贝：

传递内容机制成本
int / double / String / List / Map深拷贝与数据大小成正比
SendPort / TransferableTypedData转移所有权或传引用近似 O(1)
自定义对象逐字段深拷贝大对象很贵
闭包 / 原生句柄不可发送运行时报错

几十 MB 的 Uint8List 来回拷贝会抵消并行收益。用 TransferableTypedData 把所有权一次转移过去：

dart
import 'dart:isolate';
import 'dart:typed_data';

final bytes = Uint8List.fromList(raw);
final transferable = TransferableTypedData.fromList([bytes]);
final result = await Isolate.run(() {
  final data = transferable.materialize().asUint8List(); // 只能 materialize 一次
  return process(data);
});

不要传大对象「顺便」回传

子 isolate 里解析完 100MB JSON 后，如果回传整个 Map，深拷贝又要把 100MB 搬回主 isolate，UI 依然会卡。只回传真正需要的字段，或回传 TransferableTypedData。

六、生命周期、错误传播与调试 ​

dart
final errors = ReceivePort();
final isolate = await Isolate.spawn(
  _worker,
  message,
  onError: errors.sendPort,
  onExit: exitPort.sendPort,
  errorsAreFatal: false, // 单条消息出错不杀死 worker
);
  • 未捕获异常默认会终止 isolate；给 onError 端口才能在主 isolate 感知。
  • Isolate.run 会把异常与堆栈重新抛到调用方；spawn 需要自己监听错误端口。
  • 不再使用时调用 isolate.kill(priority: Isolate.immediate)，并关闭所有 ReceivePort。
  • 调试：给 isolate 起 debugName，在 DevTools 的 Isolate 列表 / Timeline 中区分；Isolate.pause() / resume() 可断点式挂起。
  • 打印日志时带上 isolate 名称，否则多 lane 日志会混在一起。

七、Flutter 中的后台计算选型 ​

场景推荐方案原因
一次性大 JSON 解析Isolate.run启动成本可接受，代码简单
批量图片滤镜 / 缩放长生命周期 worker + 队列避免每张图都新建 isolate
加密 / 哈希 / 压缩Isolate.run / worker纯 CPU，容易切分
高频小任务（每帧）留在主 isolate，优化算法isolate 启动与通信成本更高
Web 目标compute 或留在主线程Web 无真正多线程 isolate

后台 isolate 不能直接操作 UI；结果必须通过端口/返回值回到 root isolate，再由 setState 或状态管理更新界面。平台通道、插件调用在后台 isolate 中也需要额外注册（BackgroundIsolateBinaryMessenger），不要假设所有插件都能直接用。

同一 isolate group 内的 isolate 共享不可变代码与 VM 基础设施，但各自拥有独立堆；每个 isolate 运行在一条平台线程上，由操作系统调度交织执行，因此不需要共享内存锁。Dart 没有线程优先级 API，长时间占满所有核心反而会让 UI isolate 抢不到 CPU，控制并发数量（通常 Platform.numberOfProcessors - 1）比调优先级更实际。

可运行示例 ​

DartPad 运行环境将在滚动到此处时加载…
查看完整源码
dart
import 'dart:isolate';
import 'dart:math' as math;

import 'package:flutter/material.dart';

// CPU 密集计算放在主 isolate 会卡住动画，放到新 isolate 不会。
void main() => runApp(const _IsolateDemo());

// 故意耗时：统计 limit 以内的素数个数。
int _countPrimes(int limit) {
  var count = 0;
  for (var n = 2; n <= limit; n++) {
    var prime = true;
    for (var d = 2; d * d <= n; d++) {
      if (n % d == 0) { prime = false; break; }
    }
    if (prime) count++;
  }
  return count;
}

class _IsolateDemo extends StatefulWidget {
  const _IsolateDemo();
  @override
  State<_IsolateDemo> createState() => _IsolateDemoState();
}

class _IsolateDemoState extends State<_IsolateDemo>
    with SingleTickerProviderStateMixin {
  late final AnimationController _spin;
  int _frames = 0; // 每帧 +1，用来判断 UI 是否卡住
  bool _busy = false;
  String _status = '选择一种方式计算，观察旋转图标是否停住';

  @override
  void initState() {
    super.initState();
    _spin = AnimationController(vsync: this, duration: const Duration(seconds: 2))
      ..repeat();
    _spin.addListener(() => _frames++);
  }

  @override
  void dispose() {
    _spin.dispose();
    super.dispose();
  }

  Future<void> _run({required bool useIsolate}) async {
    const limit = 120000;
    setState(() {
      _busy = true;
      _status = useIsolate ? 'Isolate.run 计算中…' : '主 isolate 计算中…';
    });
    final before = _frames;
    final watch = Stopwatch()..start();
    var count = 0;
    var note = '';
    if (useIsolate) {
      try {
        // 闭包只捕获局部常量，才能跨 isolate 传递
        count = await Isolate.run(() => _countPrimes(limit));
      } on UnsupportedError {
        note = '（环境不支持 isolate，已退回主线程）';
        count = _countPrimes(limit);
      }
    } else {
      count = await Future<int>(() => _countPrimes(limit));
    }
    watch.stop();
    setState(() {
      _busy = false;
      _status = '$count 个素数 · ${watch.elapsedMilliseconds} ms · '
          '动画前进 ${_frames - before} 帧$note';
    });
  }

  @override
  Widget build(BuildContext context) => MaterialApp(
        home: Scaffold(
          appBar: AppBar(title: const Text('Isolate 与事件循环')),
          body: Padding(
            padding: const EdgeInsets.all(24),
            child: Column(children: [
              AnimatedBuilder(
                animation: _spin,
                builder: (context, child) => Transform.rotate(
                    angle: _spin.value * 2 * math.pi, child: child),
                child: const Icon(Icons.settings, size: 48),
              ),
              const SizedBox(height: 16),
              Text(_status, textAlign: TextAlign.center),
              const SizedBox(height: 24),
              Wrap(spacing: 12, runSpacing: 8, children: [
                FilledButton(
                  onPressed: _busy ? null : () => _run(useIsolate: false),
                  child: const Text('主 isolate 计算'),
                ),
                FilledButton(
                  onPressed: _busy ? null : () => _run(useIsolate: true),
                  child: const Text('Isolate.run 计算'),
                ),
              ]),
            ]),
          ),
        ),
      );
}

常见坑 ​

高频踩坑点

  1. 用 Future 包装 CPU 计算：await Future(() => heavy()) 只是换个时机阻塞，UI 照样掉帧；要用 isolate。
  2. 闭包捕获 this：在 State 方法里写 Isolate.run(() => _compute(_value)) 会尝试发送整个 State 对象；先把值拷到局部变量。
  3. 回传超大结果：深拷贝把收益吃光；只回传必要字段或用 TransferableTypedData。
  4. 忘记关闭端口 / isolate：ReceivePort 与长生命周期 worker 不释放，页面退出后仍在跑，造成泄漏。
  5. 在后台 isolate 里直接调 UI 或插件：没有 root isolate 的绑定，多数平台通道不可用；结果回主 isolate 再更新。
  6. 高频任务频繁 Isolate.run：每次几毫秒启动开销叠加，比同步计算还慢；改用 worker 队列。

课后练习 ​

  1. 帧计数对比：用 Ticker 统计帧数，分别在主 isolate 与 Isolate.run 中执行同一段 500ms 计算，打印「计算期间帧数」。
  2. 双向 worker：用 Isolate.spawn 建一个 worker，主 isolate 发送字符串，worker 返回长度；发送 exit 后优雅退出并关闭端口。
  3. 大数组传输：构造 20MB Uint8List，分别用普通消息与 TransferableTypedData 传到 isolate，用 Stopwatch 对比耗时。
  4. 错误传播：让 worker 对负数抛异常，分别验证 onError 端口与 Isolate.run 的 try-catch 行为。
  5. 并发上限：一次启动 numberOfProcessors + 2 个计算 isolate，观察 UI 是否仍然流畅，并尝试限制并发数后对比。 :::
