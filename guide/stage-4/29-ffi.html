FFI 原生互操作 ​

学习目标 ​

学完本章，你将能够：

  • 理解 dart:ffi 的定位：在 Dart 中直接调用 C ABI 函数与访问原生内存
  • 掌握常用类型映射：Int32、Double、Pointer<T>、Struct、Union、Array
  • 用 DynamicLibrary.open/process 加载动态库，并正确调用与释放内存
  • 用 ffigen 从 C 头文件生成绑定，减少手写 lookup 的样板代码
  • 处理回调（NativeCallable）、线程与 NativePort 的基本模型
  • 判断何时用 FFI、何时继续用 Platform Channel，并能排查原生崩溃

先理解契约

FFI 不是「调用一个函数」那么简单，而是同时接管了 ABI 约定、内存所有权、线程边界。三者任一错位，轻则数据错乱，重则进程直接崩溃。

一、FFI 能做什么、不能做什么 ​

dart:ffi 让 Dart 通过 C ABI 调用动态库函数、读写原生内存、注册原生回调。典型用途：复用 C/C++ 库（音视频、图像处理、压缩、加密、SQLite、推理引擎），实现信号处理、物理模拟等密集计算，或访问插件未暴露的底层 API。

限制：Web 不支持（要用 JS interop / WASM）；内存生命周期要自己管理；每个平台都要提供对应架构的库并处理签名打包；FFI 调用同步执行，在 UI isolate 调耗时函数会卡帧。

二、基本类型映射 ​

C 类型Dart 类型说明
int8_t / uint8_tInt8 / Uint8定宽整数
int16_t / uint16_tInt16 / Uint16注意对齐
int32_t / uint32_tInt32 / Uint32最常用
int64_t / uint64_tInt64 / Uint64大整数
float / doubleFloat / DoubleFloat 只有 32 位精度
void* / T*Pointer<Void> / Pointer<T>指针
struct / unionextends Struct / extends Union字段用 external + 注解
函数指针NativeFunction<...> + asFunction或 NativeCallable
不透明句柄Handle / Opaque只传递不访问

手写绑定示例：

dart
import 'dart:ffi';

typedef _AddNative = Int32 Function(Int32 a, Int32 b);
typedef _AddDart = int Function(int a, int b);

final lib = DynamicLibrary.open('libmathx.so');
final add = lib.lookup<NativeFunction<_AddNative>>('add').asFunction<_AddDart>();
print(add(2, 3));

NativeFunction 描述 C 侧签名，asFunction 生成 Dart 可调用函数；两个 typedef 不能省。较新的 @Native 写法由编译器在链接期解析符号：

dart
@Native<Int32 Function(Int32, Int32)>(symbol: 'add')
external int add(int a, int b);

三、加载动态库：各平台路径差异 ​

DynamicLibrary.open('libfoo.so') 加载具体动态库，DynamicLibrary.process() 从当前进程已加载符号查找，DynamicLibrary.executable() 查静态链接进二进制的符号。

平台常见库名打包位置 / 说明
Androidlibfoo.soandroid/app/src/main/jniLibs/<abi>/，按 ABI 分包
iOS静态库或内嵌 framework不能随意 dlopen，多用 DynamicLibrary.process()
macOSlibfoo.dylib / framework放 Frameworks/ 并签名
Windowsfoo.dll与 .exe 同目录或系统路径
Linuxlibfoo.so随包安装，注意 RPATH

Android 需要 arm64-v8a、armeabi-v7a、x86_64 对应产物；iOS 真机 arm64、模拟器 arm64/x86_64 需分别提供或打成 xcframework。新版 Android 还要求原生库按 16KB 页对齐，老库可能直接加载失败。

四、内存管理：malloc、calloc、free 与 Arena ​

dart
import 'dart:ffi';

final buffer = calloc<Uint8>(1024); // 分配并清零
buffer[0] = 1;
malloc.free(buffer); // 必须释放，否则泄漏
  • calloc 会清零，malloc.allocate<T>(byteCount) 不保证清零。
  • malloc.free(pointer) 只能释放同一分配器返回的指针，不能 double free。
  • 指针越界、释放后访问、结构体大小算错都属于未定义行为，桌面上通常直接段错误。
  • package:ffi 的 Arena 适合「一组临时分配、统一释放」：final arena = Arena(); final p = arena.allocate<Vec3>(sizeOf<Vec3>());，作用域结束调用 releaseAll()。
  • 跨 Dart 对象生命周期持有原生内存时，用 NativeFinalizer 在 GC 时释放，而不是依赖手写 dispose。

内存所有权必须唯一

谁分配、谁释放要写清楚。C 返回的指针如果约定「调用方负责释放」，Dart 侧必须 free；如果约定「库内部持有」，就绝不能在 Dart 侧 free。混用是最常见的崩溃来源。

五、结构体、联合体与数组 ​

dart
final class Vec3 extends Struct {
  @Double() external double x;
  @Double() external double y;
  @Double() external double z;
}

final p = calloc<Vec3>(1);
p.ref.x = 1.5;
p.ref.z = 3.5;
print(sizeOf<Vec3>()); // 24
malloc.free(p);

联合体所有字段共享同一块内存：

dart
final class Number extends Union {
  @Int32() external int asInt;
  @Double() external double asDouble;
}

数组有两种形态：Pointer<T> + elementAt(i)，或结构体内嵌 @Array(16) external Array<Double> values;。

结构体布局受对齐影响：int8 后跟 double 时通常有 7 字节填充。字段顺序、@Packed(n)、目标架构 ABI 都会改变 sizeOf；跨语言传递结构体前，务必用 Dart 侧 sizeOf 与 C 侧 sizeof 核对，并按类型宽度与对齐规则推算字段偏移。

六、回调、线程与 NativePort ​

C 库需要在事件发生时通知 Dart，就用 NativeCallable：

dart
final callable = NativeCallable<Int32 Function(Int32)>.isolateLocal(
  (value) => value * 2,
);
native_register(callable.nativeFunction);
callable.close(); // 不再需要时关闭
  • isolateLocal：在调用线程上同步执行 Dart 代码，简单但会阻塞原生线程。
  • listener：把调用转成消息投递到创建它的 isolate，适合 native 线程通知 Dart，返回值受限。
  • 原生线程向 Dart 发消息也可用 NativePort，配合 C 侧 Dart_PostCObject。

FFI 调用发生在当前 isolate 的线程上，耗时 C 函数应放到 worker isolate 调用。动态库在整个进程内共享，多个 isolate 都能调用同一份符号。

回调里不要做重活

isolateLocal 回调运行在原生线程上，耗时操作会拖住 C 库自己的线程；listener 回调虽然回到 isolate，但高频调用会淹没事件队列。回调只做转交，重活丢给队列或 worker。

七、ffigen、崩溃排查与选型 ​

ffigen 读取头文件生成 Dart 绑定：

yaml
name: native_bindings
output: 'lib/src/native_bindings.dart'
headers:
  entry-points: ['native/include/image.h']
bash
dart run ffigen --config ffigen.yaml

生成代码包含 Struct 子类、lookup 封装与注释，适合把几十个函数的手写绑定交给工具。崩溃排查思路：

  • 用 lldb / Android Studio native debugger 拿栈；Android 用 ndk-stack -sym 还原符号
  • Android NDK 编译加 -fsanitize=address，用 wrap.sh 启动，定位越界与 use-after-free
  • 检查 sizeOf / 对齐、空指针、释放后使用、回调是否在 isolate 销毁后仍被调用

FFI vs Platform Channel：

维度FFIPlatform Channel / Pigeon
调用方式同步直调 C ABI异步消息，需序列化
性能无序列化开销，适合高频/大数据每次过通道有成本
平台支持仅原生（Web 不可用）全平台，含 Web
内存手动管理，易崩Dart/原生各自 GC
开发成本需处理多架构、签名、绑定插件生态成熟
适用复用 C/C++ 库、密集计算调用系统 API、平台能力

选型口诀

「已有成熟 C 库 / 需要低延迟大数据」→ FFI；「调用相机、通知、权限等系统能力」→ Platform Channel / Pigeon。不要为了一个简单系统 API 引入 FFI 的复杂度。

本章示例不引入真实 C 库，而是用纯 Dart 模拟「地址 + 连续槽位 + 固定偏移」的契约，帮助你在不崩溃的前提下理解 FFI 的规则。

可运行示例 ​

DartPad 运行环境将在滚动到此处时加载…
查看完整源码
dart
import 'package:flutter/material.dart';

// 纯 Dart 模拟「指针 + 线性内存」契约，不 import dart:ffi。
void main() => runApp(const _FfiDemo());
const int _base = 0x1000; // 模拟起始地址
const int _size = 8; // 每个槽位 8 字节
class _FfiDemo extends StatefulWidget {
  const _FfiDemo();
  @override
  State<_FfiDemo> createState() => _FfiDemoState();
}

class _FfiDemoState extends State<_FfiDemo> {
  final List<double?> _heap = List<double?>.filled(8, null); // 64B
  int? _p;
  String _log = 'malloc(3) → 写入 → free → 读 x，观察契约如何被打破';

  int? _malloc(int slots) {
    var run = 0;
    for (var i = 0; i < _heap.length; i++) {
      run = _heap[i] == null ? run + 1 : 0;
      if (run == slots) {
        final start = i - slots + 1;
        for (var j = start; j <= i; j++) {
          _heap[j] = 0;
        }
        return _base + start * _size;
      }
    }
    return null; // 堆满：malloc 返回 NULL
  }

  int _index(int addr) {
    final i = (addr - _base) ~/ _size;
    if (i < 0 || i >= _heap.length) {
      throw StateError('越界 0x${addr.toRadixString(16)}');
    }
    if (_heap[i] == null) {
      throw StateError('use-after-free 0x${addr.toRadixString(16)}');
    }
    return i;
  }

  double _read(int addr) => _heap[_index(addr)]!;
  void _write(int addr, double v) => _heap[_index(addr)] = v;
  int get _ptr => _p ?? (throw StateError('p 为 null'));
  void _do(void Function() action) {
    try {
      action();
    } on StateError catch (e) {
      _log = '异常：${e.message}';
    }
    setState(() {});
  }

  void _allocAndWrite() => _do(() {
        _p = _malloc(3);
        _write(_ptr, 1.5); // x @ +0
        _write(_ptr + 8, 2.5); // y @ +8
        _write(_ptr + 16, 3.5); // z @ +16
        _log = 'p = 0x${_ptr.toRadixString(16)}，已写入 x/y/z';
      });

  void _freeAll() => _do(() {
        final start = _index(_ptr);
        for (var j = start; j < start + 3; j++) {
          _heap[j] = null;
        }
        _log = 'free(p)：内存失效，指针仍为 0x${_ptr.toRadixString(16)}';
      });

  void _readX() => _do(() => _log = 'x = ${_read(_ptr)}');
  @override
  Widget build(BuildContext context) => MaterialApp(
        home: Scaffold(
          appBar: AppBar(title: const Text('模拟 FFI 内存契约')),
          body: Padding(
            padding: const EdgeInsets.all(16),
            child: Column(children: [
              const Text('64 字节堆（每格 8 字节）'),
              const SizedBox(height: 8),
              Wrap(spacing: 6, children: [
                for (var i = 0; i < _heap.length; i++)
                  Container(
                    width: 50,
                    padding: const EdgeInsets.symmetric(vertical: 8),
                    color: _heap[i] == null
                        ? Colors.grey.withValues(alpha: 0.25)
                        : Colors.blue.withValues(alpha: 0.25),
                    child: Text(
                        '+${i * 8}\n${_heap[i]?.toStringAsFixed(1) ?? 'free'}',
                        textAlign: TextAlign.center),
                  ),
              ]),
              const SizedBox(height: 12),
              Text('p = ${_p == null ? 'null' : '0x${_p!.toRadixString(16)}'} · Vec3(24B)'),
              const SizedBox(height: 8),
              Wrap(spacing: 8, runSpacing: 8, children: [
                FilledButton(
                    onPressed: _allocAndWrite, child: const Text('malloc + 写入')),
                FilledButton(onPressed: _freeAll, child: const Text('free')),
                OutlinedButton(onPressed: _readX, child: const Text('读 x')),
              ]),
              const SizedBox(height: 12),
              Text(_log),
            ]),
          ),
        ),
      );
}

常见坑 ​

高频踩坑点

  1. 结构体布局与 C 不一致：字段顺序、对齐、packed 任一不同，读到的就是错位数据；用 sizeOf 与 C 侧 sizeof 双向核对。
  2. 释放后继续使用指针：Dart 侧没有悬空指针检查，free 后读字段就是 use-after-free，可能立刻崩溃也可能静默读脏数据。
  3. double free / 交叉释放：C 库返回的指针归属不明确时重复释放，堆直接损坏。
  4. 在 UI isolate 调耗时 C 函数：FFI 调用是同步的，几秒的解码会让界面完全冻结；放到 worker isolate。
  5. 只打包了一个 ABI：armeabi-v7a 设备或 x86_64 模拟器上加载失败，表现为 DynamicLibrary.open 抛异常。
  6. 回调在 isolate/对象销毁后触发：忘了 callable.close()，原生侧仍持有函数指针，进程随机崩溃。

课后练习 ​

  1. 结构体布局：定义 struct { int8 a; double b; int32 c; }，用 sizeOf 打印大小，并解释填充字节来自哪里。
  2. Arena 管理：用 package:ffi 的 Arena 分配 3 个 Vec3，在作用域结束时统一释放，对比手动 free 的代码量。
  3. ffigen 实战：写一个只有 add(int, int) 的 C 头文件，用 ffigen 生成绑定并在桌面端调用。
  4. 回调闭环：用 NativeCallable.listener 模拟「原生线程每秒回调一次」，在 Dart 侧收到 5 次后 close()。
  5. 崩溃定位：故意构造一次越界写，记录崩溃栈，说明如何用 ASan 或 ndk-stack 找到出问题的行。 :::
