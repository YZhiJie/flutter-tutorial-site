手势体系与手势冲突 ​

学习目标 ​

学完本章，你将能够：

  • 描述一次触摸从 PointerEvent 进入、经过 HitTest 命中链、到识别器回调的完整路径
  • 解释 GestureArena 的加入、关闭、清扫规则，判断内层与外层谁先胜出
  • 区分 GestureDetector 各回调的竞争关系（tap / doubleTap / longPress / drag / scale）
  • 用 Listener 与 RawGestureDetector 介入原始事件或装配自定义识别器
  • 用 IgnorePointer、AbsorbPointer、NotificationListener 处理典型冲突
  • 掌握 InteractiveViewer、Draggable / DragTarget、ScrollPhysics 的组合用法

一条主线

触摸 → 反向 HitTest 得到命中路径（由内到外）→ PointerEvent 沿路径派发 → 各识别器进竞技场 → 唯一胜者回调。

一、HitTest：事件先交给谁 ​

Flutter 的指针事件不是浏览器那种「冒泡」模型：先做一次命中测试，得到从最深子节点到根的 HitTestResult 路径，再沿路径从内向外依次派发。

  • RenderBox.hitTest 先判断自己是否命中，再 hitTestChildren，最后 hitTestSelf。
  • hitTestBehavior 决定这一层如何参与：
值含义典型用途
deferToChild只有子节点命中才算命中（默认）普通容器
opaque自己占据的区域全部命中空白背景也要监听点击
translucent自己命中的同时允许后面的兄弟节点也命中悬浮层穿透

PointerDownEvent 派发时，路径上每个 RenderObject 都会收到，GestureDetector 只是往路径上「加一个识别器」，并不中断派发。

透明区域点了没反应

Container 没有 color / decoration 时不命中自己，GestureDetector 的 behavior 默认又是 deferToChild，于是「看不见的区域点不到」。要么加背景色，要么显式写 behavior: HitTestBehavior.opaque。

二、GestureArena：一次触摸只有一个赢家 ​

每个 PointerDownEvent 都会创建一个 GestureArena，命中路径上所有想处理这次触摸的识别器都要 add 进去：

add(member)              识别器入场
close()                  路径收集完毕，不再接受新成员
sweep()                  无人反对时，默认接受「第一个入场」的成员
resolve(accept / reject) 成员主动宣布胜负
hold() / release()       延迟裁决（双击等待第二击）

推导顺序是关键：

  1. 命中路径由内向外，内层识别器先 add；
  2. 若没人主动 accept，sweep 时先入场者胜——嵌套 GestureDetector 默认是内层赢；
  3. 某个识别器满足判定条件后 resolve(accepted)，其余成员全部 reject；
  4. TapGestureRecognizer 要等到抬起才裁决，DoubleTapGestureRecognizer 会 hold 住竞技场等待第二击。

自定义识别器通常继承 OneSequenceGestureRecognizer（只跟踪一次触摸序列），在 addAllowedPointer 里开始跟踪，在 handleEvent 里判断位移或时间后主动裁决：

dart
class _SwipeRightRecognizer extends OneSequenceGestureRecognizer {
  @override
  void addAllowedPointer(PointerDownEvent event) {
    super.addAllowedPointer(event);
    startTrackingPointer(event.pointer);
  }

  @override
  void handleEvent(PointerEvent event) {
    if (event is PointerMoveEvent && event.delta.dx > 12) {
      resolve(GestureDisposition.accepted); // 抢到竞技场
    }
    if (event is PointerUpEvent) {
      resolve(GestureDisposition.rejected);
      stopTrackingPointer(event.pointer);
    }
  }

  @override
  String get debugDescription => 'swipeRight';
}

三、GestureDetector 回调的竞争关系 ​

同一个 GestureDetector 上挂的多个回调，对应不同的识别器，彼此也在竞技场里竞争：

回调识别器判定时机冲突点
onTap / onTapUpTapGestureRecognizer抬起且无明显位移有 onDoubleTap 时要等双击超时
onDoubleTapDoubleTapGestureRecognizer第二击抬起会 hold 竞技场，拖慢单击
onLongPressLongPressGestureRecognizer按住约 500ms期间移动会取消
onHorizontalDrag*HorizontalDragGestureRecognizer横向位移超过 slop与横向 Scrollable 同轴互斥
onVerticalDrag*VerticalDragGestureRecognizer纵向位移超过 slop与纵向 Scrollable 同轴互斥
onPan*PanGestureRecognizer任意方向位移不能与 onScale* 同时使用
onScale*ScaleGestureRecognizer多指或单指位移已包含平移，不必再叠 pan

单击会被双击「拖慢」

同时挂 onTap 与 onDoubleTap 时，单击必须等约 300ms 的双击窗口关闭才触发。列表项要即时反馈就只挂 onTap，双击放到单独入口。

四、Listener 与 RawGestureDetector ​

  • Listener 直接订阅 onPointerDown/Move/Up/Cancel，不参加竞技场，无论谁胜出它都能看到事件。适合「按下高亮」「记录触点」「性能打点」这类不裁决胜负的逻辑。
  • RawGestureDetector 用 GestureRecognizerFactory 手动装配识别器，可以控制构造参数（如 dragStartBehavior）、挂自定义识别器，或精确安排入场顺序：
dart
RawGestureDetector(
  gestures: <Type, GestureRecognizerFactory>{
    _SwipeRightRecognizer:
        GestureRecognizerFactoryWithHandlers<_SwipeRightRecognizer>(
      _SwipeRightRecognizer.new,
      (r) => r.onSwipe = () => debugPrint('向右滑'),
    ),
  },
  child: child,
)

五、四类典型冲突与解法 ​

场景现象原因解法
横向 ListView 里再放横向滑动内层滑不动，或列表跟着滑同轴 HorizontalDrag 互斥内层改纵向手势；或用 RawGestureDetector 明确只让内层参赛
可拖拽列表项 vs 列表滚动项拖不动，或列表滚不动同轴 VerticalDrag 竞争项用 LongPressDraggable；或按位移方向分发
缩放 + 拖拽叠加双指缩放时位置跳变onScale 已含平移只保留 onScaleUpdate，或直接用 InteractiveViewer
双击与单击单击延迟、误触双击 hold 竞技场分离区域；或用 Listener 自己计时

IgnorePointer 与 AbsorbPointer 的差别只在一处：

  • IgnorePointer(ignoring: true)：自己与整棵子树不参与命中，事件继续交给后面的兄弟或父级。
  • AbsorbPointer(absorbing: true)：自己吸收事件，子树收不到，后面的兄弟也收不到。
dart
IgnorePointer(ignoring: _busy, child: child)        // 让手势穿透到下层
AbsorbPointer(absorbing: _loading, child: child)    // 加载遮罩，彻底拦住

六、InteractiveViewer、Draggable 与 DragTarget ​

InteractiveViewer 内置 pan + scale + 边界回弹，外面不要再套 onScale：

dart
InteractiveViewer(
  minScale: 0.8,
  maxScale: 4,
  boundaryMargin: const EdgeInsets.all(32),
  child: const FlutterLogo(size: 240),
)
  • 子节点的 onTap 仍然可用；但子节点里的拖拽会和 pan 竞争，通常要给子区域让出 panEnabled: false；保存/恢复缩放用 TransformationController 并在 dispose 释放。

Draggable 负责「拖出去放到别处」：

dart
Draggable<String>(
  data: 'A',
  feedback: Material(child: Chip(label: Text('A'))),
  childWhenDragging: Opacity(opacity: 0.3, child: child),
  child: child,
)

DragTarget<String>(
  onWillAcceptWithDetails: (d) => d.data == 'A',
  onAcceptWithDetails: (d) => setState(() => _slot = d.data),
  builder: (context, candidate, rejected) => ...,
)
  • 想让「长按后才可拖」用 LongPressDraggable，它天然避开与列表滚动的竞争；feedback 记得包 Material，否则文字没有默认样式。

七、滚动行为与 NotificationListener ​

ScrollPhysics 决定「能不能滚、滚完停在哪」：

Physics行为
BouncingScrollPhysics越界回弹（iOS 风格）
ClampingScrollPhysics到边界夹紧（Android 风格）
NeverScrollableScrollPhysics禁止用户滚动，只能代码控制
PageScrollPhysics停止时吸附整页

NotificationListener<ScrollNotification> 可以在祖先处拦截滚动通知，回调返回 true 表示「已处理，不再向上冒泡」：

dart
NotificationListener<ScrollNotification>(
  onNotification: (n) {
    if (n is OverscrollNotification) return true; // 吃掉越界通知
    return false;
  },
  child: ListView(...),
)

内外层交叉轴（横向列表放纵向列表）各自独立，通常无需处理；只有同轴嵌套才需要 NeverScrollableScrollPhysics 或手势仲裁。

dart
import 'package:flutter/material.dart';

// 手势竞技场实验室：
// ① 内外层都监听点击：内层先入场，sweep 时先入场者胜
// ② 内层同时挂 tap 与 longPress：按住约 500ms，长按胜出、tap 被拒
// ③ 单击与双击共存：单击要等约 300ms 的双击窗口关闭才触发
void main() => runApp(const MaterialApp(home: _ArenaPage()));

class _ArenaPage extends StatefulWidget {
  const _ArenaPage({super.key});

  @override
  State<_ArenaPage> createState() => _ArenaPageState();
}

class _ArenaPageState extends State<_ArenaPage> {
  final Stopwatch _watch = Stopwatch()..start();
  final List<String> _logs = <String>[];
  int _seq = 0;

  void _log(String msg) {
    setState(() {
      _seq++;
      _logs.insert(0, '${_watch.elapsedMilliseconds} ms  #$_seq  $msg');
      if (_logs.length > 6) _logs.removeLast();
    });
  }

  @override
  Widget build(BuildContext context) {
    final scheme = Theme.of(context).colorScheme;
    final small = Theme.of(context).textTheme.bodySmall;
    return Scaffold(
      appBar: AppBar(title: const Text('手势竞技场')),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.fromLTRB(16, 12, 16, 0),
            child: Text(
              '依次尝试：点外层背景、点内层方块、长按内层、快速双击右侧区域，'
              '观察日志里的裁决时刻与胜者。',
              style: small,
            ),
          ),
          Expanded(
            flex: 3,
            child: Listener(
              onPointerDown: (_) => _log('原始 PointerDown：Listener 不参赛'),
              child: GestureDetector(
                behavior: HitTestBehavior.opaque,
                onTap: () => _log('外层 onTap（点内层时会被拒绝）'),
                child: Container(
                  margin: const EdgeInsets.all(12),
                  decoration: BoxDecoration(
                    color: scheme.surfaceContainerHighest,
                    borderRadius: BorderRadius.circular(16),
                  ),
                  child: Center(
                    child: GestureDetector(
                      onTap: () => _log('内层 onTap 胜出：先入场先被 sweep'),
                      onLongPress: () => _log('内层 onLongPress 胜出：tap 被拒绝'),
                      child: Container(
                        width: 170,
                        height: 110,
                        alignment: Alignment.center,
                        decoration: BoxDecoration(
                          color: scheme.primary.withValues(alpha: 0.15),
                          borderRadius: BorderRadius.circular(12),
                        ),
                        child: const Text('内层点击 / 长按区'),
                      ),
                    ),
                  ),
                ),
              ),
            ),
          ),
          Padding(
            padding: const EdgeInsets.symmetric(horizontal: 12),
            child: GestureDetector(
              onTap: () => _log('单击触发（等双击窗口关闭）'),
              onDoubleTap: () => _log('双击胜出，单击被拒绝'),
              child: Container(
                height: 64,
                alignment: Alignment.center,
                decoration: BoxDecoration(
                  color: scheme.secondaryContainer,
                  borderRadius: BorderRadius.circular(12),
                ),
                child: Text('单 / 双击区：快速点两下', style: small),
              ),
            ),
          ),
          Expanded(
            flex: 2,
            child: ListView.builder(
              padding: const EdgeInsets.all(12),
              itemCount: _logs.length,
              itemBuilder: (context, i) => Text(
                _logs[i],
                style: small?.copyWith(fontFamily: 'monospace'),
              ),
            ),
          ),
        ],
      ),
    );
  }
}

常见坑 ​

高频踩坑点

  1. 以为事件会冒泡到父级：命中路径在按下时就固定了，父级只有在这条路径上才收得到；给父级加 GestureDetector 也不会「兜底」空白区域，需要 behavior: opaque。
  2. onPan 与 onScale 同时挂：运行期直接断言失败，二者只能留一个。
  3. 横向列表嵌横向滑动：同轴竞争要么内层永远抢不到，要么列表跟着滑，先确定谁是主手势。
  4. 双击吞掉单击：onTap + onDoubleTap 让单击延迟约 300ms，交互上像「点了没反应」。
  5. 把 IgnorePointer 当遮罩：它让事件穿透，加载中仍能点到下面的按钮；要拦截请用 AbsorbPointer。
  6. TransformationController 忘记 dispose：InteractiveViewer 的状态持有者同样要释放。

课后练习 ​

  1. 竞技场观察：写一个内外两层都挂 onTap 的页面，分别在内外区域点击，用 Listener 打印事件路径，验证「内层先入场、内层胜出」。
  2. 自定义识别器：实现「向右滑超过 40px 才算数」的识别器，与 onTap 放进同一个 RawGestureDetector，观察谁先裁决。
  3. 拖拽列表项：做一个列表，项可长按拖到顶部收藏区（LongPressDraggable + DragTarget），滚动必须保持正常。
