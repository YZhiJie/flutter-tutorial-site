安全加固 ​

学习目标 ​

学完本章，你将能够：

  • 用威胁模型梳理本地存储、网络、逆向、调试四类攻击面
  • 把令牌与密钥放进 Keychain / Keystore，而不是 SharedPreferences 或源码
  • 用证书或公钥 pinning 抵抗中间人攻击，并设计 pin 轮换与失败策略
  • 通过 --dart-define、CI 注入、--obfuscate 让敏感信息与符号不落产物
  • 实现 Root / 越狱与模拟器检测、防截屏等运行时加固，并清楚它们的边界
  • 完成日志脱敏、剪贴板、WebView、深链与隐私合规的检查清单

安全是成本对抗

客户端没有「绝对安全」。目标是把攻击成本抬高到攻击者觉得不划算，同时把真正值钱的东西留在服务端。

一、威胁模型：先列攻击面 ​

攻击面典型手段加固方向
本地存储越狱/root 设备直接读文件、备份、adb backup安全存储、最小化落盘、关闭备份
网络代理抓包、自签证书中间人、DNS 劫持TLS + pinning、请求签名、防重放
逆向反编译 APK、字符串搜索、Hopper / IDA 分析混淆、符号剥离、密钥不落包
调试attach 进程、Frida hook、改内存反调试、完整性校验、服务端风控
三方 SDK / WebViewSDK 上报过度、JS 注入、开放跳转SDK 审计、白名单、CSP 思路
text
资产 → 攻击者想拿什么（账号、支付、内容）→ 从哪进来（存储/网络/进程）→ 花多少成本

威胁模型要对齐业务

支付类 App 值得上 pinning + 完整性校验；一个离线工具类 App 把密钥写死在包里也许可接受。先写清资产与损失，再决定投入，别为了「安全」把包体和故障率一起抬高。

二、安全存储：Keychain 与 Keystore ​

存储位置安全性说明
源码 / 资源文件最低反编译即可见，等同于公开
SharedPreferences / UserDefaults低明文 XML / plist，备份可读
SQLite / 本地文件低未加密时同样可读
Keychain / Keystore高由系统托管、硬件级密钥、可设访问策略
  • iOS：Keychain item 用 kSecAttrAccessibleWhenUnlockedThisDeviceOnly，避免随备份迁移到新设备。
  • Android：Keystore 生成不可导出的 AES 密钥，用它加密偏好或文件；直接调 EncryptedSharedPreferences 或社区封装的 flutter_secure_storage。
  • 记住：Keychain 在卸载重装后可能仍保留，登出时要主动清理。
dart
// 思路示意（真实项目可用 flutter_secure_storage）
final storage = FlutterSecureStorage(
  aOptions: AndroidOptions(encryptedSharedPreferences: true),
  iOptions: IOSOptions(accessibility: KeychainAccessibility.first_unlock),
);
await storage.write(key: 'session_token', value: token);

令牌生命周期也要设计

短期 access token + 可撤销 refresh token，比「一个永不过期的密钥存在本地」安全得多。存储安全只解决「读不到」，撤销能力才解决「已经泄露」。

三、证书固定（Certificate / Public Key Pinning） ​

中间人攻击的前提是客户端信任了攻击者证书。Pinning 把信任范围收窄到「你指定的证书或公钥」：

  • 证书 pin：比对叶子证书的指纹，简单但换证书就得发版。
  • 公钥 pin（推荐）：比对 SPKI 哈希，换证书时只要密钥对不变就无需发版；同时准备备用 pin 应对密钥轮换。

Dart 侧可以在 HttpClient 建连后校验，也可以在 Dio 的拦截器里做 post-handshake 校验（响应到达后再核对本次连接用的证书）：

dart
// 伪代码：哈希实现与证书获取方式依项目而定
final pins = <String>{'sha256/AAAA...', 'sha256/BBBB...'}; // 主 pin + 备用 pin

httpClient.badCertificateCallback = (cert, host, port) {
  return pins.contains(sha256Of(cert.der)); // 只信白名单，绝不 return true
};
  • 失败策略：校验失败直接断开并上报，不要静默降级成「忽略证书错误」。
  • 轮换：至少保留两个 pin（当前 + 下一把），上线前用真实域名验证。
  • 注意 pin 的是服务端证书；CDN、灰度域名、第三方支付域名通常不在范围内，别一刀切。

千万别写成「信任所有证书」

badCertificateCallback = (_, __, ___) => true 是很多教程的「跑通示例」，它等于关闭 TLS 校验，把 pinning 的意义全部抵消。任何绕过校验的分支都必须删除。

四、密钥不落代码 ​

dart
const apiBase = String.fromEnvironment('API_BASE', defaultValue: 'https://api.example.com');
bash
flutter run --dart-define=API_BASE=https://staging.example.com
flutter build apk --release --dart-define-from-file=config/prod.json
  • String.fromEnvironment 是编译期常量，值会进入产物字符串，只适合放非敏感配置（环境地址、开关、渠道号）。
  • 真正的秘密（支付私钥、第三方 secret）不能放客户端：改为服务端签发短期令牌，或用 OAuth PKCE + 设备绑定。
  • CI 用 Secrets 注入，key.properties、*.jks、.env 全部进 .gitignore；提交前用 gitleaks / trufflehog 扫历史。
  • 已经泄露过的密钥要立即轮换，删提交记录不等于失效。

五、混淆与加固 ​

bash
flutter build apk --release --obfuscate --split-debug-info=build/symbols
flutter build appbundle --release --obfuscate --split-debug-info=build/symbols
措施作用注意事项
--obfuscate重命名 Dart 符号，增加逆向阅读成本反射/动态调用可能失效
--split-debug-info符号表外置，减小包体每次发版都要归档，否则堆栈无法还原
Android R8 / ProGuard压缩、混淆 Java/Kotlin 侧保留反射、JSBridge、序列化类
iOS 符号剥离去掉无用符号同步上传 dSYM 到崩溃平台
  • 混淆后崩溃堆栈需要符号表还原：flutter symbolize -i stack.txt -d build/symbols/...。
  • json_serializable 显式写 @JsonKey(name: ...)，避免字段名被混淆后接口对不上。
  • 加固方案（如商业壳）能提高逆向成本，但会带来兼容性与审核风险，需实测启动耗时与崩溃率。

六、运行时加固与数据外泄面 ​

措施平台说明
Root 检测Android检查 su 路径、Magisk、可写系统分区；可用 Play Integrity 做服务端判定
越狱检测iOS检查 Cydia / 可写路径 / 异常 URL Scheme
模拟器检测Android / iOSBuild.FINGERPRINT、机型特征；仅作风控信号
防截屏AndroidFLAG_SECURE，系统级禁止截屏与最近任务预览
截屏/录屏检测iOSUIScreen.isCaptured + 截屏通知，用于提示或遮罩
  • Flutter 侧通过 MethodChannel 调原生开关，成本很低。
  • 检测结果只作为风控信号：客户端判断可被 hook 绕过，真正的拦截放在服务端。
  • 防截屏影响用户体验（无法截图分享），只在敏感页面开启，别全局设置。

剪贴板、日志、WebView 与深链是另一类外泄面：

对象风险做法
剪贴板验证码、密码被其他 App 读取敏感字段不提供「复制」；复制后定时清空
日志token、手机号进 logcat / 崩溃平台统一脱敏函数，release 关闭 debug 日志
WebViewJS 注入、任意 URL 跳转只加载 https 白名单；JavaScriptChannel 只暴露必要方法
深链被构造参数越权跳转scheme/host 白名单，参数校验与登录态确认

脱敏示例（token=abcd1234 → token=ab****34）：

dart
String mask(String value) {
  if (value.length <= 4) return '****';
  return '${value.substring(0, 2)}****${value.substring(value.length - 2)}';
}

WebView 侧：关闭文件访问、禁用 addJavascriptInterface 式的全量桥、校验 NavigationDelegate 的每次跳转；深链在跳转前确认目标页面与登录态，避免「链接一点就转账」。

检查项通过标准
数据最小化只采集业务必需字段，能匿名就不实名

bash

flutter build appbundle --release --obfuscate --split-debug-info=build/symbols

别把「合规」只当成文档

隐私政策写了「不采集」，代码里却初始化了会读取设备标识的 SDK，检测工具一抓就穿帮。清单要落到代码与依赖层。

可运行示例 ​

DartPad 运行环境将在滚动到此处时加载…
查看完整源码
dart
import 'package:flutter/material.dart';

// 安全加固模拟：只演示威胁模型与密钥生命周期，不做真实加密、不联网。
void main() => runApp(const MaterialApp(home: _SecurityPage()));

class _SecurityPage extends StatefulWidget {
  const _SecurityPage({super.key});

  @override
  State<_SecurityPage> createState() => _SecurityPageState();
}

class _SecurityPageState extends State<_SecurityPage> {
  static const String _placeholder = 'sk_demo_51H8xQ2mF7a9K4pZ'; // 占位串
  bool _hardcoded = true, _secureStore = false, _sanitize = true, _pinning = false;
  String? _key;
  final List<String> _timeline = <String>[];

  int get _risk => (_hardcoded ? 35 : 0) + (!_secureStore ? 25 : 0) +
      (!_sanitize ? 20 : 0) + (!_pinning ? 20 : 0);

  String _mask(String v) =>
      v.length <= 6 ? '****' : '${v.substring(0, 5)}****${v.substring(v.length - 3)}';

  void _step(String line) => setState(() {
        _timeline.insert(0, line);
        if (_timeline.length > 8) _timeline.removeLast();
      });

  void _issue() {
    setState(() => _key = _hardcoded
        ? _placeholder
        : 'runtime_${DateTime.now().millisecondsSinceEpoch}');
    _step('签发：${_hardcoded ? '写死在代码里（可被反编译）' : '运行时注入'}');
    _step('存储：${_secureStore ? 'Keychain / Keystore' : 'SharedPreferences 明文'}');
  }

  void _use() {
    final key = _key;
    if (key == null) {
      _step('没有可用密钥，先签发');
      return;
    }
    _step('使用：Bearer ${_sanitize ? _mask(key) : key}');
  }

  void _revoke() {
    if (_key == null) {
      _step('密钥已为空');
      return;
    }
    setState(() => _key = null);
    _step('销毁：内存引用置空 + 服务端吊销');
  }

  Widget _toggle(String label, bool value, ValueChanged<bool> onChanged) =>
      SwitchListTile(
        dense: true,
        contentPadding: EdgeInsets.zero,
        title: Text(label, style: const TextStyle(fontSize: 13)),
        value: value,
        onChanged: onChanged,
      );

  @override
  Widget build(BuildContext context) {
    final scheme = Theme.of(context).colorScheme;
    return Scaffold(
      appBar: AppBar(title: const Text('安全加固模拟')),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Text('风险分 $_risk / 100（仅模拟，不涉及真实加密）',
                style: const TextStyle(fontWeight: FontWeight.bold)),
            const SizedBox(height: 6),
            LinearProgressIndicator(
              value: _risk / 100,
              color: Color.lerp(Colors.green, Colors.red, _risk / 100),
              backgroundColor: scheme.surfaceContainerHighest,
            ),
            _toggle('密钥写死在代码（--dart-define 也会进产物）', _hardcoded,
                (v) => setState(() => _hardcoded = v)),
            _toggle('使用 Keychain / Keystore', _secureStore,
                (v) => setState(() => _secureStore = v)),
            _toggle('日志脱敏', _sanitize, (v) => setState(() => _sanitize = v)),
            _toggle('证书 pinning', _pinning, (v) => setState(() => _pinning = v)),
            Wrap(spacing: 8, children: [
              FilledButton(onPressed: _issue, child: const Text('签发')),
              OutlinedButton(onPressed: _use, child: const Text('使用')),
              TextButton(onPressed: _revoke, child: const Text('销毁')),
            ]),
            const Divider(),
            Expanded(
              child: ListView.builder(
                itemCount: _timeline.length,
                itemBuilder: (context, i) => Text(
                  '· ${_timeline[i]}',
                  style: const TextStyle(fontFamily: 'monospace', fontSize: 12),
                ),
              ),
            ),
          ],
        ),
      ),
    );
  }
}

常见坑 ​

高频踩坑点

  1. 把 API secret 写进 Dart 常量：反编译即可见，--dart-define 也一样进产物，只能放非敏感配置。
  2. badCertificateCallback 永远返回 true：等于关闭 TLS 校验，pinning 与 HTTPS 全部失效。
  3. 混淆后没存符号表：线上崩溃堆栈全是 A.B，无法定位；--split-debug-info 的目录必须按版本归档。
  4. 只做客户端 Root 检测就放行：hook 一下就能绕过，风控决策必须在服务端。
  5. 日志里打印完整响应体：token、手机号、身份证号进崩溃平台，等于把数据送出去。
  6. 全局开 FLAG_SECURE：用户无法截图，反馈与分享场景直接受损，应按页面开启。

课后练习 ​

  1. 威胁建模：给你的练习 App 画一张资产—攻击面表，为每一项写出「攻击成本」与「对应加固」，并标注哪些不做。
  2. 安全存储改造：把本地登录态从 SharedPreferences 迁到 Keychain / Keystore，验证卸载重装后的行为差异。
  3. Pinning 实验：用 Charles / mitmproxy 抓自己的包，先不加 pinning 观察成功，再加公钥 pin 观察失败与上报路径。
  4. 混淆验证：用 --obfuscate --split-debug-info 构建，搜索产物中的类名与字符串，再用 flutter symbolize 还原一次堆栈。
  5. 脱敏审计：全局搜索 print / debugPrint / 日志封装，列出所有可能输出 PII 的位置并补上脱敏。
