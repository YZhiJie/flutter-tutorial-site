一、多窗口：三种做法与 engine 边界 ​

桌面应用做「多窗口」时，先选架构，不要先选组件库：

方案实现成本适用
单窗口内多面板用 Stack / Docking / 分割布局模拟最低，状态共享最简单伪多窗口，用户不需要真正并行看两个屏
多顶级窗口、单 engine平台原生窗口 + 共享 Flutter engine中，需要原生窗口管理工具类应用，窗口间强共享状态
多顶级窗口、多 enginedesktop_multi_window：每个窗口独立 Flutter engine最高，内存 / 启动成本翻倍需要真正独立窗口、独立生命周期、独立渲染

desktop_multi_window 的关键事实：每个窗口是独立 engine，不共享 Dart 内存。因此：

  • 不要假设全局单例、static 缓存、ChangeNotifier 能跨窗口；
  • 共享状态必须走消息（invokeMethod）、本地存储（shared_preferences / 数据库）或服务端；
  • 每个窗口都要自己初始化插件、自己处理生命周期；
  • 子窗口崩溃不会带走主窗口，但主窗口退出通常带走全部窗口。

最小创建流程：

dart
final WindowController controller = await WindowController.create(
  WindowConfiguration(
    arguments: jsonEncode(<String, Object>{'title': '子窗口 #1'}),
  ),
);
await controller.show();

父窗口注册方法处理器，接收子窗口消息：

dart
final WindowController self = await WindowController.fromCurrentEngine();
await self.setWindowMethodHandler((MethodCall call) async {
  if (call.method == 'window_from_child') {
    final int delta = (call.arguments as Map)['delta'] as int;
    // 更新父窗口状态
    return null;
  }
  throw MissingPluginException('未实现 ${call.method}');
});

子窗口反过来通过 WindowController.getAll() 找到其他窗口并 invokeMethod。这就是本工程「子窗口 +1 回传主窗、主窗广播到所有子窗」的实现方式。

常见误区

  • 把窗口当组件：窗口有独立 engine，BuildContext、InheritedWidget、路由栈都不共享。
  • 靠内存同步：主窗口改了变量，子窗口不会自动刷新，必须显式发消息。
  • 无限开窗：每个窗口都有 isolate、渲染线程与 GPU 资源开销，要限制数量并复用。
  • 子窗口重复初始化：在子窗口入口里也要 windowManager.ensureInitialized()，不要假设主窗口做过。

二、窗口状态持久化、多显示器与缩放 ​

2.1 启动时序 ​

window_manager 的标准启动顺序：

dart
await windowManager.ensureInitialized();
await windowManager.waitUntilReadyToShow(
  const WindowOptions(size: Size(960, 640), center: true),
  () async {
    await windowManager.show();
    await windowManager.focus();
  },
);

waitUntilReadyToShow 的意义是：在窗口真正显示前完成尺寸、位置与标题设置，避免用户看到「先默认大小、再跳变」。

2.2 状态恢复与保存 ​

需要持久化的最小集合：

  • 窗口宽高；
  • 窗口左上角坐标；
  • 是否最大化；
  • （可选）是否全屏、所在显示器、窗口不透明度。

本工程的 WindowStateService 做了三件事：

  1. 启动时从 shared_preferences 读回尺寸 / 位置 / 最大化；
  2. 监听 onWindowResize、onWindowMove、onWindowMaximize，用 300ms debounce 合并高频事件；
  3. 关闭时再强制保存一次，避免最后一次拖动丢失。

为什么要 debounce

拖动窗口时 resize / move 事件非常密集。每次事件都写磁盘会造成 I/O 抖动，也会让平台侧频繁同步。合并到 300ms 一次足够。

2.3 多显示器与 DPI 缩放 ​

  • 坐标是逻辑像素还是物理像素，各平台不同；窗口恢复时要检查目标坐标是否还在当前显示器范围内。
  • 用户可能拔掉外接屏：恢复前用 screen_retriever（或平台 API）枚举显示器，坐标越界时回退到主屏居中。
  • Windows 每个显示器可设置不同缩放（125% / 150%），跨屏拖动时窗口逻辑尺寸不变但物理像素变化；不要缓存物理像素值。
  • macOS 的 Retina backing scale 由系统处理，Flutter 的逻辑像素已经归一化，一般不需要手动乘 2。
  • 图片、图标要提供多倍率资源；桌面端也要检查 MediaQuery.devicePixelRatio 与文字缩放。

3.1 托盘 ​

dart
trayManager.addListener(this);
await trayManager.setIcon('assets/tray/tray_icon.png', isTemplate: true);
await trayManager.setToolTip('企业级实验工程');
await trayManager.setContextMenu(Menu(items: <MenuItem>[
  MenuItem(key: 'show', label: '显示主窗口'),
  MenuItem(key: 'hide', label: '隐藏主窗口'),
  MenuItem.separator(),
  MenuItem(key: 'quit', label: '退出'),
]));

要点：

  • 托盘菜单的点击回调在 Dart 侧处理，但菜单渲染由平台完成；
  • 关闭主窗口不等于退出进程：常见交互是「关闭窗口 → 隐藏到托盘」，托盘菜单里再提供「退出」；
  • macOS 的模板图标（isTemplate: true）会随系统深浅色自动反色，普通彩色图标不会；
  • 托盘图标资源必须注册到 pubspec.yaml 的 assets，否则打包后可能读不到。

3.2 全局快捷键 ​

dart
final HotKey hotKey = HotKey(
  identifier: 'app.toggle-main-window',
  key: LogicalKeyboardKey.space,
  modifiers: <HotKeyModifier>[HotKeyModifier.meta, HotKeyModifier.shift],
  scope: HotKeyScope.system,
);
await hotkeyManager.register(hotKey, keyDownHandler: (_) => toggleWindow());
  • HotKeyScope.system 才是全局；HotKeyScope.inapp 只在本应用聚焦时生效。
  • macOS 首次注册全局快捷键可能需要在「系统设置 → 隐私与安全性 → 辅助功能」授权。
  • 注册前最好提供快捷键设置页并检测冲突；注册失败要给出可读原因，不能静默。
  • 应用退出前 unregister，避免残留占用。

3.3 文件关联、拖放与最近文件 ​

这三项是「Flutter 能接住事件，但注册与系统 UI 必须原生」的典型：

  • 文件关联：macOS 在 Info.plist 声明支持的 UTI / 扩展名，并在 AppDelegate 处理 application:openURLs:；Windows 写注册表或在安装器中声明 ProgId。Flutter 侧通常通过 MethodChannel 接收路径。
  • 拖放：desktop_drop 把原生拖拽事件转成 Dart 回调；沙盒应用需要用户授权访问文件。
  • 最近文件：macOS 由 NSDocumentController 维护；Windows 需要 Jump List / SHAddToRecentDocs。Flutter 侧通常只能读列表，写入需要原生。

验收标准

文件关联不能只看「双击能打开」，还要验证：冷启动、应用已运行、多个文件、文件被移动 / 删除、路径含中文与空格。

四、自动更新：Sparkle / WinSparkle / Squirrel 的真实流程 ​

4.1 完整链路 ​

一个可靠的桌面自动更新至少包含：

  1. 发现：定时或启动时请求 appcast / manifest；
  2. 比较：语义化版本比较，处理预发布版本与 build 号；
  3. 准入：最低支持版本、操作系统版本、CPU 架构、渠道（stable / beta）；
  4. 完整性：下载后校验 SHA-256 与签名（macOS EdDSA，Windows Authenticode）；
  5. 安装：替换应用、处理权限、重启或提示重启；
  6. 回滚：新版本启动失败时回到上一版本；
  7. 灰度：按用户 / 设备 / 比例分批放量，出问题立即停量。

4.2 平台方案对照 ​

平台常用方案签名备注
macOSSparkle 2EdDSA（sign_update）+ Apple 公证appcast.xml、dmg / zip、SUFeedURL
WindowsWinSparkle / Squirrel.WindowsAuthenticode（EV 证书更稳）安装器、静默更新、UAC
LinuxAppImageUpdate / 包管理器无统一强制签名发行版仓库、Flatpak / Snap 各自更新

iOS / Android 走各自应用商店更新，不需要自建这套流程；桌面端才需要。

4.3 本工程 mock 到哪一步 ​

labs/enterprise_app 只实现了可运行的检查流程：

  • assets/update/manifest.json 是本地清单；
  • UpdateService 解析清单、比较版本、判断强制更新（低于 minSupportedVersion）；
  • 页面展示「有新版本 / 已是最新 / 清单非法 / 强制更新」；
  • 「模拟下载」只是进度条，不下载文件、不校验签名、不安装。

不包含：网络请求、appcast 签名、差量包、安装器权限、回滚、灰度。文档与页面文案都明确标注了这一点。

4.4 差量与回滚 ​

  • 差量更新：只下发新旧版本差异（bsdiff / zstd patch），适合大安装包；代价是服务端要为每个版本组合生成补丁，且校验更复杂。
  • 回滚：保留上一版本完整包；新版本启动时写入「启动成功」标记，连续崩溃则下次启动回退。
  • 灰度：服务端按比例 / 渠道 / 设备下发不同 appcast，出问题先停量而不是等用户反馈。
  • 强制更新：当协议或服务端接口不兼容时，用 minSupportedVersion 拦截旧版本，但必须给出明确提示与退出路径。

五、分发、签名与公证 ​

5.1 macOS ​

  • 打包：flutter build macos --release，再用 create-dmg / hdiutil 制作 dmg；或打 pkg 走安装器。
  • 签名：codesign --deep --force --options runtime --sign "Developer ID Application: ..." App.app，Hardened Runtime 必须开启。
  • 公证：xcrun notarytool submit App.dmg --keychain-profile ... --wait，成功后 xcrun stapler staple App.dmg。
  • 常见失败：entitlements 缺失、内嵌 framework 未签名、使用了不允许的私有 API、dmg 内符号链接不规范。
  • 没有证书时：只能本机运行；分发会触发 Gatekeeper 拦截。本工程不提供证书与公证脚本。

5.2 Windows ​

  • 打包：WiX 生成 msi，或 Inno Setup 生成 exe；Squirrel 也可生成安装器。
  • 签名：signtool sign /fd sha256 /tr ... /td sha256 App.exe，安装器与主程序都要签。
  • 注意：EV 证书可减少 SmartScreen 警告；证书过期会让已发布版本也显示未知发布者。
  • 自动更新：WinSparkle 读取 appcast，下载后校验签名并调用安装器；UAC 提权与静默安装要提前设计。

5.3 Linux ​

  • AppImage：单文件分发，配合 AppImageUpdate 做增量更新；没有统一签名体系。
  • Flatpak / Snap：由运行时负责更新，应用不自己检查。
  • deb / rpm：交给包管理器，避免应用内更新与系统包管理冲突。
  • 注意：glibc 版本、图形驱动、Wayland / X11 差异要在 CI 矩阵里覆盖。

5.4 发布检查清单 ​

  • [ ] 版本号在 pubspec.yaml、安装器、appcast、关于页一致
  • [ ] macOS 已签名、已公证、已 staple，Gatekeeper 冷启动通过
  • [ ] Windows 主程序与安装器均已 Authenticode 签名
  • [ ] 自动更新清单的下载地址、SHA-256、签名可验证
  • [ ] 旧版本可检测到新版本，新版本可回滚
  • [ ] 卸载残留、用户数据迁移、权限提示都有验证
  • [ ] 多显示器、缩放 125% / 150%、深浅色、无托盘环境都跑过

  int trayClicks = 0;

  String updateMessage = '尚未检查更新';
  double progress = 0;
  bool downloaded = false;
  Timer? timer;

  @override
  void dispose() {
    timer?.cancel();
    super.dispose();
  }

  void log(String message) {
    logs.insert(0, message);
    if (logs.length > 10) logs.removeLast();
  }

  void toggleWindow(String source) {
    setState(() {
      windowVisible = !windowVisible;
      if (source == '快捷键') hotkeyHits++;
      log('$source：${windowVisible ? '显示' : '隐藏'}主窗口');
    });
  }

  KeyEventResult handleKey(FocusNode node, KeyEvent event) {
    if (event is! KeyDownEvent) return KeyEventResult.ignored;
    final HardwareKeyboard keyboard = HardwareKeyboard.instance;
    final bool modifier = keyboard.isMetaPressed || keyboard.isControlPressed;
    if (event.logicalKey == LogicalKeyboardKey.space &&
        modifier &&
        keyboard.isShiftPressed) {
      toggleWindow('快捷键');
      return KeyEventResult.handled;
    }
    return KeyEventResult.ignored;
  }

  void checkUpdate() {
    setState(() {
      updateMessage = '正在检查更新…';
      progress = 0;
      downloaded = false;
    });
    timer?.cancel();
    timer = Timer(const Duration(milliseconds: 600), () {
      if (!mounted) return;
      final bool newer = isNewer(remoteVersion, currentVersion);
      setState(() {
        updateMessage = newer
            ? '发现新版本 $remoteVersion（48.2 MB）'
            : '已是最新版本 $currentVersion';
        log(updateMessage);
      });
    });
  }

  void download() {
    if (downloaded) return;
    timer?.cancel();
    timer = Timer.periodic(const Duration(milliseconds: 150), (Timer t) {
      if (!mounted) {
        t.cancel();
        return;
      }
      setState(() => progress = (progress + 0.1).clamp(0, 1));
      if (progress >= 1) {
        t.cancel();
        setState(() {
          downloaded = true;
          updateMessage = '下载完成（模拟）：真实实现还会校验签名并安装';
        });
      }
    });
  }

  @override
  Widget build(BuildContext context) {
    return Focus(
      autofocus: true,
      onKeyEvent: handleKey,
      child: Scaffold(
        appBar: AppBar(title: const Text('42 · 桌面深度机制演示')),
        body: ListView(
          padding: const EdgeInsets.all(16),
          children: <Widget>[
            Card(
              child: Padding(
                padding: const EdgeInsets.all(16),
                child: Column(
                  crossAxisAlignment: CrossAxisAlignment.start,
                  children: <Widget>[
                    const Text('模拟桌面与系统托盘'),
                    const SizedBox(height: 8),
                    Container(
                      height: 150,
                      alignment: Alignment.center,
                      decoration: BoxDecoration(
                        color: Theme.of(context).colorScheme.surfaceContainerHighest,
                        borderRadius: BorderRadius.circular(10),
                      ),
                      child: AnimatedOpacity(
                        duration: const Duration(milliseconds: 200),
                        opacity: windowVisible ? 1 : 0,
                        child: const Card(
                          child: Padding(
                            padding: EdgeInsets.all(20),
                            child: Text('主窗口 · Cmd / Ctrl + Shift + Space 唤起'),
                          ),
                        ),
                      ),
                    ),
                    const SizedBox(height: 8),
                    Wrap(
                      spacing: 8,
                      runSpacing: 8,
                      children: <Widget>[
                        Chip(label: Text('快捷键 $hotkeyHits 次')),
                        PopupMenuButton<String>(
                          onOpened: () {
                            setState(() => trayClicks++);
                            log('打开托盘菜单');
                          },
                          onSelected: (String value) {
                            if (value == 'toggle') {
                              toggleWindow('托盘');
                            } else {
                              setState(() => log('退出（模拟）'));
                            }
                          },
                          itemBuilder: (_) => const <PopupMenuEntry<String>>[
                            PopupMenuItem<String>(
                              value: 'toggle',
                              child: Text('显示 / 隐藏窗口'),
                            ),
                            PopupMenuDivider(),
                            PopupMenuItem<String>(
                              value: 'quit',
                              child: Text('退出（模拟）'),
                            ),
                          ],
                          child: Chip(label: Text('托盘菜单 · $trayClicks 次')),
                        ),
                      ],
                    ),
                    Text(
                      '真实托盘点一下图标才弹出菜单；这里用 PopupMenuButton 近似。',
                      style: Theme.of(context).textTheme.bodySmall,
                    ),
                  ],
                ),
              ),
            ),
            const SizedBox(height: 12),
            Card(
              child: Padding(
                padding: const EdgeInsets.all(16),
                child: Column(
                  crossAxisAlignment: CrossAxisAlignment.start,
                  children: <Widget>[
                    const Text('更新检查（安装为 mock）'),
                    const SizedBox(height: 8),
                    Text('当前 $currentVersion · 远端 $remoteVersion'),
                    Text(updateMessage),
                    const SizedBox(height: 8),
                    LinearProgressIndicator(value: progress),
                    Text('进度 ${(progress * 100).toStringAsFixed(0)}%'),
                    const SizedBox(height: 8),
                    Wrap(
                      spacing: 8,
                      children: <Widget>[
                        FilledButton(
                          onPressed: checkUpdate,
                          child: const Text('检查更新'),
                        ),
                        OutlinedButton(
                          onPressed: downloaded ? null : download,
                          child: const Text('模拟下载'),
                        ),
                      ],
                    ),
                  ],
                ),
              ),
            ),
            const SizedBox(height: 12),
            const Text('操作日志'),
            for (final String line in logs)
              Text('· $line', style: Theme.of(context).textTheme.bodySmall),
          ],
        ),
      ),
    );
  }
}

bool isNewer(String remote, String current) {
  final List<int>? a = parseVersion(remote);
  final List<int>? b = parseVersion(current);
  if (a == null || b == null) return false;
  for (int i = 0; i < 3; i++) {
    if (a[i] != b[i]) return a[i] > b[i];
  }
  return false;
}

List<int>? parseVersion(String raw) {
  final RegExpMatch? match =
      RegExp(r'^(\d+)\.(\d+)\.(\d+)').firstMatch(raw.trim());
  if (match == null) return null;
  return <int>[
    int.parse(match.group(1)!),
    int.parse(match.group(2)!),
    int.parse(match.group(3)!),
  ];
}

常见坑 ​

高频踩坑点

  1. 把多窗口当多面板：需要共享内存时却用了多 engine，最后靠消息拼状态，复杂度失控。
  2. 窗口显示前就设置尺寸：没有 waitUntilReadyToShow，用户会看到尺寸跳变。
  3. 拖动时高频写磁盘：没有 debounce，窗口卡顿且寿命缩短。
  4. 只保存尺寸不保存位置：多显示器拔插后窗口出现在屏幕外。
  5. 把物理像素当逻辑像素：跨不同缩放显示器时窗口大小错误。
  6. 关闭窗口就退出进程：托盘应用应隐藏而不是退出，否则托盘失去意义。
  7. 托盘图标未注册 assets：Debug 能跑，Release 读不到图。
  8. 全局快捷键不检测冲突：与其他应用抢占，注册静默失败。
  9. macOS 未做公证：用户双击提示「无法验证开发者」，转化率暴跌。
  10. Windows 只签主程序不签安装器：SmartScreen 仍然拦截。
  11. 自动更新没有签名校验：下载通道被劫持即可投毒。
  12. 强制更新没有退出路径：用户被卡死在提示页。
  13. 差量更新没有回滚：补丁失败后应用无法启动。
  14. Web 直接 import 桌面插件：dart:io 进入 Web 编译，构建失败。
  15. 在 CI 里假设有 GUI：多窗口、托盘、快捷键需要真实桌面会话，CI 只能跑静态分析与纯逻辑单测。

课后练习 ​

  1. 给 WindowStateService 增加「记住上次所在显示器」，拔掉外接屏后自动回到主屏。
  2. 给子窗口增加「关闭前询问是否保存」，并把结果回传主窗口。
  3. 把广播改成带 event 与 payload 的通用消息总线，支持至少 3 种事件。
  4. 实现「只允许一个子窗口」的单例模式：再次创建时聚焦已有窗口。
  5. 给托盘菜单增加「开机自启」勾选项，调研 macOS 与 Windows 各自的实现方式。
  6. 用 MethodChannel 实现一个真实的「打开文件」入口，并接收系统传入的路径。
  7. 给更新检查增加渠道（stable / beta）与架构（arm64 / x64）过滤。
  8. 设计一份 appcast 签名校验流程，写出需要哪些密钥与步骤（不必真实实现）。
  9. 写一个「更新失败回滚」的状态机，并用单元测试覆盖连续崩溃场景。
  10. 在 CI 中只跑纯逻辑测试与 flutter analyze，把 GUI 验证写成手工清单并说明原因。
