47 · 国际化工程化 ​

学习目标 ​

学完本章，你将能够：

  • 用 ARB + gen-l10n 建立单一文案数据源，并把「缺失 / 多余 key、占位符不一致」接进 CI
  • 用伪本地化在真实翻译到位前发现写死字符串、布局截断与文字膨胀问题
  • 设计「模板 ARB → 翻译平台 → 回填 → 生成 → 校验」的完整流水线
  • 正确处理双向文本、复数类别与性别选择，而不是把句子拼起来
  • 用 intl 统一数字、日期、货币与单位格式，并说清货币符号与货币代码的区别
  • 规划字体子集、按需语言包与 fallback，控制包体积与首屏下载量
  • 组织运行时语言切换、状态保持与多语言测试矩阵

与第 33 章的边界

33 · 无障碍与国际化适配 讲的是单页面怎么多语言、怎么读屏；本章讲的是多语言怎么在工程里持续运转：ARB 治理、CI 校验、翻译回填、字体子集、伪本地化与运行时切换。两章不重复基础 Widget 用法。

一、ARB 是单一数据源，生成代码只是产物 ​

Flutter 官方推荐用 ARB（Application Resource Bundle，本质是 JSON）描述文案。一个最小工程：

yaml
# l10n.yaml
arb-dir: lib/l10n/arb
template-arb-file: app_en.arb
output-localization-file: app_localizations.dart
output-class: AppLocalizations
output-dir: lib/l10n/generated
nullable-getter: false
json
{
  "@@locale": "en",
  "greeting": "Hello, {name}",
  "@greeting": {
    "description": "Greeting with the current user name",
    "placeholders": {
      "name": { "type": "String", "example": "Ada" }
    }
  },
  "inboxSummary": "{count, plural, =0{No messages} =1{One message} other{{count} messages}}",
  "@inboxSummary": {
    "placeholders": { "count": { "type": "int" } }
  }
}
bash
flutter gen-l10n          # 由 l10n.yaml 生成 AppLocalizations
flutter analyze           # 生成物参与静态检查

三个原则：

  1. 只改 ARB，不改生成物。生成目录可以提交，也可以构建时生成，但绝不手工编辑。
  2. 模板语言必须完整。app_en.arb 是 key 与占位符的基准，其他语言向它对齐。
  3. 每条文案带 description 与 example。翻译人员看不到代码，上下文只能靠这两项。

1.1 把校验接进 CI ​

gen-l10n 会检查 ARB 语法，但不会检查「中文少了三个 key」这类问题。需要自己补一层审计：

dart
class ArbIssue {
  const ArbIssue(this.type, this.locale, this.key, this.detail);
  final String type;
  final String locale;
  final String key;
  final String detail;
}

审计至少覆盖四类问题：

问题典型原因后果
缺失 key新增文案只加了模板语言运行时回退，用户看到英文
多余 key删除文案时漏删某语言翻译平台持续产生无效工单
占位符不一致译员改了 {name} 的拼写运行时占位符不替换或直接崩溃
ICU 括号不配对复数 / select 手改坏了gen-l10n 报错或生成错误分支

本章实验工程把审计做成纯函数，页面与 CLI 共用同一套逻辑：

bash
cd labs/enterprise_app
dart tool/check_arb.dart
# ARB 审计：en, zh, ar · 12 个 key
# 通过：所有语言 key 与占位符一致。

CI 里只要这一步退出码非 0 就阻断合并。不要依赖运行时 fallback 兜底：fallback 是用户体验的最后一道缝，不是质量门禁。

1.2 生成物与 Flutter 版本 ​

  • flutter_localizations 必须来自 SDK，不要从 pub 装；
  • intl 版本要跟 flutter_localizations 的约束一致（本章固定 0.20.3）；
  • 升级 Flutter 后重新 flutter gen-l10n，把生成物 diff 一起提交，避免「本地能跑、CI 生成结果不同」。

二、伪本地化：在翻译之前先压测布局 ​

伪本地化（pseudo-localization）把字符串做三件事：

  1. 把拉丁字母替换成带重音的字符，暴露「界面里写死了英文」；
  2. 用 ⟦ ⟧ 包裹，暴露「拼接出来的文案」；
  3. 补长 30%～40%，暴露「按钮 / 卡片 / 单行文本被截断」。
dart
String pseudo(String input, {double expansion = 0.3}) {
  final buffer = StringBuffer('⟦');
  for (final ch in input.split('')) {
    buffer.write(_accent[ch] ?? ch);
  }
  final pad = (input.length * expansion).ceil();
  buffer
    ..write(List.filled(pad, '·').join())
    ..write('⟧');
  return buffer.toString();
}

落地方式有两种：

方式做法优点代价
构建期由脚本从模板 ARB 生成 app_en_XA.arb全应用生效，接近真实语言包要维护生成脚本与 ICU 解析
运行时在文本出口统一包一层 transform开关灵活，适合实验与回归容易漏掉绕过框架的字符串

伪本地化不是翻译

它只验证布局与硬编码，不验证语义。上线前必须回到真实语言包。

三、翻译平台对接与回填流程 ​

推荐把 ARB 当成「源文件」，翻译平台当成「协作层」：

模板 ARB（en）
   │  导出 key + description + example
   ▼
翻译平台（TMS）
   │  翻译、审校、术语库、翻译记忆
   ▼
各语言 ARB（zh / ar / …）
   │  flutter gen-l10n
   ▼
生成代码 + CI 审计 + 回归

工程要点：

  • key 用语义命名，如 checkout_payment_failed，不要用 text_1；
  • description 写使用场景，例如「结算页支付失败提示，按钮下方，最多两行」；
  • 冻结窗口：发版前 N 天只允许修 bug 文案，不再新增 key；
  • 回填只覆盖非模板语言，模板语言由开发维护；
  • 术语表与翻译记忆要跟着产品走，否则同一句「保存」会出现三种译法；
  • 禁止译员修改占位符名与 ICU 结构，平台侧应把这两类内容设为只读；
  • 每次回填跑一次审计，把缺失 key 数量作为发版指标。

四、双向文本、复数与性别 ​

4.1 双向文本（Bidi） ​

阿拉伯语、希伯来语是 RTL。Flutter 的方向来自 Directionality，而 MaterialApp 在接入 flutter_localizations 后会随 locale 自动给出正确方向。

常见坑不是「整体不翻转」，而是局部混排：

  • 英文品牌名、URL、版本号、时间在 RTL 段落里顺序错乱；
  • 数字与标点相邻时，括号、冒号跑到错误一侧；
  • 用字符串拼接把两种方向的内容粘在一起。

处理方式：

  • 让框架决定方向，不要到处写 textDirection: TextDirection.rtl；
  • 对混排片段使用 Unicode 隔离符：\u2066（LRI）、\u2069（PDI）；
  • 图标、返回箭头用 Icons.arrow_back 等方向无关资源，或按 Directionality 镜像；
  • 需要镜像的图片在 MatchTextDirection 或 Transform.flip 中处理。

4.2 复数类别 ​

CLDR 的复数规则因语言而异：

语言类别
英文one / other
中文other（不区分单复数）
阿拉伯语zero / one / two / few / many / other

所以「1 条消息 / 3 条消息」不能靠 count == 1 ? ... : ... 手写，必须交给 ICU：

json
"inboxSummary": "{count, plural, zero{لا رسائل} one{رسالة واحدة} two{رسالتان} few{{count} رسائل} many{{count} رسالة} other{{count} رسالة}}"

gen-l10n 会生成 Intl.pluralLogic，并把类别映射到当前 locale。测试时至少覆盖 0 / 1 / 2 / 3 / 11 / 100。

4.3 性别与 select ​

性别、称谓、敬语用 select：

json
"profileUpdate": "{gender, select, female{She} male{He} other{They}} updated the profile"

不要用「先生 / 女士」拼字符串，也不要把「她/他/TA」拆成独立词再拼接——语序不同的语言会立刻露馅。

五、数字、日期、货币与单位 ​

手写格式化是国际化里最常见的技术债。统一交给 intl：

dart
final price = NumberFormat.currency(locale: 'ar', symbol: 'د.إ').format(1288.5);
final compact = NumberFormat.compact(locale: 'zh').format(1288000); // 129万
final distance = NumberFormat.decimalPatternDigits(
  locale: 'zh',
  decimalDigits: 1,
).format(12.5);
类型正确做法常见错误
数字NumberFormat + locale手写 toStringAsFixed、自己加千分位
货币金额 + 货币代码（CNY / USD）+ 符号由 locale 决定把 ¥ 写死给所有语言
日期DateFormat 或 MaterialLocalizationsyyyy-MM-dd 硬编码给所有用户
单位按 locale 做单位换算与文案只翻译单位名，不换数值
百分比NumberFormat.percentPattern自己拼 % 并假设在数字后面

货币符号 ≠ 货币代码

$ 可能是 USD / CAD / AUD；¥ 可能是 CNY / JPY。金额展示用符号，结算与日志必须带 ISO 4217 代码。

日期格式化在纯 Dart 环境需要先初始化 locale 数据：

dart
import 'package:intl/date_symbol_data_local.dart';

await initializeDateFormatting('zh');
final date = DateFormat.yMMMMd('zh').format(DateTime(2026, 11, 5));

在 Flutter 里接入 flutter_localizations 后，MaterialLocalizations.formatFullDate 已经能给出 locale 正确的日期，不必自己初始化全部数据。

六、字体子集与按需语言包 ​

一个完整的中文字体动辄 10 MB 以上，阿拉伯语字体也不小。字体往往比代码更占包体积。

三个层次：

  1. 子集化：构建期只保留产品用到的字符集（常用 3500 字、数字、标点），用 pyftsubset 等工具产出小字体；
  2. 按需语言包：首次启动只加载当前语言 + 拉丁回退，切换语言时再下载；
  3. 缓存与淘汰：语言包按语言维度缓存，设置容量上限，避免用户切遍所有语言后存储膨胀。
dart
class LocalePack {
  const LocalePack({
    required this.code,
    required this.fontBytes,
    required this.glyphCount,
    required this.latinFallback,
  });
  final String code;
  final int fontBytes;
  final int glyphCount;
  final bool latinFallback;
}

规划逻辑比数据更重要：

  • 当前语言不是拉丁语系时，回退链需要额外加载 en；
  • 缓存命中不产生网络流量，但占用磁盘；
  • emoji、生僻字、少数民族文字可能不在任何子集内，必须显式走系统字体回退；
  • 语言包下载失败时，先展示已缓存语言 + 提示，不要白屏。

七、fallback 策略 ​

框架的解析顺序大致是：

精确 locale（zh-Hant-HK）
  → 同语言变体（zh-Hant）
  → 同语言（zh）
  → 模板语言（en）
  → 原始 key（绝不建议展示给用户）

工程上要区分两种 fallback：

类型场景策略
文案 fallback某语言某 key 缺失回退模板语言，同时上报埋点
字体 fallback字形不在子集内回退系统字体，记录缺失字形
功能 fallback语言包加载失败使用已缓存语言，提示可重试

CI 应该把「文案 fallback」压到 0；运行时 fallback 只处理线上突发情况。

八、运行时切换与测试 ​

8.1 切换 ​

可运行示例 ​

下面的脚本不依赖 intl，用最小实现演示「复数类别 → 文案选择 → 数字格式化 → 伪本地化 → 缺失 key 审计」这条链路，可直接运行观察输出。

DartPad 运行环境将在滚动到此处时加载…
查看完整源码
dart
/// 国际化工程化最小实验：复数类别、性别选择、数字格式、伪本地化、key 审计。
///
/// 纯 Dart，无第三方依赖；可直接运行观察输出。
void main() {
  const List<String> locales = <String>['en', 'zh', 'ar'];

  for (final String locale in locales) {
    print('=== $locale ===');
    print(_plural(locale, 0));
    print(_plural(locale, 1));
    print(_plural(locale, 2));
    print(_plural(locale, 11));
    print(_selectGender(locale, 'female'));
    print(_selectGender(locale, 'other'));
    print('currency: ${_currency(locale, 1288.5)}');
    print('compact: ${_group(1288000, locale)}');
    print('pseudo: ${_pseudo(_greeting(locale, 'Ada'))}');
  }

  print('=== 审计 ===');
  final List<Map<String, String>> audits = <Map<String, String>>[
    <String, String>{'en': 'greeting', 'zh': 'greeting', 'ar': 'greeting'},
    <String, String>{'en': 'greeting, inbox', 'zh': 'greeting', 'ar': 'inbox'},
  ];
  for (final Map<String, String> arbs in audits) {
    print(_audit(arbs));
  }
}

String _plural(String locale, int count) {
  final String category = _category(locale, count);
  final Map<String, String> forms = <String, Map<String, String>>{
    'en': <String, String>{
      'zero': 'No messages',
      'one': 'One message',
      'other': '$count messages',
    },
    'zh': <String, String>{
      'zero': '没有消息',
      'one': '1 条消息',
      'other': '$count 条消息',
    },
    'ar': <String, String>{
      'zero': 'لا رسائل',
      'one': 'رسالة واحدة',
      'two': 'رسالتان',
      'few': '$count رسائل',
      'many': '$count رسالة',
      'other': '$count رسالة',
    },
  }[locale]!;
  return '[${locale.padRight(2)}] $category → ${forms[category] ?? forms['other']}';
}

String _category(String locale, int count) {
  if (locale == 'zh') return count == 0 ? 'zero' : 'other';
  if (locale == 'ar') {
    if (count == 0) return 'zero';
    if (count == 1) return 'one';
    if (count == 2) return 'two';
    if (count % 100 >= 3 && count % 100 <= 10) return 'few';
    if (count % 100 >= 11 && count % 100 <= 99) return 'many';
    return 'other';
  }
  return count == 1 ? 'one' : 'other';
}

String _selectGender(String locale, String gender) {
  final Map<String, Map<String, String>> words =
      <String, Map<String, String>>{
    'en': <String, String>{
      'female': 'She',
      'male': 'He',
      'other': 'They',
    },
    'zh': <String, String>{
      'female': '她',
      'male': '他',
      'other': 'TA',
    },
    'ar': <String, String>{
      'female': 'قامت',
      'male': 'قام',
      'other': 'قاموا',
    },
  };
  return '[${locale.padRight(2)}] $gender → ${words[locale]![gender]} updated the profile';
}

String _greeting(String locale, String name) {
  final Map<String, String> templates = <String, String>{
    'en': 'Hello, {name}',
    'zh': '你好，{name}',
    'ar': 'مرحبًا، {name}',
  };
  return templates[locale]!.replaceFirst('{name}', name);
}

String _currency(String locale, double amount) {
  final String formatted = _group(amount, locale);
  switch (locale) {
    case 'zh':
      return '¥$formatted';
    case 'ar':
      return '$formatted د.إ';
    default:
      return '\$$formatted';
  }
}

String _group(double value, String locale) {
  final String fixed = value.toStringAsFixed(value == value.roundToDouble() ? 0 : 2);
  final List<String> parts = fixed.split('.');
  final StringBuffer grouped = StringBuffer();
  for (int i = 0; i < parts.first.length; i++) {
    if (i > 0 && (parts.first.length - i) % 3 == 0) {
      grouped.write(locale == 'ar' ? '٬' : ',');
    }
    grouped.write(parts.first[i]);
  }
  final String result = parts.length > 1
      ? '${grouped.toString()}${locale == 'ar' ? '٫' : '.'}${parts[1]}'
      : grouped.toString();
  return locale == 'ar' ? _arabicDigits(result) : result;
}

String _arabicDigits(String input) {
  const String western = '0123456789';
  const String arabic = '٠١٢٣٤٥٦٧٨٩';
  final StringBuffer buffer = StringBuffer();
  for (final String ch in input.split('')) {
    final int index = western.indexOf(ch);
    buffer.write(index >= 0 ? arabic[index] : ch);
  }
  return buffer.toString();
}

String _pseudo(String input) {
  const Map<String, String> accents = <String, String>{
    'a': 'á', 'b': 'ƀ', 'c': 'ç', 'd': 'ð', 'e': 'é', 'f': 'ƒ',
    'g': 'ĝ', 'h': 'ĥ', 'i': 'í', 'j': 'ĵ', 'k': 'ķ', 'l': 'ļ',
    'm': 'ɱ', 'n': 'ñ', 'o': 'ó', 'p': 'þ', 'q': 'զ', 'r': 'ŕ',
    's': 'š', 't': 'ţ', 'u': 'ú', 'v': 'ṽ', 'w': 'ŵ', 'x': 'ẋ',
    'y': 'ý', 'z': 'ž',
  };
  final StringBuffer buffer = StringBuffer('⟦');
  for (final String ch in input.split('')) {
    buffer.write(accents[ch] ?? ch);
  }
  final int pad = (input.length * 0.3).ceil();
  buffer
    ..write(List<String>.filled(pad, '·').join())
    ..write('⟧');
  return buffer.toString();
}

String _audit(Map<String, String> arbs) {
  final Set<String> template =
      arbs['en']!.split(',').map((String s) => s.trim()).toSet();
  final List<String> issues = <String>[];
  for (final String locale in arbs.keys) {
    if (locale == 'en') continue;
    final Set<String> keys =
        arbs[locale]!.split(',').map((String s) => s.trim()).toSet();
    for (final String key in template.difference(keys)) {
      issues.add('$locale 缺失 $key');
    }
    for (final String key in keys.difference(template)) {
      issues.add('$locale 多余 $key');
    }
  }
  return issues.isEmpty ? '通过：key 一致' : issues.join('；');
}

常见坑 ​

  1. 只改生成代码：下次 gen-l10n 全部覆盖，白改。
  2. 模板 ARB 缺 key：其他语言无从对齐，审计也失去基准。
  3. 占位符被翻译：{name} 变成 {名前}，运行时不替换。
  4. 手写复数：阿拉伯语有 6 个类别，count == 1 远远不够。
  5. 拼接句子：「你好，」+ 名字 + 「！」在日语 / 韩语语序下会错。
  6. 手写千分位：印度语系的数字分组不是三位。
  7. 货币符号当代码：$ 无法区分 USD / CAD / AUD。
  8. 日期格式硬编码：yyyy-MM-dd 不是所有地区的习惯。
  9. RTL 到处写死：局部写 TextDirection.rtl 会破坏框架的方向传播。
  10. 混排不加隔离：英文品牌名在阿拉伯语段落中顺序错乱。
  11. 忘记镜像图标：返回箭头在 RTL 下仍指向左。
  12. 字体全量打包：CJK 字体让包体积翻倍。
  13. 子集漏字：用户输入生僻字后显示豆腐块。
  14. emoji 没有回退：子集字体不含 emoji，需要系统字体兜底。
  15. 语言包下载失败白屏：应先使用缓存语言并提示重试。
  16. 测试只跑英文：RTL、复数、货币全都没覆盖。
