48 · 安全实战 ​

学习目标 ​

学完本章，你将能够：

  • 用 --obfuscate + --split-debug-info 保护 Dart 符号，并配合 R8 / ProGuard 收缩原生代码
  • 把密钥放进 Keychain / Keystore，并用抽象接口隔离存储实现，杜绝硬编码与明文配置
  • 设计设备完整性信号的分级策略，知道检测能被怎么绕过、什么必须交给服务端
  • 实现 SPKI 证书固定、备用 pin 与轮换窗口，避免「换证书即全量断网」
  • 写对 iOS ATS 与 Android network_security_config
  • 用最小授权、签名、防重放与导航白名单把 WebView / JS Bridge 关进笼子
  • 在日志与埋点出口统一脱敏，而不是在调用点手写
  • 从 pubspec.lock 生成 SBOM，把依赖供应链审计接进 CI

与第 32 章的边界

32 · 安全加固 讲的是威胁模型与自查清单：有哪些攻击面、上线前该问哪些问题。本章讲的是落地实现：每一条怎么写成能跑、能测、能进 CI 的代码。两章不重复威胁建模。

一、构建期：混淆与原生收缩 ​

Dart 的 --obfuscate 做两件事：把类名 / 方法名 / 文件名替换成短标识，并保留一张映射表供你还原堆栈。

bash
flutter build apk --release \
  --obfuscate \
  --split-debug-info=build/symbols/android
flutter build ipa --release \
  --obfuscate \
  --split-debug-info=build/symbols/ios

要点：

  1. --split-debug-info 必须配。不开它，混淆后的崩溃堆栈几乎无法定位；把它和版本号一起归档，线上崩溃用对应版本符号还原。
  2. 混淆不是加密。常量、字符串、协议路径、硬编码 URL 仍然可见；真正的秘密不能进产物。
  3. 反射 / 序列化要验证。依赖 runtimeType 字符串、按名字查方法、动态 fromJson key 的代码，混淆后可能失效，必须用 release 包回归。
  4. Web 平台不适用。--obfuscate 只对 AOT 产物（Android / iOS / 桌面）生效，Web 走的是另一套压缩流程。

原生侧（Android）默认开启 R8，需要显式确认：

gradle
android {
  buildTypes {
    release {
      minifyEnabled true
      shrinkResources true
      proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'),
                    'proguard-rules.pro'
    }
  }
}

proguard-rules.pro 里至少保留反射入口、Bridge / Channel 名字、序列化模型：

proguard
-keep class com.example.app.bridge.** { *; }
-keep class com.example.app.model.** { *; }
-keepattributes *Annotation*, Signature

iOS 侧由 Xcode 在 Archive 时 strip 符号；Bitcode 已废弃，不要再找开关。最终检查：对 release 包执行 strings / apktool，确认没有明文域名白名单、测试账号、内网地址。

二、密钥与凭据：只走系统安全存储 ​

硬编码的三个常见变体，全都不安全：

  • 源码常量：const apiKey = "sk_live_..."；
  • --dart-define：值会编进产物，strings 就能捞出来；
  • 明文配置文件：assets/config.json 随包分发，改包即可替换。

正确做法是把存储抽象成接口，让业务代码不关心平台：

dart
abstract interface class SecretStore {
  Future<void> write(String key, String value, {Duration? ttl});
  Future<String?> read(String key);
  Future<void> delete(String key);
  Future<List<String>> keys();
}
  • iOS 实现落 Keychain：kSecClassGenericPassword + kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly，需要生物识别时加 SecAccessControl；
  • Android 实现落 Keystore：生成不可导出的 AES key，用 EncryptedSharedPreferences 或自写 Cipher 加密后再落盘；
  • 实验工程里的 MemorySecretStore 只是可测试替身，进程退出即丢，不可用于生产。

配套策略：

策略做法
最短 TTL会话 token 写明过期时间，读取时过期即删
只存必要密码、支付凭证不落客户端；refresh token 也尽量交给服务端
掩码展示日志、设置页只显示 abcd****xyz
CI 扫描源码 / 配置命中 sk_、BEGIN PRIVATE KEY 直接失败

三、设备完整性：检测是输入，不是判决 ​

常见信号与权重（实验工程用的分级模型）：

信号权重来源
debugger35调试端口、ptrace、sysctl
emulator25传感器缺失、Build 指纹、文件特征
rooted / jailbroken40su 路径、Magisk、越狱文件、可写系统分区
developerMode10系统设置
hooked45Frida / Xposed / Substrate 端口与内存特征
signatureMismatch50重打包签名比对

判定分三档：trusted 放行、risky 降级（隐藏敏感入口、要求二次验证）、compromised 阻断（停止支付 / 凭据读写并上报）。

必须接受的现实：

  1. 所有本地检测都能被绕过。Frida 可以 hook 掉判断函数，Magisk 可以隐藏 root，改包可以去掉检测代码。
  2. 不要用单一信号封号。误报会伤到真用户，尤其是开发机、模拟器测试账号。
  3. 把关键决策交给服务端。Play Integrity / App Attest 的证明在服务端验签，客户端只负责取 token。
  4. 对抗成本要算账。加壳、反调试、完整性自校验会带来崩溃率与维护成本，按业务价值取舍。

四、证书固定：pin 公钥，不 pin 整张证书 ​

生产推荐 pin SPKI（Subject Public Key Info）的 SHA-256，而不是整张叶子证书：

  • 叶子证书 90 天一轮换，pin 整张会导致频繁发版；
  • pin SPKI 可以在证书续期时保持不变（同一密钥对）；
  • 中间 CA 的 SPKI 也可以作为一层兜底。
dart
import 'dart:convert';
import 'package:crypto/crypto.dart';

String spkiPin(List<int> spkiDer) =>
    base64.encode(sha256.convert(spkiDer).bytes);

判定与轮换模型：

dart
class PinSet {
  const PinSet({
    required this.host,
    required this.primaryPins,
    this.backupPins = const <String>{},
    this.expiresAt,
  });
  final String host;
  final Set<String> primaryPins;
  final Set<String> backupPins;
  final DateTime? expiresAt;
}
  • 命中主 pin → 放行；
  • 命中备用 pin → 放行，但标记「应尽快切换主 pin」；
  • 都不命中 → 拒绝连接；
  • expiresAt 过期 → 直接拒绝，强制完成轮换。

轮换流程（提前 30～60 天）：

  1. 新证书密钥对生成后，先把新 pin 作为备用 pin 随版本下发；
  2. 观察一段时间，确认灰度用户都用上了含备用 pin 的版本；
  3. 服务端切换证书；
  4. 下一个版本把新 pin 升为主 pin，旧 pin 转为备用；
  5. 再下一个版本移除旧 pin。

注意：pin 失败时不要静默降级成不校验。要么按策略阻断，要么上报后由服务端下发开关，绝不能在客户端「失败就放行」。

五、网络安全配置：ATS 与 network_security_config ​

iOS 的 ATS 默认禁止明文 HTTP。最小配置是保持默认：

xml
<!-- ios/Runner/Info.plist：不要加 NSAllowsArbitraryLoads -->

必须放开某个域名时，只做例外，不要全局放开：

xml
<key>NSAppTransportSecurity</key>
<dict>
  <key>NSExceptionDomains</key>
  <dict>
    <key>legacy.example.com</key>
    <dict>
      <key>NSExceptionAllowsInsecureHTTPLoads</key>
      <true/>
    </dict>
  </dict>
</dict>

Android 用 network_security_config.xml，默认拒绝明文并配置 pin：

xml
<!-- android/app/src/main/res/xml/network_security_config.xml -->
<network-security-config>
  <base-config cleartextTrafficPermitted="false" />
  <domain-config>
    <domain includeSubdomains="true">app.example.com</domain>
    <pin-set>
      <pin digest="SHA-256">base64(SPKI)</pin>
      <pin digest="SHA-256">base64(备用 SPKI)</pin>
    </pin-set>
  </domain-config>
</network-security-config>
xml
<!-- AndroidManifest.xml -->
<application
  android:networkSecurityConfig="@xml/network_security_config"
  android:usesCleartextTraffic="false" />

注意：network_security_config 的 <pin-set> 只对部分网络栈生效，OkHttp / Cronet 需要各自配置；Flutter 默认 dart:io 的 HttpClient 不会读取 Android pin 配置，所以真正的 pin 校验要在 Dart 层或原生拦截器里做。

六、WebView 隔离与 JS Bridge ​

四条底线：

  1. 最小授权：为每个 Bridge 方法标注所需 scope，页面只拿到当前业务需要的 scope；
  2. 消息校验：方法必须注册、payload 有体积上限、字段按 schema 校验；
  3. 完整性：HMAC 覆盖 method|nonce|timestamp|payload，时间窗 ±60 s，nonce 去重防重放；
  4. 导航白名单：只允许明确的 scheme / host / path 前缀，禁止 file://、javascript: 与未知域名。
dart
String sign(String method, String nonce, DateTime ts, String payload) {
  final material = '$method|$nonce|${ts.millisecondsSinceEpoch}|$payload';
  return Hmac(sha256, secret).convert(utf8.encode(material)).toString();
}

签名比较要用常量时间实现，避免逐字节提前返回泄露信息：

dart
bool constantTimeEquals(String a, String b) {
  if (a.length != b.length) return false;
  var diff = 0;
  for (var i = 0; i < a.length; i++) {
    diff |= a.codeUnitAt(i) ^ b.codeUnitAt(i);
  }
  return diff == 0;
}

WebView 侧还应：

  • 只加载 HTTPS，关闭 setAllowFileAccess / setAllowFileAccessFromFileURLs / setAllowUniversalAccessFromFileURLs；
  • 不需要 JS 的页面直接关掉 JavaScript；
  • 拦截 shouldOverrideUrlLoading，白名单之外一律拒绝或交给系统浏览器；
  • 注入桥时使用受限命名空间，不要暴露 window.App = { ... } 这种全量对象；
  • 页面侧加 CSP，防止被注入脚本后直接调用桥。

七、日志与埋点脱敏 ​

脱敏应在统一出口做一次，而不是每个 log() 前手写：

dart
class Redactor {
  const Redactor._();

  static final List<RedactionRule> defaultRules = <RedactionRule>[
    // 规则顺序：更具体的格式先匹配（18 位身份证先于 11 位手机号）
    // ...
  ];

  static RedactionResult redact(String input, {Set<String> disabledRules = const {}}) {
    // 逐条替换，并统计每条规则命中次数
  }
}

三类规则：

类型例子处理
凭据Bearer ...、sk_live_...、私钥块整段替换为占位符
个人信息邮箱、手机号、身份证、IP替换或按字段阻断上报
业务敏感订单号、余额、地址按字段策略，不靠正则

两个容易忽略的点：

  1. 顺序敏感：身份证号里可能包含 11 位手机号模式，先替换身份证才不会截断；
  2. 结构化字段优先：埋点里的手机号应在上报前就按字段类型剔除，正则只作为兜底。

还要给脱敏写测试：故意关掉某条规则，断言敏感值会漏出——这样规则被误删时 CI 会失败。

八、供应链审计与 SBOM ​

两个动作：

  1. 锁定并审计版本：pubspec.lock 入库，CI 用 flutter pub get --enforce-lockfile；
  2. 生成 SBOM：把依赖清单交给 Dependency-Track / OWASP DC 做漏洞匹配。

实验工程的脚本直接解析 pubspec.lock，输出 CycloneDX 1.5 JSON：

bash
cd labs/enterprise_app
dart tool/generate_sbom.dart
# 写入 build/sbom.cdx.json

关键字段：purl（pkg:pub/name@version）、直接 / 传递依赖标记、来源（hosted / git / path）。CI 里把 SBOM 作为构建产物归档，版本升级时对比新增组件。

审查重点：

  • 新增依赖是否必要，维护状态与最近发布时间；
  • 是否有 git / path 来源的依赖（难以审计、可能指向可变分支）；
  • 传递依赖里是否出现已知漏洞版本；
  • 许可证是否与分发方式兼容。

可运行示例 ​

下面的脚本不依赖第三方包，演示脱敏、导航白名单、Bridge 授权、pin 判定与完整性分级这条链路，可直接运行观察输出。

dart
/// 安全落地机制最小实验：日志脱敏、导航白名单、Bridge 授权、完整性分级。
///
/// 纯 Dart，无第三方依赖；直接运行观察输出。
/// 证书 pin 这里用 FNV-1a 代替 SHA-256，只为演示「比对 + 轮换」的判定逻辑；
/// 生产必须用 `package:crypto` 的 SHA-256 / HMAC。
void main() {
  print('=== 1. 日志脱敏 ===');
  const String raw =
      'Authorization: Bearer demo.token\n'
      'mail=ada@example.com phone=13800138000 ip=203.0.113.7';
  final Redaction redaction = Redaction.defaults();
  print(redaction.apply(raw).text);

  print('\n=== 2. 导航白名单 ===');
  for (final String url in <String>[
    'https://app.example.com/home',
    'https://app.example.com/admin',
    'https://evil.example.com/home',
    'file:///etc/passwd',
  ]) {
    final Allowed decision = allowNavigation(url);
    print('$url -> ${decision.allowed ? '允许' : '拒绝'}（${decision.reason}）');
  }

  print('\n=== 3. Bridge 授权 ===');
  const Map<String, String> methodScopes = <String, String>{
    'getUserProfile': 'profile:read',
    'saveSettings': 'settings:write',
  };
  for (final String method in <String>['getUserProfile', 'saveSettings', 'deleteAccount']) {
    final Allowed decision = authorizeBridge(
      method: method,
      grantedScopes: const <String>{'profile:read'},
      payloadBytes: 512,
      maxPayloadBytes: 4096,
      methodScopes: methodScopes,
    );
    print('$method -> ${decision.allowed ? '允许' : '拒绝'}（${decision.reason}）');
  }

  print('\n=== 4. 证书 pin 与轮换 ===');
  final String primary = fnv1a('cert-current');
  final String backup = fnv1a('cert-rotated');
  for (final String presented in <String>['cert-current', 'cert-rotated', 'cert-rogue']) {
    print('$presented -> ${verifyPin(primary, backup, presented)}');
  }
  print('剩余 10 天，是否进入轮换窗口：${shouldRotate(10)}');
  print('剩余 40 天，是否进入轮换窗口：${shouldRotate(40)}');

  print('\n=== 5. 完整性分级 ===');
  for (final Set<String> signals in <Set<String>>[
    <String>{},
    <String>{'debugger'},
    <String>{'rooted', 'hooked', 'debugger'},
  ]) {
    print('$signals -> ${assessIntegrity(signals)}');
  }
}

class RedactionRule {
  const RedactionRule(this.name, this.pattern, this.replacement);

  final String name;
  final RegExp pattern;
  final String replacement;
}

class RedactionResult {
  const RedactionResult(this.text, this.hits);

  final String text;
  final List<String> hits;
}

class Redaction {
  const Redaction(this.rules);

  final List<RedactionRule> rules;

  factory Redaction.defaults() => Redaction(<RedactionRule>[
        RedactionRule(
          'bearerToken',
          RegExp(r'Bearer\s+[A-Za-z0-9._~+/=-]+', caseSensitive: false),
          'Bearer [TOKEN]',
        ),
        RedactionRule(
          'email',
          RegExp(r'[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}'),
          '[EMAIL]',
        ),
        RedactionRule(
          'idCard',
          RegExp(r'\d{17}[\dXx]'),
          '[ID]',
        ),
        RedactionRule(
          'phone',
          RegExp(r'1[3-9]\d{9}'),
          '[PHONE]',
        ),
        RedactionRule(
          'ipv4',
          RegExp(r'(?<!\d)(?:\d{1,3}\.){3}\d{1,3}(?!\d)'),
          '[IP]',
        ),
      ]);

  RedactionResult apply(String input) {
    String output = input;
    final List<String> hits = <String>[];
    for (final RedactionRule rule in rules) {
      final int count = rule.pattern.allMatches(output).length;
      if (count == 0) continue;
      output = output.replaceAll(rule.pattern, rule.replacement);
      hits.add('${rule.name}×$count');
    }
    return RedactionResult(output, hits);
  }
}

class Allowed {
  const Allowed(this.allowed, this.reason);

  final bool allowed;
  final String reason;
}

Allowed allowNavigation(String url) {
  final Uri? uri = Uri.tryParse(url);
  if (uri == null || !uri.hasScheme) {
    return const Allowed(false, 'URL 无法解析');
  }
  if (uri.scheme != 'https') return Allowed(false, 'scheme ${uri.scheme} 不在白名单');
  if (!<String>{'app.example.com', 'cdn.example.com'}.contains(uri.host)) {
    return Allowed(false, 'host ${uri.host} 不在白名单');
  }
  for (final String prefix in <String>['/logout', '/admin']) {
    if (uri.path.startsWith(prefix)) {
      return Allowed(false, 'path ${uri.path} 命中禁止前缀 $prefix');
    }
  }
  return const Allowed(true, '命中导航白名单');
}

Allowed authorizeBridge({
  required String method,
  required Set<String> grantedScopes,
  required int payloadBytes,
  required int maxPayloadBytes,
  required Map<String, String> methodScopes,
}) {
  final String? requiredScope = methodScopes[method];
  if (requiredScope == null) return const Allowed(false, '方法未注册');
  if (!grantedScopes.contains(requiredScope)) {
    return Allowed(false, '缺少 scope $requiredScope');
  }
  if (payloadBytes > maxPayloadBytes) {
    return const Allowed(false, 'payload 超过体积上限');
  }
  return const Allowed(true, '通过授权');
}

String fnv1a(String input) {
  int hash = 0x811c9dc5;
  for (int i = 0; i < input.length; i++) {
    hash ^= input.codeUnitAt(i);
    hash = (hash * 0x01000193) & 0xFFFFFFFF;
  }
  return hash.toRadixString(16).padLeft(8, '0');
}

String verifyPin(String primary, String backup, String presented) {
  final String digest = fnv1a(presented);
  if (digest == primary) return 'ok（命中主 pin）';
  if (digest == backup) return 'backupUsed（命中备用 pin，应尽快轮换）';
  return 'mismatch（拒绝连接）';
}

bool shouldRotate(int daysLeft, {int leadDays = 30}) => daysLeft < leadDays;

String assessIntegrity(Set<String> signals) {
  const Map<String, int> weights = <String, int>{
    'debugger': 35,
    'emulator': 25,
    'rooted': 40,
    'jailbroken': 40,
    'developerMode': 10,
    'hooked': 45,
    'signatureMismatch': 50,
  };
  final int score = signals.fold<int>(
    0,
    (int sum, String signal) => sum + (weights[signal] ?? 0),
  );
  if (score >= 50) return 'compromised（score $score，阻断敏感能力）';
  if (score >= 25) return 'risky（score $score，降级并二次验证）';
  return 'trusted（score $score，放行）';
}

常见坑 ​

  1. 只开混淆不存符号：线上崩溃堆栈全是 a.b(c)，无法定位。
  2. 以为混淆能藏密钥：常量与字符串仍可被 strings 提取。
  3. --dart-define 当保险箱：值同样进产物。
  4. token 写 SharedPreferences：root / 越狱设备可直接读。
  5. 把完整性检测当封号依据：误报伤真实用户，且检测可被 hook。
  6. pin 整张叶子证书：证书续期即全量断网。
  7. 没有备用 pin：轮换窗口内新旧版本混跑，必然有一批用户连不上。
  8. pin 失败静默放行：等于没做。
  9. Android 配了 pin 就以为 Dart 请求也生效：dart:io 不读该配置。
  10. ATS 全局 NSAllowsArbitraryLoads：上架审核风险，且打开所有明文。
  11. WebView 允许 file://：本地文件与桥接口同时暴露。
  12. Bridge 不校验 nonce：抓包重放即可重复执行敏感操作。
  13. 签名比较用 == 提前返回：时序侧信道。
  14. 脱敏规则顺序错：身份证被手机号规则截断。
  15. 埋点直接上报原始参数：脱敏只做在日志侧，埋点侧漏光。
  16. SBOM 只在发版时生成：漏洞爆发时无法快速定位影响版本。
