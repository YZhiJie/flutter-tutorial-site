49 · 端侧 AI 实战 ​

学习目标 ​

学完本章，你将能够：

  • 说清端侧 AI 的完整链路：训练与转换在服务端 / 工具链，Flutter 端只做推理与调度
  • 在 TFLite 与 ONNX Runtime 之间做出有理由的选型，并知道各自的产物格式
  • 理解 int8 / float16 量化对精度、体积和速度的影响，能判断何时不该量化
  • 配置 NNAPI / CoreML / GPU delegate，并知道 delegate 失败时的回退路径
  • 保证预处理 / 后处理的数值一致性，避免「模型没问题但结果全错」
  • 用 Isolate 把推理移出主线程，控制首帧、内存峰值与并发
  • 设计模型热更新：版本比较、签名校验、灰度与回滚
  • 对功耗与发热建立预算，避免后台推理把设备烤热

与第 34 章的边界

34 · 端侧 AI 与 Flutter GPU 讲的是可行性与技术选型：端侧 AI 能做什么、方案怎么选。本章讲落地实现：转换链路、量化、delegate、调度、热更新怎么写。

一、链路：谁训练、谁转换、谁推理 ​

┌────────────────────────────── 服务端 / CI ──────────────────────────────┐
│  PyTorch / TensorFlow 训练 → 导出 ONNX → TFLite Converter              │
│                              → 训练后量化（int8 / float16）             │
│                              → 签名 + 版本清单 + 灰度发布               │
└──────────────────────────────────────┬──────────────────────────────────┘
                                       │ 下载 / 随包内置
┌──────────────────────────────────────▼──────────────────────────────────┐
│ Flutter 端：加载 .tflite → 预处理 → delegate 推理 → 后处理 → 业务      │
│ 训练、量化、图优化都不在端上发生                                        │
└─────────────────────────────────────────────────────────────────────────┘

记住三条边界：

  1. Flutter 不训练模型。端侧只有前向计算，没有反向传播、没有优化器。
  2. 量化在转换工具链里做。TFLite Converter 需要校准数据集，产出已经量化的 .tflite。
  3. 端侧只负责调度。加载、预热、输入组装、delegate 选择、并发控制、结果解析。

二、运行时选型：TFLite 还是 ONNX Runtime ​

维度tflite_flutteronnxruntime
产物.tflite，TFLite Converter 直出.onnx，跨框架通用
平台覆盖Android / iOS / 桌面；Web 支持有限Android / iOS / 桌面 / Web 较完整
硬件加速NNAPI、CoreML、GPU delegate、XNNPACKNNAPI、CoreML、XNNPACK、QNN 等
生态Google 移动端主推，算子针对移动优化训练框架中立，模型来源更广
维护状态更新频率一般，需关注 issue官方维护活跃，版本跟随 ONNX Runtime

选型建议：

  • 模型来自 TensorFlow / Keras，或需要 NNAPI / CoreML 开箱即用 → TFLite；
  • 模型来自 PyTorch 且同一份 ONNX 还要给服务端 / 其他端复用 → ONNX Runtime；
  • 需要 Web 端也跑 → 优先 ONNX Runtime Web 或 TFLite Web 的 WASM 后端，并单独验证。

本章的可运行示例不引入任一依赖：仓库里没有可离线获取的模型文件，示例用生成权重演示推理与量化逻辑；真实接入路径在文档中给出。

三、量化：int8 与 float16 的取舍 ​

精度权重体积精度损失速度适用
float324 B / 权重基准基准精度敏感、模型很小
float162 B / 权重很小（约 1e-3 量级）多数设备小幅提升通用折中，GPU delegate 友好
int81 B / 权重 + scale取决于校准质量明显提升（整数算子）移动端主力，视觉 / 语音常见

关键事实：

  • int8 不一定更快。算子不支持整数内核时会回退到 float32，甚至多一次反量化；
  • per-channel 量化比 per-tensor 精度好，卷积层应优先；
  • 校准集要覆盖真实分布。用训练集的一小撮做校准，线上长尾输入可能崩；
  • 端到端精度要验。分类 top-1、检测 mAP、语音 WER，都要在量化前后对比；
  • 量化误差可以测。实验工程里 maxAbsError 就是权重级的直接度量。
dart
// 实验工程的核心思路：量化 → 反量化回 double → 复用同一套前向
final double scale = maxAbs / 127.0;
final List<int> q = [for (final w in weights) (w / scale).round().clamp(-127, 127)];
final List<double> dequantized = [for (final v in q) v * scale];

四、Delegate 与硬件加速 ​

平台Delegate注意
AndroidNNAPI机型差异大，部分算子不支持会整图回退；需按机型灰度
Android / iOSGPU delegate首次初始化慢，适合长驻模型；小模型可能不如 CPU
iOSCoreML delegate需要模型转换时开启相应选项；版本兼容要验证
全平台XNNPACK（CPU）默认兜底，稳定但功耗高

工程做法：

  1. 启动时探测 delegate 可用性，不可用就回退 CPU，不要把失败暴露成崩溃；
  2. delegate 与模型版本绑定，换模型要重新跑兼容性测试；
  3. 首次推理包含 delegate 初始化，必须预热，否则首帧时间不可信；
  4. 线程数显式配置，默认值在大核 / 小核调度上表现不一。

// 真实 API 形态（需 tflite_flutter）
final Interpreter interpreter = await Interpreter.fromAsset('model.tflite');
// interpreter 的 options 里指定 delegate；初始化失败时捕获并回退

五、预处理与后处理的数值一致性 ​

模型在服务端训练时用的预处理，端侧必须逐项复刻：

环节常见不一致后果
归一化mean / std 不同、顺序不同输出整体偏移，置信度全低
通道顺序RGB ↔ BGR颜色相关任务直接崩
缩放插值双线性 ↔ 最近邻 ↔ 裁剪策略小目标检测漏检
数据类型0-255 ↔ 0-1 ↔ int8 量化参数数值溢出或全零
后处理NMS 阈值、softmax 温度框数量与类别全变

落地手段：

  • 把预处理参数写进模型清单，端侧从清单读取，不散落在代码里；
  • 用黄金张量做单测：固定输入 → 期望 logits / 概率，误差阈值写死；
  • 量化模型的输入也是 int8 时，注意 zero-point 与 scale 的换算方向。

六、Isolate 调度：别让推理卡住 UI ​

推理是 CPU / GPU 密集任务，放主 isolate 会直接掉帧。推荐结构：

dart
Future<Prediction> inferInBackground(TinyMlp model, List<double> input) {
  return Isolate.run(() => model.predict(input));
}

要点：

  1. 每个 Isolate 各自持有 interpreter，不能跨 isolate 共享原生句柄；
  2. 限制并发，同一时刻只跑一个推理任务，避免内存峰值叠加；
  3. 预热一次，把初始化和首帧预算拆开统计；
  4. 结果回主 isolate 再更新 UI，Isolate 只负责算张量；
  5. Web 没有真正的 Isolate，compute 会回落到主线程，不能把 Web 耗时当作收益。

配套预算：

dart
FrameBudgetVerdict assessFrameBudget(double inferenceMs) {
  if (inferenceMs <= 8) return const FrameBudgetVerdict(fitsInFrame: true, text: '可同步');
  if (inferenceMs <= 16.7) return const FrameBudgetVerdict(fitsInFrame: true, text: '接近预算');
  return const FrameBudgetVerdict(fitsInFrame: false, text: '必须移出主线程');
}

七、内存峰值与首帧 ​

端侧 AI 的内存峰值通常出现在三个时刻：

  1. 加载模型：fp32 权重 + 量化副本同时存在；
  2. 首次推理：delegate 初始化 + 中间张量分配；
  3. 并发推理：多个 interpreter 同时持有权重与激活。

控制手段：

  • 加载完成后释放原始 fp32 权重，只留量化产物；
  • 输入张量复用缓冲区，不要每帧新建；
  • 首帧前做一次预热推理，把初始化挪出启动关键路径；
  • 给推理设置最大并发 1，排队而不是并行；
  • 监控 RSS / GPU 内存，把峰值写进性能预算。

八、模型热更新与版本管理 ​

更新的是模型文件，不是代码。最低要求：

dart
class ModelRelease {
  final String modelId;
  final String version;      // 1.4.0
  final String quantization; // int8
  final int bytes;
  final String minAppVersion;
}

规则：

  1. modelId 必须一致，防止把无关模型替换进来；
  2. 远端版本必须更新，拒绝降级（降级只走回滚流程）；
  3. minAppVersion 不满足就阻断，新模型可能依赖新算子 / 新预处理；
  4. 下载后校验签名与哈希，校验失败即丢弃；
  5. 保留上一版本作回滚点，新模型线上指标异常可一键回退；
  6. 灰度发布，按设备 / 地域 / 用户分批，观察精度与崩溃。

九、功耗与发热 ​

推理是持续负载，移动端要按预算做：

  • 按需推理：传感器触发、用户操作触发，不要定时全量跑；
  • 降频 / 降采样：高负载时降低输入采样率或推理频率；
  • 热状态感知：读取平台热状态，过热时暂停非关键推理；
  • 避免后台常驻：后台推理既耗电又容易被系统杀；
  • 量化是第一节能手段：int8 通常比 fp32 省电，但要看算子实现。

/// 端侧 AI 最小实验：纯 Dart 小模型推理 + int8 / float16 量化对比 + 版本判定。
///
/// 权重由固定种子生成，仅用于演示推理与量化流程；真实模型来自服务端训练与
/// TFLite Converter，Flutter 端不做训练。
void main() {
  final Mlp model = Mlp.generated();

  print('参数数量：${model.parameterCount}');
  final List<double> input = normalizeInput(
    <double>[42.0, 1.8, 0.6, 0.7],
    mean: <double>[0.0, 0.0, 0.0, 0.0],
    std: <double>[50.0, 2.0, 1.0, 1.0],
  );

  print('\n=== float32 ===');
  printPrediction(model.predict(input));

  print('\n=== float16 ===');
  final QuantizedModel fp16 = quantizeFloat16(model);
  print('体积 ${fp16.bytes} B，最大权重误差 ${fp16.maxAbsError.toStringAsFixed(5)}');
  printPrediction(fp16.model.predict(input));

  print('\n=== int8 ===');
  final QuantizedModel int8 = quantizeInt8(model);
  print('体积 ${int8.bytes} B，最大权重误差 ${int8.maxAbsError.toStringAsFixed(5)}');
  printPrediction(int8.model.predict(input));

  print('\n=== 模型版本 ===');
  print('1.5.0 vs 1.4.0 → ${compareVersions('1.5.0', '1.4.0')}');
  print('2.0.0 vs 1.10.0 → ${compareVersions('2.0.0', '1.10.0')}');
  print(evaluateUpdate(
    remoteVersion: '1.5.0',
    installedVersion: '1.4.0',
    remoteMinApp: '2.0.0',
    appVersion: '2.4.0',
  ));
  print(evaluateUpdate(
    remoteVersion: '2.0.0',
    installedVersion: '1.4.0',
    remoteMinApp: '3.0.0',
    appVersion: '2.4.0',
  ));
}

void printPrediction(Prediction prediction) {
  final String probs = <String>[
    for (int i = 0; i < prediction.probabilities.length; i++)
      '${i}:${(prediction.probabilities[i] * 100).toStringAsFixed(1)}%',
  ].join(' ');
  print('分类 ${prediction.label}，概率 $probs');
}

class Mlp {
  Mlp({
    required this.inputSize,
    required this.hiddenSize,
    required this.labels,
    required this.w1,
    required this.b1,
    required this.w2,
    required this.b2,
  });

  final int inputSize;
  final int hiddenSize;
  final List<String> labels;
  final List<double> w1;
  final List<double> b1;
  final List<double> w2;
  final List<double> b2;

  int get parameterCount => w1.length + b1.length + w2.length + b2.length;

  factory Mlp.generated() {
    int state = 7;
    double next() {
      state = (state * 1103515245 + 12345) & 0x7FFFFFFF;
      return (state / 0x7FFFFFFF) * 2 - 1;
    }

    const int inputSize = 4;
    const int hiddenSize = 6;
    const List<String> labels = <String>['idle', 'walk', 'run'];
    return Mlp(
      inputSize: inputSize,
      hiddenSize: hiddenSize,
      labels: labels,
      w1: <double>[for (int i = 0; i < hiddenSize * inputSize; i++) next()],
      b1: <double>[for (int i = 0; i < hiddenSize; i++) next() * 0.2],
      w2: <double>[for (int i = 0; i < labels.length * hiddenSize; i++) next()],
      b2: <double>[for (int i = 0; i < labels.length; i++) next() * 0.2],
    );
  }

  List<double> logits(List<double> input) {
    final List<double> hidden = List<double>.filled(hiddenSize, 0);
    for (int h = 0; h < hiddenSize; h++) {
      double sum = b1[h];
      for (int i = 0; i < inputSize; i++) {
        sum += w1[h * inputSize + i] * input[i];
      }
      hidden[h] = sum > 0 ? sum : 0;
    }
    final List<double> output = List<double>.filled(labels.length, 0);
    for (int c = 0; c < labels.length; c++) {
      double sum = b2[c];
      for (int h = 0; h < hiddenSize; h++) {
        sum += w2[c * hiddenSize + h] * hidden[h];
      }
      output[c] = sum;
    }
    return output;
  }

  Prediction predict(List<double> input) {
    final List<double> probs = softmax(logits(input));
    int best = 0;
    for (int i = 1; i < probs.length; i++) {
      if (probs[i] > probs[best]) best = i;
    }
    return Prediction(
      label: labels[best],
      confidence: probs[best],
      probabilities: probs,
    );
  }

  Mlp withWeights(List<double> weights) {
    int offset = 0;
    List<double> take(int count) {
      final List<double> slice = weights.sublist(offset, offset + count);
      offset += count;
      return slice;
    }

    return Mlp(
      inputSize: inputSize,
      hiddenSize: hiddenSize,
      labels: labels,
      w1: take(w1.length),
      b1: take(b1.length),
      w2: take(w2.length),
      b2: take(b2.length),
    );
  }

  List<double> flattenWeights() => <double>[...w1, ...b1, ...w2, ...b2];
}

class Prediction {
  const Prediction({
    required this.label,
    required this.confidence,
    required this.probabilities,
  });

  final String label;
  final double confidence;
  final List<double> probabilities;
}

class QuantizedModel {
  const QuantizedModel({
    required this.model,
    required this.bytes,
    required this.maxAbsError,
  });

  final Mlp model;
  final int bytes;
  final double maxAbsError;
}

QuantizedModel quantizeFloat16(Mlp model) {
  final List<double> weights = model.flattenWeights();
  final List<double> rounded = <double>[
    for (final double weight in weights) roundToFloat16(weight),
  ];
  return QuantizedModel(
    model: model.withWeights(rounded),
    bytes: rounded.length * 2,
    maxAbsError: maxAbsError(weights, rounded),
  );
}

QuantizedModel quantizeInt8(Mlp model) {
  final List<double> weights = model.flattenWeights();
  double maxAbs = 0;
  for (final double weight in weights) {
    if (weight.abs() > maxAbs) maxAbs = weight.abs();
  }
  final double scale = maxAbs == 0 ? 1 : maxAbs / 127.0;
  final List<int> q = <int>[
    for (final double weight in weights) (weight / scale).round().clamp(-127, 127),
  ];
  final List<double> dequantized = <double>[
    for (final int value in q) value * scale,
  ];
  return QuantizedModel(
    model: model.withWeights(dequantized),
    bytes: q.length + 4,
    maxAbsError: maxAbsError(weights, dequantized),
  );
}

double roundToFloat16(double value) {
  if (value == 0) return 0;
  final bool negative = value < 0;
  double abs = value.abs();
  int exponent = 0;
  while (abs >= 2) {
    abs /= 2;
    exponent++;
  }
  while (abs < 1) {
    abs *= 2;
    exponent--;
  }
  const double step = 1 / 1024;
  double rounded = (abs / step).round() * step;
  if (rounded >= 2) {
    rounded = 1;
    exponent++;
  }
  double result = rounded;
  if (exponent > 0) {
    for (int i = 0; i < exponent; i++) {
      result *= 2;
    }
  } else if (exponent < 0) {
    for (int i = 0; i < -exponent; i++) {
      result /= 2;
    }
  }
  return negative ? -result : result;
}

double maxAbsError(List<double> original, List<double> rounded) {
  double worst = 0;
  for (int i = 0; i < original.length; i++) {
    final double diff = (original[i] - rounded[i]).abs();
    if (diff > worst) worst = diff;
  }
  return worst;
}

List<double> softmax(List<double> logits) {
  double maxLogit = logits[0];
  for (final double value in logits) {
    if (value > maxLogit) maxLogit = value;
  }
  final List<double> expValues = <double>[];
  double total = 0;
  for (final double value in logits) {
    double expValue = 1.0;
    double term = value - maxLogit;
    // e^x 的级数展开，避免依赖 dart:math 之外的实现差异。
    double factor = 1;
    for (int i = 1; i <= 20; i++) {
      factor *= term / i;
      expValue += factor;
    }
    expValues.add(expValue);
    total += expValue;
  }
  return <double>[for (final double value in expValues) value / total];
}

List<double> normalizeInput(
  List<double> raw, {
  required List<double> mean,
  required List<double> std,
}) {
  return <double>[
    for (int i = 0; i < raw.length; i++)
      std[i] == 0 ? 0 : (raw[i] - mean[i]) / std[i],
  ];
}

int compareVersions(String a, String b) {
  List<int> parts(String version) => <int>[
        for (final String segment in version.split('.'))
          int.tryParse(segment.replaceAll(RegExp(r'[^0-9]'), '')) ?? 0,
      ];
  final List<int> left = parts(a);
  final List<int> right = parts(b);
  final int length = left.length > right.length ? left.length : right.length;
  for (int i = 0; i < length; i++) {
    final int l = i < left.length ? left[i] : 0;
    final int r = i < right.length ? right[i] : 0;
    if (l != r) return l > r ? 1 : -1;
  }
  return 0;
}

String evaluateUpdate({
  required String remoteVersion,
  required String installedVersion,
  required String remoteMinApp,
  required String appVersion,
}) {
  if (compareVersions(remoteMinApp, appVersion) > 0) {
    return '阻断：远端模型要求 app >= $remoteMinApp';
  }
  final int diff = compareVersions(remoteVersion, installedVersion);
  if (diff > 0) return '可热更新到 $remoteVersion';
  if (diff == 0) return '版本一致，无需更新';
  return '拒绝降级到 $remoteVersion';
}

常见坑 ​

  1. 以为 Flutter 能训练模型：端侧只有前向，训练与转换都在服务端。
  2. 把 .onnx 直接塞给 TFLite：必须经过 TFLite Converter。
  3. 量化后不验精度：top-1 掉几个点才发现。
  4. 校准集不覆盖长尾：线上输入分布一变就崩。
  5. delegate 失败没有回退：部分机型直接不可用。
  6. 首帧把初始化算进去：启动预算被虚高，或反过来掩盖真实卡顿。
  7. 预处理参数散落在代码：与服务端不一致，输出整体偏移。
  8. 通道顺序搞反：RGB / BGR 混用，视觉任务全错。
  9. 主线程推理：几十毫秒直接掉帧。
  10. 多个 Isolate 并发推理：内存峰值与温度双高。
  11. Web 上把 compute 当线程：实际仍在主线程执行。
  12. 热更新不校验签名：可被替换成恶意模型。
  13. 热更新允许降级：旧模型覆盖新模型，指标回退。
  14. 没有回滚点：新模型出问题只能等发版。
  15. 后台常驻推理：耗电、发热、被系统清理。
  16. 只看平均耗时：P95 / 最大值才是卡顿来源。

  1. 用 TFLite Converter 把一个 MNIST 模型转成 float32 / float16 / int8 三份，比较体积与准确率。
